Eligibility Traces

The λ-return, TD(λ), true online TD(λ) and Sarsa(λ): one short-term memory vector that turns every TD error into credit for the whole recent past

Monte Carlo waits for the end of the episode and trusts only what happened; one-step TD updates at once but looks only one step ahead. The n-step methods of the previous chapters sit in between, but they make you pick one n and keep n steps of history. Eligibility traces do the same job with a single vector z: every state the agent visits leaves a mark, the marks fade at the rate γλ, and each TD error is handed back to every marked state in proportion to its mark. The figure shows the marks on the 19-state random walk as an episode plays. Slide λ to make the memory longer or shorter; at λ = 0 only the current state is marked, at λ = 1 nothing is forgotten.

The idea · 12.1

From n-step returns to the λ-return

The previous chapters gave us a whole family of update targets. The n-step return Gt:t+n takes n real rewards and then bootstraps: it stands in for everything after step t+n with the current estimate v̂(St+n, wt+n−1). With n = 1 it is the TD(0) target; once t+n reaches the end of the episode there is nothing left to estimate and it is the full Monte Carlo return Gt. Each n is a legitimate target, and so is any average of them: half of the 2-step return plus half of the 4-step return is a perfectly good target too, because its expected value is still a mixture of correct estimates. Such averages are called compound updates. The only rule is that the weights are non-negative and sum to one.

The λ-return is one particular compound update, chosen for a property that will matter enormously in the next section: its weights decay geometrically. The n-step return gets weight (1 − λ)λn−1, so each extra step of looking ahead is trusted λ times less than the one before. Because the geometric series sums to one, the normaliser is just (1 − λ). In an episode that ends at time T, the n-step returns for n ≥ T − t are all the same thing, the Monte Carlo return, so all their weight is lumped onto it: the final return gets the whole remaining tail, λT−t−1. Slide λ under the figure and watch the weights move from the 1-step return (λ = 0, which is TD(0)) to the final return (λ = 1, which is Monte Carlo).

\[ \begin{aligned} G_{t:t+n} &\doteq R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1} R_{t+n} + \gamma^{n}\,\hat v(S_{t+n}, \mathbf w_{t+n-1}), \qquad 0 \le t \le T-n \\ G_t^{\lambda} &\doteq (1-\lambda)\sum_{n=1}^{\infty} \lambda^{n-1}\, G_{t:t+n} \\ G_t^{\lambda} &= (1-\lambda)\sum_{n=1}^{T-t-1} \lambda^{n-1}\, G_{t:t+n} \;+\; \lambda^{T-t-1}\, G_t \quad \text{(episodic form)} \end{aligned} \]
Read it as: the first line is the n-step return: n rewards, then the estimate of the state n steps on, using the weights available at that time. The second line averages every n-step return with weight (1−λ)λn−1; these weights sum to 1 because (1−λ)(1 + λ + λ2 + …) = 1. The third line is the same thing in an episode that ends at T: returns that reach the end all equal Gt, so their weights are pooled into λT−t−1. With λ = 0 the sum collapses to Gt:t+1 (TD(0)); with λ = 1 only the final term survives (Monte Carlo).
Say it“The lambda-return is one minus lambda, times the sum over n of lambda to the n minus one times the n-step return.”

Two numbers in the panel are worth remembering. The mean look-ahead 1/(1−λ) is the average n under the geometric weights: λ = 0.9 looks on average 10 steps ahead, λ = 0.99 a hundred. And the number of returns holding 95% of the weight tells you how far you must actually see to compute the λ-return to good accuracy, which is the question the truncated methods of section 4 will answer. For now, notice the problem the forward view creates: to compute Gλt you must wait for the rewards of every later step. The λ-return is a beautiful target, and an acausal one.

A little history. The order of discovery was the reverse of the order of this chapter. Harry Klopf proposed in 1972 that a synapse should become “eligible” for modification for a while after it fires, and be modified only if reinforcement arrives during that window; Sutton and Barto built learning rules on the idea in the early 1980s, and Sutton’s 1988 paper defined TD(λ) directly in its backward, trace form, with the random-walk experiment of section 3 as its showcase. The forward view, the λ-return as a weighted average of n-step returns, was worked out by Watkins in his 1989 thesis as a way of understanding what the traces were computing, and the exact online equivalence between the two views had to wait until van Seijen and Sutton in 2014. The chapter follows the logical order, from the target to the mechanism, because that is the direction in which the algorithm can be derived rather than merely stated.

Forward view · 12.1

The forward view: look ahead, then update

The simplest algorithm that uses the λ-return is the offline λ-return algorithm: run the episode to the end, then, for every time step t, compute Gλt and make a semi-gradient step toward it. Nothing changes during the episode (hence offline), so all the targets are computed with the same weight vector. This is the forward view: standing at each state in turn, we look forward into the future rewards and states and decide how to update that state. It is theoretically clean and it is the standard against which every trace method is measured. It is also, on its own, unusable in a continuing task and wasteful in a long episode.

Before any machinery, do one by hand. The walk below has five non-terminal states A–E in a row. The agent starts in C and moves left or right at random; stepping off the left end gives reward 0, off the right end reward 1, and every other reward is 0 (this is the walk from the TD chapter). Every value is initialised to 0.5, γ = 1, and we take λ = ½ so the arithmetic is powers of two. One episode happened: C, D, C, D, E, then off the right end (T = 5). The calculation runs through the n-step returns of the first visit to C, assembles its λ-return, does the same for the other visits, and applies the offline update with α = 0.1. The figure on the right makes the same construction on the full 19-state walk with one twist: the values are set to their true values, so every bootstrapped n-step return is exactly right in expectation and the only thing left in the picture is variance. Even so the λ-return wanders away from v(St), and it wanders further the larger λ is, because a larger λ puts more weight on the long returns, which depend on more coin flips. With wrong estimates the picture gains a second ingredient, bias, which goes the other way: short returns inherit the error of the estimate they bootstrap from. The best λ balances the two, and it is not at either end.

Backward view · 12.2

TD(λ): the backward view with accumulating traces

Here is the trick that makes the chapter. Instead of standing at a state and looking forward for its target, stand at the current time step, compute the ordinary one-step TD error δt, and hand it backward to every state visited recently, in proportion to how recently and how often. The bookkeeping is a single vector the size of w, the eligibility trace zt. At every step it decays by γλ, and the gradient of the current state’s estimate is added to it (for a lookup table: add 1 to the slot of the current state). A state visited three steps ago has a mark of (γλ)3; one visited twice has two marks added together, which is why these are called accumulating traces. The update is then w ← w + αδtzt: one scalar error, broadcast along the trace.

Why does this reproduce the λ-return? Because the gap between a λ-return and the current value, Gλt − V(St), can be rewritten exactly as a γλ-discounted sum of the future one-step TD errors, provided the values do not change during the episode. Summing the backward-view updates over an episode then gives the same total as the forward view, term for term. \[ \begin{aligned} \mathbf z_{-1} &\doteq \mathbf 0 \\ \mathbf z_t &\doteq \gamma\lambda\,\mathbf z_{t-1} + \nabla\hat v(S_t,\mathbf w_t) \\ \delta_t &\doteq R_{t+1} + \gamma\,\hat v(S_{t+1},\mathbf w_t) - \hat v(S_t,\mathbf w_t) \\ \mathbf w_{t+1} &\doteq \mathbf w_t + \alpha\,\delta_t\,\mathbf z_t \end{aligned} \]
Read it as: semi-gradient TD(λ). The trace starts at zero, decays by γλ every step and accumulates the gradient of the visited state (a 1 in that state’s slot for a table, the feature vector x(St) for a linear approximator). δt is the usual TD error. Every component of w moves by αδt times its trace. λ = 0 makes zt = ∇v̂(St) and recovers TD(0); λ = 1 with γ = 1 never forgets, and the episode’s total update equals the Monte Carlo update.
Say it“Decay the trace by gamma lambda, add the gradient of the current state, then move every weight by alpha times the TD error times its trace.”
\[ \begin{aligned} G_t^{\lambda} - V(S_t) &= \sum_{k=t}^{T-1} (\gamma\lambda)^{k-t}\,\delta_k \quad \text{(V held fixed)} \\ \sum_{t=0}^{T-1} \alpha\big[G_t^{\lambda} - V(S_t)\big]\mathbb 1_{S_t=s} &= \sum_{k=0}^{T-1} \alpha\,\delta_k \sum_{t\le k} (\gamma\lambda)^{k-t}\,\mathbb 1_{S_t=s} = \sum_{k=0}^{T-1}\alpha\,\delta_k\, z_k(s) \end{aligned} \]
Read it as: the forward–backward equivalence. The first line telescopes the λ-return into TD errors: write Gλt − V(St) = δt + γλ[Gλt+1 − V(St+1)] and unroll. The second line swaps the order of summation: the total forward-view increment to state s equals the sum over time of αδk times zk(s), where zk(s) = Σt≤k(γλ)k−t1[St = s] is exactly the accumulating trace. The identity is exact only if V is frozen during the episode; online TD(λ) changes V as it goes, so it approximates the offline λ-return algorithm, the better the smaller α is.
Say it“Lambda-return minus value equals the gamma-lambda-discounted sum of future TD errors.”
how exactly? Deriving Gλt − V(St) = Σk(γλ)k−tδk
Start from the recursive form of the λ-return, which you can read straight off its definition: Gλt = Rt+1 + γ(1−λ)V(St+1) + γλGλt+1. (The 1-step return contributes Rt+1 + γV(St+1) with weight 1−λ; every longer return shares the first reward Rt+1 and then continues as a return from t+1, and those continuations, re-weighted, are exactly Gλt+1.)
Subtract V(St) from both sides and add and subtract γλV(St+1):
Gλt − V(St) = [Rt+1 + γV(St+1) − V(St)] + γλ[Gλt+1 − V(St+1)] = δt + γλ[Gλt+1 − V(St+1)].
Now unroll: the bracket on the right has the same shape one step later, so it equals δt+1 + γλ[…], and so on until the terminal time T, where GλT and V(ST) are both 0. The result is δt + γλδt+1 + (γλ)2δt+2 + … + (γλ)T−1−tδT−1.
The step “Rt+1 + γV(St+1) − V(St) = δt” silently uses the same V throughout. Online TD(λ) computes δt with the values current at time t, which the earlier updates of this episode have already changed; that is the whole of the approximation.

With a function approximator

Nothing in the backward view assumed a table. With a linear approximator v̂(s, w) = wℤx(s), the gradient is the feature vector, so the trace is a decaying sum of the feature vectors of the states visited, zt = Σk≤t(γλ)t−kx(Sk), and the update w ← w + αδtzt moves every weight that any recent state used. Generalisation happens for free: a TD error in one state adjusts the values of all states sharing its features, in the proportions the trace remembers. With a non-linear approximator the same equations apply with ∇v̂ in place of x, which is how TD-Gammon trained its neural network, although the forward–backward equivalence then holds only approximately even with frozen weights, because the gradient itself changes with w.

Linear TD(λ) on-policy converges (Tsitsiklis and Van Roy, 1997), and to a point whose quality depends on λ: the asymptotic value error is bounded by (1 − γλ)/(1 − γ) times the best error attainable in the feature space. At λ = 1 the factor is 1 (Monte Carlo finds the least-squares fit to the returns); at λ = 0 it is 1/(1 − γ), the bound of chapter 3.2b for TD(0), which for γ = 0.99 allows an error a hundred times the best possible. In practice the fixed points are far closer than the bound suggests, but the direction is real: larger λ trusts the approximator less and lands closer to the best representable value function, at the price of more variance along the way.

\[ \begin{aligned} \mathbf z_t &= \gamma\lambda\,\mathbf z_{t-1} + \mathbf x(S_t) = \sum_{k=0}^{t} (\gamma\lambda)^{t-k}\,\mathbf x(S_k) \\ \overline{\text{VE}}(\mathbf w_\infty) &\le \frac{1-\gamma\lambda}{1-\gamma}\,\min_{\mathbf w}\overline{\text{VE}}(\mathbf w) \end{aligned} \]
Read it as: the first line writes out what the linear trace contains: each past feature vector, discounted by how long ago it was active. The second is the Tsitsiklis–Van Roy bound on the error of linear on-policy TD(λ) at convergence, in the μ-weighted squared norm of chapter 3.2b; the factor ranges from 1/(1−γ) at λ = 0 to 1 at λ = 1.
Say it“The trace is the discounted sum of past feature vectors, and the larger lambda, the closer TD(lambda) gets to the best fit.”

The vocabulary in one place

  • λ ∈ [0, 1]The trace-decay parameter. Also the weight ratio between consecutive n-step returns in the λ-return. Not a discount: γ says how much the future is worth, λ says how far to trust your own estimates when assembling a target.
  • zt ∈ ℝdThe eligibility trace, the same size as the weight vector. It is a short-term memory of which weights have recently contributed to value estimates; the long-term memory is w itself.
  • Gt:t+nThe n-step return: n rewards, then bootstrap. Gt:t+1 is the TD(0) target, Gt:T = Gt the Monte Carlo return.
  • GλtThe λ-return, the geometrically weighted average of all n-step returns. The forward-view target.
  • Gλt:hThe truncated λ-return with horizon h: the same average, cut off at the h-step return, which receives the pooled tail weight.
  • δtThe one-step TD error at time t. In the backward view it is the only new information at each step; the trace decides who receives it.
  • Forward viewDecide each state’s update by looking ahead from it (the λ-return algorithms). Conceptually clear, computationally awkward.
  • Backward viewAt each step, send the current TD error back to recently visited states via the trace (TD(λ), Sarsa(λ)). Causal, cheap, and equivalent to the forward view when the values are frozen.

Truncation · 12.3

Truncated λ-returns: stop looking at horizon h

The offline λ-return algorithm has two problems that the same fix solves. In a continuing task the λ-return is never finished, because there is always another reward coming; and even in an episodic task, waiting until the end to learn anything is a waste, since most of the weight sits on the first handful of n-step returns anyway (look back at the “returns holding 95%” readout of section 1). So cut the sum off. The truncated λ-return Gλ|ht uses the n-step returns only up to some horizon h > t, and gives all the weight that would have gone further, λh−t−1, to the longest return it does have, Gt:h, which bootstraps from v̂(Sh). It is the episodic formula of section 1 with the horizon h playing the role of the end of the episode T, and the longest return bootstrapping instead of terminating.

The truncation error is controlled by how much weight was pushed onto the bootstrapped return, and that is just λh−t−1: with λ = 0.9 a horizon 22 steps ahead leaves about 10% of the target bootstrapped, 44 steps ahead leaves 1%. The family of algorithms that updates each state once its horizon has arrived, so with a delay of n = h − t steps, is called truncated TD(λ), TTD(λ) (Cichosz, 1995; van Seijen, 2016). They sit between n-step TD and the full λ-return: like n-step methods they have a fixed delay n, but within that window the n returns are blended geometrically instead of using only the n-th. Slide the horizon to see the weights pile up on the bootstrapped return, and read off, on the 19-state walk, how far the truncated target actually is from the full one.

Two limits place the idea. At λ = 1 the truncated λ-return is just the n-step return Gt:t+n, so TTD(1) is n-step TD and the previous chapter is a special case of this one. At n = 1 it is the 1-step return whatever λ is. Redoing the past · 12.4

The online λ-return algorithm: redo every update at every step

Truncation forces an awkward choice. A short horizon lets us update soon but with a poor target; a long horizon gives a good target but makes us wait. The online λ-return algorithm refuses the choice: at every time step h it goes back to the start of the episode and redoes all the updates so far, using truncated λ-returns with the horizon now at h, which is the longest horizon currently available. Each pass starts from the weights the episode began with and produces a fresh sequence wh0, wh1, …, whh; the last of them, whh, is the weight vector the algorithm actually uses at time h, written wh. When the episode ends, the final pass uses the full λ-returns, so its final weight vector is the forward view done properly, except that every intermediate target was also allowed to use the best available weights.

The cost is absurd: each step redoes a whole episode, so an episode of T steps costs about T2/2 updates. The quality is excellent: on the 19-state walk it beats both the offline λ-return algorithm and TD(λ) at every λ (Sutton and Barto’s Figure 12.8), because every target is built from values that have already been improved by this very episode. Think of it as the ideal that a practical algorithm should aim at. The exact shortcut · 12.5 & 12.6

True online TD(λ) and the dutch trace

The online λ-return algorithm produces a triangle of weight vectors but only ever uses its diagonal, w0, w1, …, wT. In 2014 Harm van Seijen and Richard Sutton showed that, for linear function approximation v̂(s, w) = wℤx(s), each vector on that diagonal can be computed from the previous one with a single update of the ordinary kind, w, a trace z and one extra scalar. The resulting method is true online TD(λ): it is not an approximation of the online λ-return algorithm, it is the online λ-return algorithm, step for step, at the memory and per-step cost of TD(λ). The “true” is a quiet dig at conventional TD(λ), which only approximates the forward view it was named for.

Two things change relative to TD(λ). The trace becomes a dutch trace: it still decays by γλ and adds the feature vector, but the addition is scaled down by (1 − αγλzℤx), so a state that is already heavily marked receives a smaller new mark, something between the accumulating trace (which always adds 1) and the replacing trace of the next section (which resets to 1). And the weight update gains a correction term in Vt − Vt−1, the amount by which the current state’s estimate was itself changed by the previous update; this is precisely the quantity that the online λ-return algorithm’s redo accounts for and plain TD(λ) ignores. The lab puts the four methods on the same 19-state episode, starting from noisy values so that the TD errors are non-zero throughout, and plots how far each is from the online λ-return triangle’s diagonal at every step. True online TD(λ) sits on the floor of floating-point noise.

\[ \begin{aligned} \delta_t &\doteq R_{t+1} + \gamma\,\mathbf w_t^{\!\top}\mathbf x_{t+1} - \mathbf w_t^{\!\top}\mathbf x_t \\ \mathbf z_t &\doteq \gamma\lambda\,\mathbf z_{t-1} + \big(1 - \alpha\gamma\lambda\,\mathbf z_{t-1}^{\!\top}\mathbf x_t\big)\,\mathbf x_t \\ \mathbf w_{t+1} &\doteq \mathbf w_t + \alpha\,\delta_t\,\mathbf z_t + \alpha\big(\mathbf w_t^{\!\top}\mathbf x_t - \mathbf w_{t-1}^{\!\top}\mathbf x_t\big)\big(\mathbf z_t - \mathbf x_t\big) \end{aligned} \]
Read it as: true online TD(λ) for linear v̂. The first line is the usual TD error. The second is the dutch trace: the new feature vector is added with a factor that shrinks as the trace already points along xt (for a lookup table, zℤxt is the current state’s own trace). The third line is TD(λ)’s update plus a correction proportional to Vt − Vt−1, how much the value of the current state changed in the last update, applied along zt − xt, that is to the older part of the trace. Its output wt equals the online λ-return algorithm’s wtt exactly, for every t. In the pseudocode it is written with Vold: w ← w + α(δ + V − Vold)z − α(V − Vold)x.

What the correction term is for. In the online λ-return algorithm, the truncated return that corrects St at pass h bootstraps from values that pass h itself has not touched, but the estimate v̂(St, wht) being corrected has already been moved by the earlier steps of the same pass. TD(λ) applies αδt along the whole trace as if every traced state’s estimate were still the one used when its TD error was last computed. The term α(Vt − Vt−1)(zt − xt) in true online TD(λ) repairs exactly that: Vt − Vt−1 is how much the current state’s value changed in the last update, and it is fed back along the older part of the trace, the states whose λ-returns bootstrapped from this state. In the hand example that difference was the gap between 0.515625 and 0.5153125.

Back in the lab of section 3, switch the algorithm to true online TD(λ) and compare with accumulating traces: at small λ the two are the same, at large λ and large α true online is clearly better, and it never develops the instability of the accumulating trace at λ = 1 with large α, because the dutch trace cannot grow without bound when a state is revisited. Note what is being compared: the random walk is a lookup table, the simplest linear approximator, and the equivalence is exact for any linear features, including the tile coding of the project. For non-linear approximators true online TD(λ) is defined by the same equations but the equivalence with the online λ-return is lost.

Three traces · 12.5 & 12.7

Accumulating, replacing and dutch traces

Three recipes for the trace have now appeared, and they differ only in what happens when a feature is already active when it becomes active again. The accumulating trace adds the feature vector regardless, so a state visited k times in quick succession carries a mark close to k. The replacing trace (Singh and Sutton, 1996) resets the mark of a revisited binary feature to 1 instead of adding, so it never exceeds 1; it was for years the standard fix for the accumulating trace’s tendency to over-credit states the agent loops through. The dutch trace adds the feature scaled by (1 − αγλzℤx): for a binary feature with trace z, the new trace is γλz + 1 − αγλz, which for α → 0 is the accumulating trace and for α = 1 is exactly the replacing trace. With the dutch trace in hand, the replacing trace is best understood as a crude approximation of it, and it has no forward-view justification of its own.

The difference matters most where states are revisited: a gridworld in which the agent wanders back and forth, or a tile coding in which a slowly moving car keeps the same tiles active for many consecutive steps. In the project you will watch the accumulating trace blow up on exactly that. Click on the timeline below to mark the steps at which a state is visited (or use a preset), and compare the three traces for that visit pattern; the panel gives the peak value and the total credit the state would collect from a run of equal TD errors.

For control there is one more choice. When the agent revisits a state and takes a different action, the old action’s trace is still live. Singh and Sutton’s replacing-trace Sarsa therefore came in a variant that, on every visit, sets the taken action’s trace to 1 and clears the traces of the other actions in that state, on the argument that the later choice supersedes the earlier one as the thing to be credited. In their experiments the clearing version learned fastest; the gridworld in the next section offers it as “replacing + clearing”, and true online Sarsa(λ) makes the question moot by deriving its trace from the forward view rather than from an argument.

\[ \begin{aligned} \text{accumulating:}\quad & \mathbf z_t = \gamma\lambda\,\mathbf z_{t-1} + \mathbf x_t \\ \text{dutch:}\quad & \mathbf z_t = \gamma\lambda\,\mathbf z_{t-1} + \big(1 - \alpha\gamma\lambda\,\mathbf z_{t-1}^{\!\top}\mathbf x_t\big)\,\mathbf x_t \\ \text{replacing (binary features):}\quad & z_{i,t} = \begin{cases} 1 & \text{if } x_{i,t} = 1 \\ \gamma\lambda\, z_{i,t-1} & \text{otherwise} \end{cases} \end{aligned} \]
Read it as: all three decay by γλ between visits. On a visit the accumulating trace adds 1 (for a one-hot or binary feature), the replacing trace sets 1, and the dutch trace adds 1 − αγλz, which lands in between: at α = 1 it sets γλz + 1 − γλz = 1, the replacing trace exactly. Only the accumulating and dutch traces are defined for arbitrary real-valued features; the replacing trace needs binary features and, for Sarsa(λ), comes in a variant that also zeroes the traces of the other actions in the visited state.

Choosing λ and α in practice

What λ buys and costs

  • Credit assignment speed. A reward reaches a state k steps back after one episode with weight (γλ)k; with λ = 0 it needs k episodes. In sparse-reward control this is the difference between learning and not learning in a reasonable time.
  • Variance. Larger λ means more of the target is real, noisy outcome and less is smoothed estimate. The random-walk curves show the compensation: the best α shrinks as λ grows.
  • Bias. Smaller λ leans on the current estimates, which are wrong early on. With function approximation the fixed point also moves with λ: at λ = 1 it is the least-squares fit to the returns; at λ = 0 it is the TD fixed point of chapter 3.2b, whose error bound is worse by a factor (1 − γλ)/(1 − γ).
  • A default. On most problems λ between 0.8 and 0.95 is hard to beat, which is why so many published systems use 0.9 or 0.92 (TD-Gammon used 0.7; Sutton’s Mountain Car used 0.92). Sweep it like any other hyper-parameter; the curves here are what such a sweep looks like.

Which trace, which step size

  • Accumulating traces are the textbook default and the right one when features are rarely re-activated. With binary features and slow dynamics they can grow past 1 and a step size tuned for a single visit becomes several times too large.
  • Replacing traces fix that crudely and work well in practice for binary features; for Sarsa(λ) the variant that also clears the other actions’ traces in the visited state was long the standard recipe.
  • Dutch traces, via true online TD(λ) and true online Sarsa(λ), are the principled version: exact forward view, bounded traces, the same cost. Prefer them when the approximator is linear.
  • Step size with tile coding. With n tilings each state activates n features, so a step α per feature moves the estimate by nα times the error; α = 1/n moves it all the way (one-trial learning). Sutton and Barto recommend about 1/(10n) for noisy problems; the project’s slider is in units of 1/8 for this reason.

Control · 12.7

Sarsa(λ): traces for control, and the glow of the path

Everything so far was prediction. Control needs action values, and the move is the obvious one: replace v̂(s, w) by q̂(s, a, w) and the state feature vector by a state–action feature vector, keep the trace, keep the TD error, and act greedily (or ε-greedily) with respect to q̂. The result is Sarsa(λ). Its TD error is the Sarsa error, Rt+1 + γq̂(St+1, At+1) − q̂(St, At), and its trace is accumulated over state–action pairs, so the trace vector now remembers not just where the agent was but what it did there. With linear binary features, as in tile coding, the trace of each active feature is bumped (or set) and every update touches only the features with non-zero traces.

Why does this matter so much for control? Think of the first time a gridworld agent stumbles onto the goal after a long wander. One-step Sarsa increases the value of exactly one action, the last one. Ten-step Sarsa increases the last ten, all by the same amount. Sarsa(λ) increases every action along the path, by an amount that fades with distance from the goal: the eligibility trace at the moment of the reward is a picture of the path, brightest at the end. Sutton and Barto draw this as a “glow” along the trajectory; the gridworld below renders the trace vector live so you can watch the glow form and fade as the agent moves. Had δ been −0.5, every weight with a trace would have moved by 0.1 × (−0.5) × its trace: with accumulating traces w7 would fall by 0.095, with replacing traces by 0.05. That factor of nearly two, on a feature that merely stayed active for two consecutive steps, is the whole story of the accumulating trace on Mountain Car.

Two cautions carry over from prediction. With accumulating traces and a policy that dithers, a cell the agent crosses back and forth over can build a trace well above 1, and a large α then over-corrects; replacing traces, with or without clearing, and the dutch trace keep that in check (the project makes this failure dramatic). And Sarsa(λ) is on-policy: the trace credits the actions the agent actually took, exploratory ones included. Watkins’s Q(λ) cuts the trace to zero at every exploratory action so that only greedy stretches are credited; that, and the off-policy trace methods built on importance sampling, are the subject of the next chapter.

Real-world project

Project: Mountain Car with Sarsa(λ) over tile coding

The project runs the chapter’s control algorithm on the classic under-powered car (Moore, 1990; Sutton and Barto, Example 10.1). The car sits in a valley; its engine is too weak to drive straight up to the flag on the right, so it must first reverse up the left slope to gain momentum. The state is continuous, position x ∈ [−1.2, 0.5] and velocity v ∈ [−0.07, 0.07]; the actions are full reverse, coast and full throttle; every step costs −1 until the car reaches x ≥ 0.5. The function approximator is a tile coding with 8 tilings of 8 × 8 tiles, each tiling offset from the last, so each state–action pair activates exactly 8 binary features out of 1,944, and q̂ is the sum of their 8 weights. Sarsa(λ) learns online, greedy with respect to q̂ (ε = 0; the zero initial values are optimistic because every real return is negative, which drives exploration by itself).

Where the λ idea lives today

1992 · games

TD-Gammon

Tesauro trained a backgammon network with TD(λ), λ = 0.7, over a non-linear approximator, by self-play: the first eligibility-trace system to reach expert level, and the ancestor of every later game-playing value network.

1996 · control

Sarsa(λ) + tile coding

Sutton’s Mountain Car, Acrobot and puddle-world results with replacing traces and sparse coarse coding, the setting of this project, established the recipe for linear RL control that held for two decades.

2016 · policy gradients

Generalised advantage estimation

GAE (Schulman et al.) estimates the advantage with a λ-return over TD errors, Σ(γλ)kδt+k: section 3’s identity, applied to a learned critic. PPO’s default λ = 0.95 is this chapter’s dial.

2016 · off-policy

Retrace(λ) and V-trace

Off-policy deep RL (ACER, IMPALA) uses λ-weighted multi-step targets with clipped importance ratios so that replayed or lagged data can be used safely: the next chapter’s material at scale.

2017 · value-based

n-step returns in Rainbow

Deep Q-learning agents mostly use fixed n-step returns (n = 3 in Rainbow) rather than traces, because replay buffers break the trace’s assumption of consecutive online updates; forward-view λ variants exist for this setting too.

2014–2016 · theory

True online methods

van Seijen and Sutton’s exact equivalence made the online λ-return the standard against which trace methods are judged, and true online Sarsa(λ) the recommended linear control method in the textbook.

"""Eligibility traces: the 19-state random walk and Mountain Car with Sarsa(lambda).
Pure numpy. Uses the same mulberry32 generator as the lecture page so the two agree."""
import math, json, sys
import numpy as np
np.seterr(all='ignore')   # accumulating traces at lambda = 1, alpha = 1 diverge on purpose; let them

def mulberry32(seed):
    a = seed & 0xFFFFFFFF
    def rnd():
        nonlocal a
        a = (a + 0x6D2B79F5) & 0xFFFFFFFF
        t = ((a ^ (a >> 15)) * (a | 1)) & 0xFFFFFFFF
        t = (t ^ (t + (((t ^ (t >> 7)) * (t | 61)) & 0xFFFFFFFF))) & 0xFFFFFFFF
        return ((t ^ (t >> 14)) & 0xFFFFFFFF) / 4294967296
    return rnd

# ---------------- Part 1: the 19-state random walk (gamma = 1) ----------------
N = 19
TRUE = np.array([(i + 1) / 10 - 1 for i in range(N)])

def episode(rng):
    S, s = [9], 9
    while True:
        s += -1 if rng() < 0.5 else 1
        if s < 0: return S, -1.0
        if s >= N: return S, 1.0
        S.append(s)

def make_runs(n_runs, n_ep, seed):      # one generator per run, shared by that run's episodes
    out = []
    for r in range(n_runs):
        rng = mulberry32(seed + r)
        out.append([episode(rng) for _ in range(n_ep)])
    return out

def offline_lambda_return(V, ep, lam, alpha):
    S, R = ep; T = len(S); G = [0.0] * T; G[-1] = R
    for t in range(T - 2, -1, -1):                # G^l_t = R_{t+1} + (1-l) V(S_{t+1}) + l G^l_{t+1}
        G[t] = (1 - lam) * V[S[t + 1]] + lam * G[t + 1]
    U = V.copy()
    for t in range(T): U[S[t]] += alpha * (G[t] - V[S[t]])
    V[:] = U

def td_lambda(V, ep, lam, alpha, replacing=False):
    S, R = ep; T = len(S); z = np.zeros(N)
    for t in range(T):
        s = S[t]
        if replacing: z[s] = 1.0
        else: z[s] += 1.0
        delta = (R if t == T - 1 else V[S[t + 1]]) - V[s]
        V += alpha * delta * z
        z *= lam

def true_online_td(V, ep, lam, alpha):
    S, R = ep; T = len(S); z = np.zeros(N); v_old = 0.0
    for t in range(T):
        s = S[t]; v = V[s]; v_next = 0.0 if t == T - 1 else V[S[t + 1]]
        delta = (R if t == T - 1 else 0.0) + v_next - v
        zx = z[s]; z *= lam; z[s] += 1 - alpha * lam * zx          # dutch trace
        V += alpha * (delta + v - v_old) * z; V[s] -= alpha * (v - v_old)
        v_old = v_next

def rms(V): return math.sqrt(float(np.mean((V - TRUE) ** 2)))

def curve(runs, algo, lam, alpha):
    tot = n = 0
    for eps in runs:
        V = np.zeros(N)
        for ep in eps:
            algo(V, ep, lam, alpha); tot += rms(V); n += 1
    return tot / n

# ---------------- Part 2: Mountain Car, Sarsa(lambda) over 8 tilings of 8 x 8 ----------------
NT, TWP, TWV = 8, 1.7 / 8, 0.14 / 8
NW = NT * 9 * 9 * 3
CAP = 5000

def feats(x, v, a):
    return [((i * 9 + math.floor((x + 1.2) / TWP + i / 8)) * 9 + math.floor((v + 0.07) / TWV + ((3 * i) % 8) / 8)) * 3 + a
            for i in range(NT)]

def q(w, F):
    s = 0.0
    for i in F: s += w[i]
    return s

def greedy(w, x, v):
    best, bq = 0, -math.inf
    for a in range(3):
        qa = q(w, feats(x, v, a))
        if qa > bq: bq, best = qa, a
    return best

def step(x, v, a):
    v = v + 0.001 * (a - 1) - 0.0025 * math.cos(3 * x)
    v = min(0.07, max(-0.07, v)); x = x + v
    if x < -1.2: x, v = -1.2, 0.0
    return x, v

def sarsa_lambda_episode(w, rng, lam, alpha, kind, gamma=1.0):
    z = np.zeros(NW); x, v = -0.6 + 0.2 * rng(), 0.0
    A = greedy(w, x, v); F = feats(x, v, A); q_old = 0.0; n = 0
    while True:
        x2, v2 = step(x, v, A); n += 1; done = x2 >= 0.5 or n >= CAP
        if kind == 'dutch':                                   # true online Sarsa(lambda)
            Q = q(w, F); Q2 = 0.0; A2 = 0; F2 = None
            if not done: A2 = greedy(w, x2, v2); F2 = feats(x2, v2, A2); Q2 = q(w, F2)
            delta = -1 + gamma * Q2 - Q; zx = sum(z[i] for i in F)
            z *= gamma * lam
            for i in F: z[i] += 1 - alpha * gamma * lam * zx
            w += alpha * (delta + Q - q_old) * z
            for i in F: w[i] -= alpha * (Q - q_old)
            q_old = Q2
            if done: break
            x, v, A, F = x2, v2, A2, F2
        else:                                                 # replacing or accumulating traces
            delta = -1.0
            for i in F:
                delta -= w[i]
                if kind == 'rep': z[i] = 1.0
                else: z[i] += 1.0
            if done: w += alpha * delta * z; break
            A2 = greedy(w, x2, v2); F2 = feats(x2, v2, A2)
            for i in F2: delta += gamma * w[i]
            w += alpha * delta * z; z *= gamma * lam
            x, v, A, F = x2, v2, A2, F2
    return n

def mc_run(lam, alpha, kind, n_ep, seed):
    w = np.zeros(NW); rng = mulberry32(seed)
    return [sarsa_lambda_episode(w, rng, lam, alpha, kind) for _ in range(n_ep)]

Wrap-up · 12.13

Five lines to remember

  • The λ-return averages every n-step return with weights (1−λ)λn−1, pooling the tail onto the final return. λ = 0 is TD(0), λ = 1 is Monte Carlo, and the error-minimising setting is almost always strictly in between.
  • The forward view (look ahead from each state) and the backward view (hand each TD error back along a trace that decays by γλ) are the same computation when the values are frozen: Gλt − V(St) = Σk(γλ)k−tδk. TD(λ) is the backward view with accumulating traces and one weight update per step.
  • Truncating the λ-return at a horizon h hands the leftover weight λh−t−1 to a bootstrapped return; redoing all the truncated updates at every step is the online λ-return algorithm, the ideal that uses each episode’s information as soon as it exists.
  • True online TD(λ) computes the online λ-return algorithm exactly for linear function approximation, at the cost of TD(λ), using the dutch trace z ← γλz + (1 − αγλzℤx)x and a correction for how much the current state’s value just changed. The dutch trace also falls out of running linear Monte Carlo forward in time; traces are about computation, not about TD.
  • Accumulating traces add on revisits, replacing traces reset to 1, dutch traces add a little less each time. For control, Sarsa(λ) with any of them turns a single success into credit for the whole path, which is why it learns Mountain Car in a fraction of the episodes one-step Sarsa needs; accumulating traces with binary features and a large step size are the combination to avoid.

Mistakes that are easy to make

bookkeeping

Decaying the trace at the wrong moment

Decay, then add the current gradient, then update w with that trace. Updating with last step’s trace, or adding before decaying, gives a method that is subtly not TD(λ); the hand examples in sections 3 and 7 are the quickest way to check an implementation.

episodes

Carrying the trace across episodes

z must be reset to 0 at the start of every episode; the final TD error of one episode has nothing to say about the first state of the next. (With γλ < 1 the leak fades, but it is still wrong.) Weights, of course, carry over.

step size

Reusing TD(0)’s α at large λ

The trace multiplies the effective step: with accumulating traces a revisited state can receive several α’s worth of one error. Re-tune α whenever λ changes, or use dutch traces, whose addition shrinks as the trace grows.

terminal states

Bootstrapping from the terminal state

At the last transition the next value is 0 by definition, not v̂(terminal, w). With function approximation it is easy to feed the terminal state’s features through the approximator by accident and learn a value for “after the end”.

traces and FA

Replacing traces with non-binary features

“Set the trace to 1” only makes sense for a feature that is either on or off. With real-valued features use accumulating or dutch traces; the dutch trace is defined for any x.

off-policy data

Using Sarsa(λ) traces off-policy

Sarsa(λ) credits the actions actually taken. With exploratory actions, replayed data or a different behaviour policy the trace must be cut or re-weighted (Watkins’s Q(λ), Tree-Backup(λ), Retrace); that is chapter 3.2d.

Check your understanding

Why do the weights (1−λ)λn−1 sum to 1, and what happens to the weight of returns that reach the end of an episode?

They are a geometric series: (1−λ)(1 + λ + λ2 + …) = (1−λ)/(1−λ) = 1. Every n-step return with t+n ≥ T is the same number, the Monte Carlo return Gt, so their weights can be added up: (1−λ)Σn≥T−tλn−1 = λT−t−1. In the five-step hand example that pooled weight was 1/16 for the first visit to C and 1 for the visit to E.

TD(λ) with accumulating traces reproduces the offline λ-return algorithm exactly in the hand example but only approximately on the 19-state walk. What is different?

The forward–backward identity needs the values to stay fixed while the TD errors of one episode are summed. In the hand example every TD error before the last step was 0, so the values did not change until the final update and the identity held exactly. On the random walk the values change at every step, so each later TD error is computed from already-updated values; the sum of the online updates differs from the offline total by terms of order α2. The smaller α is, the closer the two agree.

In the online λ-return algorithm, why is wh0 the same for every horizon h, and what does the algorithm output?

Each pass is a fresh re-run of the episode so far, so it must start from the weights that were in force when the episode began; otherwise the earlier updates would be applied twice. The output is the diagonal of the triangle: at time h the algorithm acts on wh = whh, the last vector of the pass with horizon h. Those diagonal vectors are also the ones the truncated returns bootstrap from, which is what true online TD(λ) reproduces one step at a time.

Set α = 1 in the dutch trace. Which trace do you get, and what does that say about replacing traces?

For a binary feature with trace z, the dutch update gives γλz + (1 − γλz)·1 = 1: the replacing trace. So the replacing trace is the dutch trace at the extreme step size, and for any smaller α it under-credits revisited features relative to the trace that the online λ-return algorithm actually implies. That is why true online methods have largely replaced replacing traces: they come with an exact forward view, the replacing trace does not.

In the Mountain Car project the accumulating trace at α = 1/8 stops reaching the flag within 5,000 steps while the replacing and dutch traces learn in a few hundred. What goes wrong?

The car moves slowly through tile space, so the same 8 tiles stay active for many consecutive steps and their accumulating traces grow toward 1/(1−γλ), ten at λ = 0.9. Each TD error is then applied with an effective step size ten times α, the values overshoot, and the greedy policy they imply thrashes. Replacing traces cap every trace at 1; the dutch trace shrinks the addition by αγλzℤx and stays bounded as well. Lowering α rescues the accumulating trace, at the price of slower learning everywhere else.
