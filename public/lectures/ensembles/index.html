Forests & Boosting

Many weak voters beat one expert

One decision tree is quick, readable — and jumpy: change a few training points and it grows a different tree. The fix is to stop relying on one. Train hundreds of trees on different views of the data and let them vote (random forests), or train them one after another, each fixing the last one's mistakes (boosting). These two ideas win most competitions on tabular data. On the right, watch a forest grow: add trees and see the jagged single-tree boundary smooth into a confident one.

The idea

The wisdom of crowds

At a 1906 country fair in Plymouth, 787 people guessed the weight of an ox. Francis Galton collected the tickets: individual guesses were all over the place, but their median, 1,207 lb, was within 1% of the true 1,198 lb. Errors that point in different directions cancel when you average them. The catch: they must be different. If everyone copies the same loudmouth, averaging can't fix the shared error. Try both:

\[ \text{Var}\Big(\frac{1}{B}\sum_{b=1}^{B} X_b\Big) = \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2 \]
Read it as: B guessers, each with error spread σ and pairwise correlation ρ. More guessers shrink the second term towards zero, but the first term, ρσ², never goes away. So an ensemble needs many members that are as different as possible. Random forests are an engineering answer to exactly this formula.
Say it“The variance of an average is rho sigma squared plus one-minus-rho over B times sigma squared.”

Ensemble idea 1

Bagging: many trees, different views

We only have one training set, so where do different trees come from? Bootstrap it: draw n examples with replacement from the n we have. Each draw repeats some examples and leaves others out, so each tree sees a slightly different dataset and grows a different shape. Average their votes: bootstrap aggregating — bagging (Breiman, 1996). Six bootstrap trees below; the big plot is their vote.

\[ P(\text{example } i \text{ is never drawn}) = \Big(1 - \frac{1}{n}\Big)^{n} \;\longrightarrow\; \frac{1}{e} \approx 0.368 \]
Read it as: each of the n draws misses example i with probability 1 − 1/n. So every bootstrap sample contains about 63.2% of the distinct examples; the other 36.8% are out-of-bag for that tree, a fact we'll exploit shortly.
Say it“The chance of being left out is one minus one over n, to the n, which tends to one over e.”

Ensemble idea 1, sharpened

Random forests: decorrelating the trees

Bagged trees still look alike: if one feature is very strong, every tree splits on it first. Remember the ρσ² term. Random forests (Breiman, 2001) add a second dose of randomness: at every split, each tree may only consider a random subset of the features (max_features). Trees become more different and ρ falls, so the average holds up — and on data with many correlated features it improves — even though each single tree gets worse.

A free bonus

Out-of-bag: a test set for free

Every training example was left out by about 37% of the trees. Ask only those trees to predict it, and you have an honest prediction from models that never saw it. Do that for every example and you get the out-of-bag (OOB) error — a built-in estimate of test error, with no separate validation set and no cross-validation.

\[ \hat{y}_{\text{OOB}}(x_i) = \text{vote of the trees } b \text{ with } i \notin \text{bootstrap}_b \]
Read it as: for each training example, collect votes only from the trees that didn't train on it. The accuracy of these votes tracks real test accuracy closely.
Say it“The out-of-bag prediction for example i is the vote of the trees that never saw i.”

Ensemble idea 2

AdaBoost: learning from mistakes

Boosting builds the team in sequence. Start with a stump — a tree with one question. Then increase the weight of every example it got wrong, so the next stump is forced to care about them. Each stump gets a say α based on how good it was. Freund & Schapire's AdaBoost (1997) turns rules barely better than coin flips into a strong classifier. Press Next round: dot size is weight.

\[ \varepsilon_t = \sum_{i:\,h_t(x_i)\ne y_i} w_i, \qquad \alpha_t = \tfrac{1}{2}\ln\frac{1-\varepsilon_t}{\varepsilon_t} \]
Read it as: εt is the stump's weighted error; its say αt is large when the error is small, zero for a coin flip.
Say it“Alpha is half the log of one-minus-epsilon over epsilon.”
\[ w_i \leftarrow w_i\, e^{-\alpha_t\, y_i\, h_t(x_i)}, \qquad H(x) = \text{sign}\Big(\sum_t \alpha_t h_t(x)\Big) \]
Read it as: with labels ±1, a mistake makes y·h = −1, so its weight is multiplied by eα (grows); a correct one shrinks. Then renormalise. The final answer is the α-weighted vote.
Say it“Multiply each weight by e to the minus alpha y h, and predict the sign of the weighted sum of stumps.”

Ensemble idea 2, generalised

Gradient boosting: fitting the residuals

Friedman (2001) saw boosting as gradient descent in “function space”. For regression it's beautifully plain: start with the average; fit a small tree to the residuals (what's still wrong); add a fraction ν of it; repeat. Each tree is weak, but every one of them chips away at the remaining error. Step through the stages and watch the residuals flatten.

\[ r_i^{(m)} = y_i - F_{m-1}(x_i), \qquad h_m \approx r^{(m)}, \qquad F_m(x) = F_{m-1}(x) + \nu\, h_m(x) \]
Read it as: the residual r is the negative gradient of squared error; each small tree hm learns to predict it; the learning rate ν (0.05–0.3) adds only part of the correction, so many small steps beat one greedy leap. XGBoost and LightGBM are fast, regularised versions of exactly this loop.
Say it“Fit a tree to the residuals, then add nu times that tree to the model.”

Choosing

Bias, variance and the ensemble zoo

The two families fix opposite problems. Bagging and forests average deep, low-bias, high-variance trees, so they mostly reduce variance; they're hard to overfit by adding trees and are trained in parallel. Boosting adds shallow, high-bias trees in sequence, so it mostly reduces bias; it is usually the most accurate, but it can overfit if you add too many stages, and needs its learning rate tuned.

Real-world project

Project: pricing California homes

The California housing data (Pace & Barry, 1997) describes every census block group in the 1990 US census: median income, house age, rooms, occupancy, population and location, with the median house value as the target (in $100,000s; values were capped at $500,000). The same project in scikit-learn

import numpy as np
from sklearn.datasets import fetch_california_housing
from sklearn.linear_model import LinearRegression
from sklearn.tree import DecisionTreeRegressor
from sklearn.ensemble import RandomForestRegressor, GradientBoostingRegressor
from sklearn.metrics import r2_score

d = fetch_california_housing()
pick = np.random.RandomState(7).choice(len(d.target), 5000, replace=False)
X, y = d.data[pick], d.target[pick]                     # rounded as on this page
X_tr, y_tr, X_te, y_te = X[:4000], y[:4000], X[4000:], y[4000:]

models = {"linear regression": LinearRegression(),
          "single tree (depth 6)": DecisionTreeRegressor(max_depth=6, random_state=0),
          "random forest (100)": RandomForestRegressor(n_estimators=100, random_state=0),
          "gradient boosting (300)": GradientBoostingRegressor(n_estimators=300, max_depth=3,
                                                               learning_rate=0.1, random_state=0)}
for name, m in models.items():
    print(f"{name:24s} test R² = {r2_score(y_te, m.fit(X_tr, y_tr).predict(X_te)):.4f}")
linear regression        test R² = 0.5869
single tree (depth 6)    test R² = 0.6393
random forest (100)      test R² = 0.7661
gradient boosting (300)  test R² = 0.7934

Linear regression, the single tree and gradient boosting are deterministic, so the page reproduces scikit-learn's numbers. A random forest depends on its random draws, so your browser's forest will land close to, but not exactly on, scikit-learn's 0.7661.

Wrap-up

Five lines to remember

  • Averaging many different, decent models beats any one of them — as long as their errors aren't the same (the ρσ² term).
  • Bagging trains deep trees on bootstrap samples and votes; random forests also restrict each split to random features, making the trees more different.
  • Out-of-bag predictions give a free, honest estimate of test error.
  • Boosting builds trees in sequence: AdaBoost re-weights the mistakes, gradient boosting fits the residuals with a small learning rate.
  • Forests mostly cut variance and are hard to break; boosting mostly cuts bias and is usually the most accurate — on California housing, 0.79 R² against 0.64 for the best single tree.

Check your understanding

Why does adding more trees to a random forest (almost) never cause overfitting, while adding more stages to boosting can?

Forest trees are independent; more of them only reduce the variance of the average, which converges. Each boosting stage fits what's left of the training error, so with enough stages it starts fitting noise; use a small learning rate and early stopping.

What would happen to a random forest if every tree used the same bootstrap sample and all features?

Every tree would be identical (ρ = 1): the forest would be one tree, with all its variance. Both sources of randomness exist to make the trees different.

Why is the out-of-bag estimate honest?

Each example is predicted only by trees that never saw it during training, exactly like a held-out test example.

In AdaBoost, a stump has weighted error ε = 0.5. What is its say α, and why?

α = ½ ln(0.5 / 0.5) = 0. A coin-flip rule carries no information, so it gets no vote.

Gradient boosting with learning rate 1 fits the training data fast but tests worse than 0.1. Why?

Each full-size step lets one greedy tree commit hard to its view of the residuals, noise included. Small steps average many trees' views, a form of regularisation (“shrinkage”).
