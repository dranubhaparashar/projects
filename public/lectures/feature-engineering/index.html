Feature Engineering

Same model, better inputs

A model never sees a house. It sees a row of numbers, and it can only find patterns that those numbers make easy to find. Feature engineering is the craft of choosing that row: scaling it, encoding words as numbers, filling its holes, bending skewed columns straight, inventing new columns from what you know, and throwing out the ones that only add noise. On the right, 1,460 real house sales and one straight line. Switch the feature the line is allowed to use and watch how much of the price it explains.

The idea

The model sees only what you hand it

Here are two years of Washington, D.C.’s Capital Bikeshare: one dot per day, the day’s temperature against the number of rides. A linear model draws a straight line through it, and a straight line is all it can draw from one column. Yet the cloud bends: rides rise with warmth and fall again in the sticky heat, and the second year is busier than the first. The model has no way to know either thing. You do. Hand it a column that says “degrees above c”, and another that says which year it is, and the very same least-squares fit suddenly bends and splits. Switch the features on, then drag c to find where the heat starts to hurt.

\[ \begin{aligned} \hat y = w_0 &+ w_1\, t \\ &+ w_2 \max(0,\ t - c) \\ &+ w_3\cdot\text{year} \end{aligned} \]
Read it as: t is the day’s temperature in °C. max(0, t − c) is zero on cool days and counts the degrees above c on hot ones, so w₂ is the change of slope once it gets hot. year is 0 for 2011 and 1 for 2012. The model is still a straight line in its columns; we made the columns curved. Every weight is fitted by ordinary least squares.
Say it“y-hat is w-nought plus w-one t, plus w-two times the degrees above c, plus w-three times the year.”

Scaling

Scaling: one ruler for every feature

Ames records a house’s overall quality on a 1–10 scale and its year of construction in years: one column moves by single points, the other by decades. Many methods care. k-NN and SVMs measure distances, so the column with the bigger numbers dominates (chapter 1.6 showed this). Ridge and lasso penalise weights, so a column’s units decide how hard it is punished. And gradient descent, the engine inside neural networks, crawls when one direction of its error bowl is much steeper than another. Below we fit log price from the two columns by gradient descent, with the same safe step size rule each time. Change the scaling and run the descent.

\[ \begin{aligned} z &= \frac{x - \mu}{\sigma} && \text{(standardise)} \\ x' &= \frac{x - \min}{\max - \min} && \text{(min–max)} \end{aligned} \]
Read it as: standardising subtracts the column’s mean and divides by its standard deviation, so every column has mean 0 and spread 1. Min–max squeezes it into [0, 1]. Both are learned from the training data and then applied, unchanged, to new data. Trees don’t care either way: a split at 1985 is the same split at z = 0.46.
Say it“z is x minus its mean, over its standard deviation.”
\[ \begin{aligned} \kappa &= \frac{\lambda_{\max}(H)}{\lambda_{\min}(H)}, \quad H = \tfrac1n X^{\top}X \\ \text{steps} &\approx \tfrac{\kappa}{2} \,\ln\tfrac{1}{\varepsilon} \end{aligned} \]
Read it as: H describes the curvature of the squared-error bowl (X holds the centred, scaled columns). Its largest eigenvalue fixes the biggest safe step, 1/λmax; its smallest says how slowly the flattest direction is then explored. The ratio κ (the condition number) is how many times longer the bowl is than it is wide, squared. With the step 1/λmax, gradient descent needs about (κ/2) ln(1/ε) steps to cut the remaining error to a fraction ε of where it started.
Say it“Kappa is the largest curvature over the smallest; descent needs about kappa over two, times log one over epsilon, steps.”

Encoding

Encoding categories as numbers

Models do arithmetic, so a word like “CollgCr” (the College Creek neighbourhood) has to become numbers first. The lazy way numbers the neighbourhoods 0, 1, 2… alphabetically. But then the model believes Blueste lies “between” Blmngtn and BrDale, and a linear model must draw one straight line through an order that means nothing. One-hot encoding gives each category its own 0/1 column, so each gets its own weight. When the categories do have an order, as kitchen quality does (fair < typical < good < excellent), an ordinal code 2, 3, 4, 5 is honest and costs one column. Try all four encodings and click a column of dots to see how that category is encoded.

\[ \begin{aligned} \text{one-hot: } &x_k = [\,c = k\,], \ \ k = 1..K \\ \text{ordinal: } &x = \text{rank}(c) \end{aligned} \]
Read it as: [c = k] is 1 if the category is k and 0 otherwise, so a house sets exactly one of the K columns. With an intercept in the model, any K−1 of them carry the same information (the last is “none of the others”); dropping one avoids the dummy-variable trap in plain least squares, while ridge copes either way. The ordinal code is a single column, and it forces equal steps between neighbouring levels.
Say it“Column k is one when the category is k, zero otherwise; the ordinal code is just the rank.”

Missing values

Missing values: filling the holes

Real tables have holes, and most models refuse to run on them. First ask why a value is missing. In Ames, a blank pool quality almost always means “no pool” (1,453 of 1,460 houses): the blank is information, so encode it as its own level. A blank street frontage (259 houses) is a genuine unknown. For those you impute: fill in a guess, and usually add a 0/1 column that remembers the guess was made. To grade the guesses we need the truth, so below we take the 1,201 houses whose frontage is known and punch our own holes. Change how the holes are made and how they are filled.

\[ \begin{aligned} \text{mean: } &\hat x_i = \bar x_{\text{obs}} \\ \text{regression: } &\hat x_i = a + b\,\ln(\text{lot area}_i) \end{aligned} \]
Read it as: the mean (or median) fills every hole with the same number, which is simple but squashes the column’s spread and ignores everything else we know about the house. Regression imputation predicts the missing value from another column, here the lot area, with a and b fitted on the rows where frontage was observed. Both assume the holes are not hiding something systematic.
Say it“Fill a hole with the observed mean, or with a line fitted on the observed rows.”

Transforms

Taming skew with logs and powers

House prices are skewed: most sales sit between $100k and $250k, and a long tail stretches to $755k. A least-squares model fitted to raw prices spends its effort on the tail, where a $50k miss is routine, and treats a $50k miss on a $90k cottage as equally bad. Take logs and the tail folds in, and errors become relative: a miss of 0.1 in log price is about 10% either way. The Box–Cox family (1964) is a dial of such transforms, with the log at λ = 0. Turn λ until the histogram looks like the bell, then let the page find the best λ.

\[ x^{(\lambda)} = \begin{cases} \dfrac{x^{\lambda} - 1}{\lambda} & \lambda \ne 0 \\[6pt] \ln x & \lambda = 0 \end{cases} \]
Read it as: for x > 0. λ = 1 only shifts the data, λ = ½ is a square root, λ = 0 the log (the limit of the top line), λ = −1 a reciprocal. Smaller λ pulls a long right tail in harder. The “best” λ maximises the likelihood that the transformed values are normal.
Say it“x to the lambda minus one, over lambda; and the log of x when lambda is zero.”
\[ g_1 = \frac{\tfrac1n\sum_i (x_i - \bar x)^3}{\Big(\tfrac1n\sum_i (x_i - \bar x)^2\Big)^{3/2}} \]
Read it as: the skewness: the average cubed deviation, in units of the standard deviation cubed. Cubing keeps the sign, so a long right tail gives g₁ > 0 and a long left tail g₁ < 0. A symmetric bell has g₁ = 0.
Say it“Skewness is the mean cubed deviation over the standard deviation cubed.”

Crafting features

Crafting features from what you know

Some of the best features are invented. A house’s total floor area is basement plus ground floor plus upstairs; its age is the sale year minus the build year. Neither is a column in the raw table, and both are worth more to a model than their parts. Time needs special care. Here are 11,865 working-day hours of Capital Bikeshare rides: a morning rush, a lunchtime bump, an evening rush. Hour 23 and hour 0 are neighbours on the clock but 23 apart as numbers. Wrap the hour round a circle with a sine and a cosine and they become neighbours again; add higher harmonics and the curve can follow both rushes. Try each encoding of the hour.

\[ \begin{aligned} \phi_K(h) = \big(&\sin\tfrac{2\pi h}{24}, \cos\tfrac{2\pi h}{24}, \dots, \\ &\sin\tfrac{2\pi K h}{24}, \cos\tfrac{2\pi K h}{24}\big) \end{aligned} \]
Read it as: each pair (sin, cos) of harmonic k places the hour on a circle that goes round k times a day, so 23:00 sits right next to 0:00. K harmonics give 2K columns, and a linear model on them can draw any smooth daily curve with up to K bumps. One-hot hours (23 columns) can draw any 24 values at all, the ceiling for a model that knows only the hour.
Say it“Phi-K of h is the sines and cosines of two pi k h over 24, for k from one to K.”

The pipeline rule

Target encoding and the pipeline rule

One-hot encoding a ZIP code gives you thousands of columns. A popular shortcut is target encoding: replace each category by the average target of the training rows in it. It is powerful and dangerous. If the averages are computed on all the data before cross-validation, each row’s own answer is baked into its feature, and with many small categories the model learns to read it back. Below, 400 rows, a category with L levels assigned at random, and a target that is pure noise: no honest method can beat R² = 0. Raise the number of levels and compare the wrong way with the right way.

\[ \text{enc}(c) = \frac{\sum_{i:\,c_i = c} y_i \;+\; m\,\bar y}{n_c + m} \]
Read it as: the sum of the targets in category c plus m “imaginary” rows at the overall mean ȳ, divided by the nc real rows plus m. Small categories are pulled towards ȳ (this is smoothing, or shrinkage); big ones keep their own average. A category never seen in training gets ȳ. The right way computes it from the training fold only, and even there each training row’s encoding is cross-fitted from the other training rows (as scikit-learn’s TargetEncoder does), so a row’s own y never enters its own feature.
Say it“The encoding of c is the sum of its targets plus m times the mean, over its count plus m.”
\[ \begin{aligned} \theta &= \text{fit}(\text{train fold}) \\ X_{\text{train}} &= \text{transform}_\theta(\text{train fold}) \\ X_{\text{val}} &= \text{transform}_\theta(\text{val fold}) \end{aligned} \]
Read it as: the pipeline rule. Every learned step (scaler means, imputation medians, one-hot vocabularies, target encodings, selected columns) is fitted on the training fold and only applied to the validation fold. scikit-learn’s Pipeline does this for you inside cross-validation; doing it by hand is where leaks start.
Say it“Fit on the training fold, transform both folds with what was fitted.”

Selection

Feature selection: fewer, better inputs

More columns always lower the training error, because a least-squares fit can only use an extra column or ignore it. On new data, useless columns add noise to every prediction. Feature selection keeps the useful ones. A filter ranks columns by a quick score, such as their correlation with the target, one at a time. A wrapper such as forward selection adds, at each step, the column that most reduces the error given those already chosen, so it skips a column that only repeats what it has. (Lasso, in the project, is the third family: selection built into the fit.) Below: 33 numeric Ames columns, plus as many columns of pure noise as you like, and a plain least-squares model. The ranking is redone inside every training fold, the right way. Slide k and add noise.

\[ r_j = \frac{\sum_i (x_{ij} - \bar x_j)(y_i - \bar y)}{\sqrt{\sum_i (x_{ij}-\bar x_j)^2 \sum_i (y_i-\bar y)^2}} \]
Read it as: the filter scores column j by its correlation with the target, alone, and keeps the k largest |rj|. Fast, but blind to redundancy: three columns that all measure size score high together.
Say it“r-j is the correlation between column j and y.”
\[ j^{*} = \arg\min_{j \notin S}\ \text{RSS}\big(S \cup \{j\}\big) \]
Read it as: start with no columns (S empty). At each step, try adding each unused column, refit, and keep the one with the smallest residual sum of squares. The order it adds columns in is a ranking; cross-validation then chooses how many to keep.
Say it“j-star is the column whose addition gives the smallest residual sum of squares.”

Real-world project

Project: pricing 1,460 Ames houses, step by step

Dean De Cock (2011) assembled the Ames Housing data from the city assessor’s office of Ames, Iowa, as a modern replacement for the old Boston housing set: every residential sale from 2006 to 2010, with 79 columns describing each house, from lot shape to kitchen quality. We use the 1,460-sale version on OpenML (data set 42165, the training half of Kaggle’s competition). The model never changes: ridge regression (α = 10), scored by 5-fold cross-validation on the error of log price, the same yardstick Kaggle uses. Only the features change, one step at a time, and every step lives inside the pipeline, re-fitted on each training fold.

The same project in scikit-learn

import numpy as np, pandas as pd
from sklearn.model_selection import KFold, cross_val_predict
from sklearn.pipeline import make_pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.linear_model import Ridge, Lasso

df = pd.read_csv("ames.csv")                           # OpenML 42165: 1,460 Ames sales
y = df.pop("SalePrice").to_numpy(float)
num  = [c for c in df if pd.api.types.is_numeric_dtype(df[c]) and c != "Id"]
holey = [c for c in num if df[c].isna().any()]               # LotFrontage, MasVnrArea, GarageYrBlt
full = [c for c in num if c not in holey]                    # 33 complete numeric columns
qual = ["ExterQual", "ExterCond", "BsmtQual", "BsmtCond", "HeatingQC",
        "KitchenQual", "FireplaceQu", "GarageQual", "GarageCond", "PoolQC"]
nominal = [c for c in df if c not in num + qual + ["Id"]] + ["MSSubClass"]
for c in qual: df[c] = df[c].map({"Po": 1, "Fa": 2, "TA": 3, "Gd": 4, "Ex": 5}).fillna(0)  # missing = none
for c in nominal: df[c] = df[c].astype(object).where(df[c].notna(), "None").astype(str)
df["TotalSF"] = df.TotalBsmtSF + df["1stFlrSF"] + df["2ndFlrSF"]
df["TotalBath"] = df.FullBath + 0.5 * df.HalfBath + df.BsmtFullBath + 0.5 * df.BsmtHalfBath
df["Age"], df["RemodAge"] = df.YrSold - df.YearBuilt, df.YrSold - df.YearRemodAdd
df["QualSF"] = df.OverallQual * df.GrLivArea
crafted = ["TotalSF", "TotalBath", "Age", "RemodAge", "QualSF"]
for c in ["LotArea", "GrLivArea", "TotalSF", "1stFlrSF"]: df["log_" + c] = np.log1p(df[c])
logs = [c for c in df if c.startswith("log_")]

def pipeline(step, alpha=10):
    dense = [c for c in full if not (step >= 5 and c == "MSSubClass")]
    dense += (qual if step >= 4 else []) + (crafted if step >= 6 else []) + (logs if step >= 7 else [])
    parts = [("dense", StandardScaler(), dense)]
    if step >= 3: parts.append(("holey", make_pipeline(SimpleImputer(strategy="median", add_indicator=True), StandardScaler()), holey))
    if step >= 5: parts.append(("onehot", OneHotEncoder(handle_unknown="ignore"), nominal))
    model = Lasso(alpha=0.001, tol=1e-8, max_iter=200_000) if step >= 8 else Ridge(alpha=alpha)
    return make_pipeline(ColumnTransformer(parts, sparse_threshold=0), model)   # dense: exact solvers

cv = KFold(5, shuffle=True, random_state=0)
names = ["predict the mean", "33 numeric columns, raw price", "+ log target", "+ impute 3 holey columns",
         "+ ordinal quality scales", "+ one-hot categories", "+ crafted totals and ages", "+ logs of skewed areas", "lasso selection"]
print(f"step  {'':30s} cols  CV RMSE (log price)")
for step, name in enumerate(names):
    if step == 0: print(f"{0:4d}  {name:30s} {0:4d}  {np.sqrt(np.mean((np.log(y) - np.log(y).mean())**2)):.4f}"); continue
    pipe = pipeline(step); t = np.log(y) if step >= 2 else y
    p = cross_val_predict(pipe, df, t, cv=cv)
    p = p if step >= 2 else np.log(np.maximum(p, 10_000))      # raw-price model: clip, then score on log scale
    m = pipe.fit(df, t)[-1]; cols = m.coef_.size; nz = (m.coef_ != 0).sum()
    print(f"{step:4d}  {name:30s} {cols:4d}  {np.sqrt(np.mean((p - np.log(y))**2)):.4f}" + (f"   ({nz} non-zero)" if step == 8 else ""))
step                                 cols  CV RMSE (log price)
   0  predict the mean                  0  0.3993
   1  33 numeric columns, raw price    33  0.2005
   2  + log target                     33  0.1606
   3  + impute 3 holey columns         39  0.1629
   4  + ordinal quality scales         49  0.1587

The page re-implements each piece (median imputer with missing-value flags, standard scaler, one-hot encoder that ignores unseen categories, ridge by Cholesky, lasso by coordinate descent) and uses scikit-learn’s exact folds. Every number in the table agrees with scikit-learn to seven decimals, including the lasso’s 84 non-zero weights. One trap we hit on the way: when one-hot columns make the matrix sparse enough, scikit-learn’s ColumnTransformer hands Ridge a sparse matrix, Ridge then switches to an iterative solver that stops early, and step 5 came out 0.0000029 off. sparse_threshold=0 keeps the exact solver. Two caveats about the data. Three predictions of the raw-price model fall below $10,000 (two of them are negative, one as low as −$41,324) and are clipped so a log can be taken. And two enormous partial sales (houses 524 and 1299, over 4,500 sq ft, sold for under $200k) contribute about a fifth of the final model’s squared error on their own; De Cock himself recommends setting houses over 4,000 sq ft aside.

Wrap-up

Five lines to remember

  • A model can only use what its columns make visible. A kink, a year, a log or a sine wave you add by hand is a curve the linear model gets for free.
  • Scale features for anything that measures distance, penalises weights or runs gradient descent; trees don’t need it. Encode categories one-hot, or ordinally when they really are ordered.
  • Ask why a value is missing before filling it. “None” is often information; imputation needs a flag, and no imputer can fix holes that hide the large values.
  • Logs (or a Box–Cox power) tame skewed columns and turn price errors into relative errors; crafted totals, ages and cyclical encodings put domain knowledge into the row.
  • Every learned step (scaling, imputing, encoding, selecting) is fitted on the training fold only: put it in the pipeline, or your cross-validation score is a leak.

Check your understanding

You standardise a column using the mean and standard deviation of the whole data set, then split into train and test. What is wrong, and how big a problem is it?

The test rows helped set the scaler, a mild leak. Fit the scaler on the training data only (a pipeline does it inside every fold). For scaling the effect is usually small; for target encoding or feature selection it can be enormous.

A column “day of week” is stored as 1–7. How should a linear model see it?

As one-hot columns (six with an intercept), or as a sine and cosine of 2πd/7 if you expect a smooth weekly cycle. As a single number 1–7 it would force Sunday and Monday to be six steps apart and every day’s effect onto one straight line.

Incomes are often missing for the highest earners, who decline to answer. Will median imputation give an unbiased average income?

No. The holes are not random: they hide large values, so any imputer that learns from the observed rows fills them too low. Flag the imputed rows, and treat the result as biased unless you can model why values went missing.

A model is trained on log price and its CV RMSE is 0.13. Roughly how far off is a typical prediction, in dollars, for a $200,000 house?

e0.13 ≈ 1.14, so about 13–14%: roughly $26,000–28,000 either way. Errors on the log scale are relative errors.

Why can forward selection beat a correlation filter with the same number of columns?

The filter scores each column alone, so it happily picks several columns that all measure the same thing (size). Forward selection asks what each column adds given the ones already chosen, so it skips the redundant ones and picks up different information.
