Regularised Autoencoders: Sparse, Denoising & Contractive

Give the network room to copy, then make copying the wrong answer

Chapter 2.7 forced an autoencoder to learn by squeezing it through a narrow code. This chapter keeps the code wide and adds a rule instead: keep the code sparse, rebuild clean data from damaged copies, or keep the encoder insensitive to small nudges. Each rule makes plain copying fail, so the network has to learn where the data live. On the right, 300 points lie along a curl. Each arrow points from a spot to where an autoencoder sends it (long arrows are shortened), and the arrows of a denoising autoencoder all point back to the curl. Move your pointer over the picture (or drag a finger) to drop a point and watch the denoiser walk it home, then switch to the plain autoencoder, which has learned only to copy.

The problem

When copying is too easy

An autoencoder has an encoder f that turns an input x into a code h, and a decoder g that turns h back into a reconstruction r. It is trained to make r close to x. In chapter 2.7 the code was narrower than the input, an undercomplete autoencoder, so it had to keep only what mattered. Undercomplete is not a guarantee, though. Give the encoder and decoder enough power and even a one-number code can be abused: in principle the encoder could map the i-th training example to the number i and the decoder could memorise the examples, learning nothing about the space in between.

The opposite case is worse. If the code is as wide as the input, or wider (overcomplete), the network can learn the identity, r = x, and get zero error on every input, data or not. The fix this chapter studies is to keep the capacity and change the objective. A regularised autoencoder adds a rule that copying breaks: sparse codes, small derivatives, robustness to noise or missing values. These rules make the model learn something about the data distribution even when the code is wide.

Below, the 300 points lie along a curl, two numbers each. The network is 2→H→2 with tanh units in the middle and no rule at all. Pick a code width and press Train. Watch the arrows: each shows where the trained network sends the point at its tail. Then drag the ring off the curl.

\[ \begin{aligned} &\mathbf{h} = f(\mathbf{x}), \quad \mathbf{r} = g(\mathbf{h}) \\ &\min_{f,\,g}\ \frac1n \sum_{i=1}^n L\big(\mathbf{x}_i,\ g(f(\mathbf{x}_i))\big) \end{aligned} \]
Read it as: the plain objective. L measures how far the reconstruction is from the input; here L(x, r) = ‖x − r‖². Nothing in it rewards learning the shape of the data: a network that copies perfectly scores a perfect zero.
Say it“Minimise the average loss between each x and g of f of x.”
\[ \begin{aligned} \min_{f,\,g}\ \frac1n \sum_{i=1}^n \Big[ &L\big(\mathbf{x}_i,\ g(f(\mathbf{x}_i))\big) \\ &+ \Omega(\mathbf{h}_i, \mathbf{x}_i) \Big] \end{aligned} \]
Read it as: the regularised objective adds a penalty Ω. A sparse autoencoder uses Ω = λ∑|hj|; a contractive one uses Ω = λ‖∂f/∂x‖². A denoising autoencoder changes the input instead: it feeds a damaged copy x̃ and asks for the clean x. All three make the identity a bad solution.
Say it“Reconstruction loss plus a penalty omega on the code and the input.”

Rule one

Sparse codes: pay for every active unit

A sparse autoencoder adds a price for each unit that is switched on: Ω(h) = λ∑j|hj|. With 100 code units for a 64-pixel image, the network could copy, but copying through many active units is expensive, so it learns to describe each image with a few units. Each unit then has to stand for something that recurs across many images, which is exactly what a useful feature is.

Why this penalty? It is not weight decay. Weight decay is a prior on the parameters; the sparsity penalty has no prior on the parameters at all. Think of the autoencoder as a model with latent variables h and visible x, so that log p(x, h) = log p(h) + log p(x | h). Training approximately maximises log p(x, h) at one likely value of h, the one the encoder outputs. The reconstruction term plays log p(x | h). The sparsity term plays log p(h), and the absolute-value penalty is exactly what a Laplace prior on each hj gives (our codes are never negative, so only its positive half, an exponential, is in play). Other priors give other penalties: a Student-t prior gives a log penalty, and Andrew Ng’s popular version penalises the KL divergence between a target firing rate ρ and each unit’s average rate.

These are 1,500 real handwritten digits, 8×8 pixels each (the rest are held out). The network is 64→100→64 with sigmoid code units (each between 0 and 1), and the decoder’s weights tied to the encoder’s (transposed), so it cannot dodge the penalty by shrinking the code and enlarging the decoder. Set λ and press Train; then raise λ and train again. Watch most units fall silent while the rest turn from speckle into pieces of ink.

\[ \begin{aligned} \min\ \frac1n \sum_{i=1}^n \Big[ &\lVert \mathbf{x}_i - g(f(\mathbf{x}_i)) \rVert^2 \\ &+ \lambda \sum_{j=1}^{100} |h_{ij}| \Big] \end{aligned} \]
Read it as: squared reconstruction error plus λ times the total size of the code, averaged over the training digits. Pixels run from 0 (paper) to 1 (ink), so a digit’s squared error is summed over its 64 pixels. Sigmoid units make hj ≥ 0, so |hj| = hj, and the penalty pushes most of them close to zero.
Say it“Squared error plus lambda times the sum of the absolute code values.”
\[ \begin{aligned} p(h_j) &= \tfrac{\lambda}{2}\, e^{-\lambda |h_j|} \\ -\log p(\mathbf{h}) &= \sum_j \Big( \lambda |h_j| - \log \tfrac{\lambda}{2} \Big) \end{aligned} \]
Read it as: the Laplace prior is a sharp peak at zero with exponential tails. Its negative log is λ|hj| plus a constant that does not depend on h, so minimising the penalty is maximising the prior. The constant is why λ behaves like a prior’s rate: larger λ believes in smaller codes.
Say it“Minus log p of h is the sum of lambda times absolute h-j, minus log lambda over two.”

Rule two

Denoising: rebuild what was damaged

A denoising autoencoder (DAE) changes the task instead of adding a penalty. Each training step takes a clean example x, damages it with a corruption process C(x̃ | x), feeds the damaged x̃ to the encoder, and scores the output against the clean x. Copying is now useless: the input itself is wrong. To undo the damage the network has to know what digits look like, which strokes go together, which pixels are usually ink.

Formally, the DAE learns a reconstruction distribution pdecoder(x | h) with h = f(x̃), by stochastic gradient descent on the expected negative log-likelihood over training examples and fresh corruptions. Two common corruptions: add Gaussian noise to every pixel, or mask a random subset of pixels to zero, so the network must fill in missing values.

Below, two networks of the same shape (64→100→64, sigmoid code, tied weights) train side by side on the same digits: a plain autoencoder that sees clean inputs, and a DAE that sees damaged ones. Both are then shown the same damaged test digits. Choose a corruption and level, then press Train.

\[ \begin{aligned} &\tilde{\mathbf{x}} \sim C(\tilde{\mathbf{x}} \mid \mathbf{x}), \quad \mathbf{h} = f(\tilde{\mathbf{x}}) \\ &\min\ \mathbb{E}_{\mathbf{x} \sim \hat p_{\text{data}}}\, \mathbb{E}_{\tilde{\mathbf{x}} \sim C(\cdot \mid \mathbf{x})} \\ &\qquad \big[ -\log p_{\text{decoder}}(\mathbf{x} \mid \mathbf{h}) \big] \end{aligned} \]
Read it as: draw a training example, damage it, encode the damaged copy, and maximise the probability the decoder gives to the clean example. The outer average is over the training set, the inner one over fresh damage, redrawn every time the example is used.
Say it“Minimise the expected minus log-probability of the clean x, given the code of its corrupted copy.”
\[ \begin{aligned} &-\log \mathcal{N}\big(\mathbf{x};\, g(\mathbf{h}),\, \tfrac12 I\big) \\ &\quad = \lVert \mathbf{x} - g(f(\tilde{\mathbf{x}})) \rVert^2 + \tfrac{d}{2}\log \pi \\ &\tilde{\mathbf{x}} = \mathbf{x} + \sigma\boldsymbol{\epsilon} \ \text{ or } \ \tilde{x}_k = m_k x_k \end{aligned} \]
Read it as: if the decoder’s distribution is a Gaussian centred on g(h) with variance ½, the negative log-likelihood is just the squared error plus a constant (d = 64 pixels). For the corruptions, ε is standard Gaussian noise, and each mask bit mk is 0 with the chosen probability and 1 otherwise.
Say it“With a Gaussian decoder, the loss is the squared distance from the clean x to the reconstruction of the corrupted x.”

What a denoiser knows

The arrows estimate the score

The score of a distribution is the gradient of its log density, ∇x log p(x): an arrow at every point, pointing the way the density rises fastest. A DAE trained with Gaussian noise and squared error learns, at its best, to output the average clean point that could have produced a given noisy one, E[x | x̃]. A short calculation (often called Tweedie’s formula) shows that this average is the noisy point plus σ² times the score of the blurred data density. So the denoiser’s arrows r(x̃) − x̃ are a scaled estimate of the score: they point towards the data, longest where the density changes fastest.

That is what the hero showed, and here we can check it. Our curl is not just a picture: the points were drawn from a known mixture of 40 small Gaussians (standard deviation 0.05) strung along the curve, so the exact score of the blurred density can be computed. Choose a noise level σ and press Train; the coloured arrows are the network’s, the grey ones the exact answer. Then release the walkers.

\[ \begin{aligned} r^*(\tilde{\mathbf{x}}) &= \mathbb{E}[\mathbf{x} \mid \tilde{\mathbf{x}}] \\ &= \tilde{\mathbf{x}} + \sigma^2\, \nabla_{\tilde{\mathbf{x}}} \log p_\sigma(\tilde{\mathbf{x}}) \end{aligned} \]
Read it as: r* is the best possible denoiser under squared error. pσ is the data density blurred by the noise, N(0, σ²I). The step the best denoiser takes, r*(x̃) − x̃, is σ² times the score of pσ. For our mixture, pσ is again a mixture with variance 0.05² + σ² per component, so its score is a weighted pull towards the component centres.
Say it“The best denoiser returns x-tilde plus sigma squared times the score of the blurred density.”
\[ \begin{aligned} &\mathbb{E}\,\lVert r(\tilde{\mathbf{x}}) - \mathbf{x} \rVert^2 = \text{const} \\ &+ \sigma^4\, \mathbb{E}\, \Big\lVert \tfrac{r(\tilde{\mathbf{x}}) - \tilde{\mathbf{x}}}{\sigma^2} - \nabla \log p_\sigma(\tilde{\mathbf{x}}) \Big\rVert^2 \end{aligned} \]
Read it as: the denoising loss equals the error of the implied score, (r − x̃)/σ², measured against the true score, times σ4, plus a constant that does not depend on the network. The constant is the loss of the perfect denoiser r*. So training a DAE is fitting the score, a method called denoising score matching.
Say it“The denoising loss is sigma to the fourth times the squared score error, plus a constant.”

A short history

Training networks to clean up their input is old: LeCun (1987) and Gallinari and colleagues (1987) trained multilayer perceptrons to denoise, and Behnke (2001) used recurrent networks to clean images. What Vincent, Larochelle, Bengio and Manzagol (2008) added was the aim: denoising as a way to learn a good representation, with the denoising itself as a side effect. Hyvärinen (2005) had introduced score matching, fitting a model by matching its score to the data’s without ever normalising the density, and Vincent (2011) showed that a denoising autoencoder with Gaussian noise does a version of it: the identity in the second formula. Alain and Bengio (2014) proved that, as the noise shrinks, a well-trained DAE’s r(x) − x approaches σ² times the score of the data itself, and Bengio and colleagues (2013) turned a DAE into a sampler by alternating corruption and denoising, which is what the walkers do. Fitting scores at many noise levels and walking down them is the core of the diffusion models in the next chapter.

Rule three

Contractive: flatten the encoder

The third rule penalises derivatives. A contractive autoencoder (CAE) adds λ times the squared Frobenius norm of the encoder’s Jacobian: the sum of the squares of every ∂hi/∂xj. It wants a code that barely moves when the input moves. On its own that would make every input look the same; the reconstruction term pulls the other way, because different training points must get different codes. The compromise is a code that changes only where the data force it to: in the directions that lead from one training point to another, and not elsewhere.

“Contractive” is meant locally: a small neighbourhood of x is mapped to a smaller neighbourhood of h. The two rules are close cousins. Alain and Bengio showed that a DAE with small Gaussian noise behaves like a CAE whose penalty is on the whole reconstruction r(x) instead of on f. Two practical points. For a one-layer encoder the penalty is cheap (formula below), but for deep encoders it is expensive, so deep CAEs are usually built as a stack of one-layer CAEs, each trained on the codes of the one below. And the penalty can be dodged: the encoder can shrink its weights by a factor ε while the decoder grows by 1/ε. Rifai and colleagues tie the decoder’s weights to the encoder’s; our small network below charges its decoder a little weight decay instead.

The clearest picture is in one dimension. The 80 training points sit in four clusters on a line. The network is 1→24→1 with tanh units. Raise λ and press Train, then drag the probe along the axis.

\[ \begin{aligned} \Omega(\mathbf{h}, \mathbf{x}) &= \lambda \Big\lVert \frac{\partial f(\mathbf{x})}{\partial \mathbf{x}} \Big\rVert_F^2 \\ &= \lambda \sum_{i}\sum_{j} \Big( \frac{\partial h_i}{\partial x_j} \Big)^2 \end{aligned} \]
Read it as: J = ∂f/∂x is the Jacobian of the encoder, one row per code unit and one column per input. The penalty adds up the squares of all its entries, at every training point, so it is small only if no code unit reacts strongly to any input direction there.
Say it“Lambda times the squared Frobenius norm of the encoder’s Jacobian.”
\[ \begin{aligned} &h_i = \tanh(\mathbf{w}_i^\top \mathbf{x} + b_i) \ \Rightarrow \\ &\Big\lVert \frac{\partial f}{\partial \mathbf{x}} \Big\rVert_F^2 = \sum_i \big(1 - h_i^2\big)^2\, \lVert \mathbf{w}_i \rVert^2 \end{aligned} \]
Read it as: for a one-layer encoder, unit i’s gradient is (1 − hi²) wi. A unit adds nothing to the penalty where it is saturated (hi near ±1), so the cheap way to be contractive is to place units so that they are flat on the data and switch between clusters.
Say it“Sum over units of one minus h-i squared, squared, times the squared length of w-i.”

Representational power

Depth: why one layer is not enough

Autoencoders are often trained with a single layer each side, but they do not have to be. The universal approximation theorem says that a network with one hidden layer can approximate any reasonable function, so an autoencoder with one hidden layer in total can, in principle, represent the identity. But in such a network the mapping from input to code is shallow: the encoder is a single layer, and a single layer cannot enforce arbitrary constraints on the code, such as sparsity, or follow a curved structure. A deep encoder, with at least one hidden layer of its own, can approximate any mapping from input to code. Depth can also cut the cost of representing some functions exponentially, and reduce the training data needed. In practice deep autoencoders compress much better than shallow or linear ones (Hinton & Salakhutdinov, 2006); a common way to train them was to pretrain a stack of shallow autoencoders greedily, one layer at a time.

Here is the limit in a picture. Back on the curl, give the network a one-number code, which is all a curve needs. The decoder is the same in both networks (1→16→2, tanh). Press Train and switch between the encoders: the colours show the code each point of the plane receives.

\[ \begin{aligned} h_{\text{one layer}} &= \mathbf{w}^\top \mathbf{x} + b \\ h_{\text{two layers}} &= \mathbf{v}^\top \tanh(W\mathbf{x} + \mathbf{b}) + c \end{aligned} \]
Read it as: a one-layer encoder (with or without a squashing function on top) gives the same code to every point on a straight line, wᵀx = constant: its contours are parallel lines, so points from different turns of the curl that share a line share a code. A two-layer encoder with 16 tanh units can bend its contours to follow the curve.

Learning manifolds

Tangent directions of a digit

The idea behind all three rules is the manifold hypothesis: real data concentrate near a low-dimensional, curved surface inside the big input space. At each point the surface has a tangent plane, the few directions in which you can move and stay on it. For a digit these are small, meaningful changes: a slightly thicker stroke, a little slant, a shift. Moving in any other direction makes noise.

Every regularised autoencoder strikes the same bargain. The reconstruction term needs the code to tell training examples apart, so the code must change along the tangent directions. The rule (sparsity, denoising or contraction) wants the code to change as little as possible. So the code ends up sensitive only along the manifold, and the reconstruction function becomes flat across it, mapping nearby off-manifold points back on. The Jacobian of the encoder reads this off directly: its right singular vectors with large singular values are the tangent directions, and a contractive autoencoder makes the rest of the spectrum fall away quickly.

The non-parametric alternative, which methods such as Isomap, locally linear embedding and Laplacian eigenmaps build on, describes the manifold through a nearest-neighbour graph: each example and its neighbours define a little flat patch, and the patches are stitched together. That works when the manifold is smooth and densely sampled, but each patch learns only from its own neighbours. A manifold that twists in many places needs a patch per twist, and so a training example per patch, while a parametric encoder can share what it learns across the whole space. Train the autoencoder, then compare its tangent directions with the patch estimate from the digit’s 10 nearest training neighbours.

\[ \begin{aligned} J_f(\mathbf{x}) &= \frac{\partial f(\mathbf{x})}{\partial \mathbf{x}} = U \Sigma V^\top \\ T_{\mathbf{x}} &\approx \operatorname{span}(\mathbf{v}_1, \ldots, \mathbf{v}_d) \end{aligned} \]
Read it as: the singular value decomposition of the 100×64 Jacobian. Each right singular vector vk is a direction in pixel space (an 8×8 picture); its singular value σk says how strongly the code reacts to a step that way. The directions with large σk estimate the tangent plane Tx; the code is nearly blind to the rest.
Say it“J-f equals U Sigma V-transpose; the tangent plane is spanned by the first few v’s.”
\[ C_{\mathbf{x}} = \frac1k \sum_{\mathbf{x}' \in N_k(\mathbf{x})} (\mathbf{x}' - \bar{\mathbf{x}})(\mathbf{x}' - \bar{\mathbf{x}})^\top \]
Read it as: the local, non-parametric estimate. Nk(x) are the k = 10 training digits closest to x, x̄ their mean. The top eigenvectors of their covariance are the directions in which the neighbours differ most: the local patch’s tangent plane.
Say it“C-x is the covariance of the k nearest neighbours of x.”

Applications

Search by code: semantic hashing

Autoencoders earn their keep in two ways. The first is dimensionality reduction: a short code makes classifiers faster and often better, uses less memory, and puts similar examples near each other, which helps information retrieval. The extreme version is semantic hashing (Salakhutdinov & Hinton): make the code a few bits, and use those bits as an address in a hash table. Finding similar items is then a lookup: read out everything stored at the query’s address, and at the addresses one or two bit-flips away. No distances are computed at all.

To get binary codes, the code units are sigmoids, and during training noise is added just before the sigmoid. A unit sitting near ½ would pass on mostly noise, so to get information through, the network learns to push its code units into saturation, near 0 or 1. Our version ramps the noise up over training, as the original work did. The second application, anomaly detection, is the project: a model that reconstructs normal data well will reconstruct something unusual badly.

Below, a 64→32→8→32→64 autoencoder hashes every training digit into one of 256 buckets. Digit labels are used only to grade the results. Train with and without noise, then pick queries and widen the search radius.

\[ \begin{aligned} \mathbf{b}(\mathbf{x}) &= \mathbb{1}\big[f(\mathbf{x}) > \tfrac12\big] \in \{0,1\}^8 \\ d_H(\mathbf{b}, \mathbf{b}') &= \sum_{j=1}^{8} |b_j - b'_j| \end{aligned} \]
Read it as: threshold each of the 8 code units at ½ to get an 8-bit address. The Hamming distance dH counts the bits two addresses disagree on; a search of radius r returns every training digit whose address is within r flips of the query’s.
Say it“b of x is one where f of x exceeds a half; the Hamming distance counts the disagreeing bits.”
\[ \begin{aligned} h_j &= \operatorname{sigmoid}(a_j + \epsilon_j) \\ \epsilon_j &\sim \mathcal{N}(0, s_t^2) \end{aligned} \]
Read it as: during training only, each code unit’s input aj gets Gaussian noise before the sigmoid. Its size st grows from 0 to the chosen s over the first 30 of 40 epochs. At test time there is no noise.
Say it“h-j is the sigmoid of a-j plus noise of size s.”

Real-world project

Project: catching card fraud by what an autoencoder cannot rebuild

The Credit Card Fraud Detection data were collected by Worldline and the Machine Learning Group of the Université Libre de Bruxelles (Dal Pozzolo et al., 2015): 284,807 card transactions made by European cardholders over two days in September 2013, of which 492 (0.17%) are frauds. For confidentiality, 28 of the features, V1–V28, are principal components of the original, undisclosed variables; the others are Time and Amount. The data are published under the Open Database License (ODbL 1.0), with contents under the Database Contents License; we downloaded them from OpenML (dataset 1597). The extract embedded in this page is a derivative of that database and is shared under the same ODbL 1.0 licence.

The plan is the one from the last section: train a denoising autoencoder on normal transactions only, then flag the transactions it rebuilds worst. No fraud label is used in training. We drew 5,000 normal transactions at random: 3,000 to train on and 2,000 to test, plus all 492 frauds. Features are V1–V28 and log(1 + Amount), each standardised with the training mean and standard deviation and then squashed with asinh to tame their very long tails (stored in the page in steps of 0.04). The network is 29→16→6→16→29 with tanh units, trained by Adam (step 0.003, batches of 100, 40 passes); the anomaly score of a transaction is its squared reconstruction error, summed over the 29 features.

4 · Checking the browser against Python

The Python script below re-implements the page’s training exactly: the same random-number generator (ported to numpy), the same initial weights, shuffles and noise, the same Adam steps. It then scores the test set with scikit-learn’s metrics, and, because Python is not limited by page size, also scores all 281,315 normal transactions that were not used for training.

import numpy as np
from sklearn.metrics import roc_auc_score, average_precision_score
from sklearn.decomposition import PCA

D = np.load("cc_q.npz")                       # int8 codes of asinh(standardised features), scale 1/25
Q, y, tr, ten, frd = D["Q"], D["y"], D["tr"], D["ten"], D["frd"]
X = Q.astype(np.float64) / 25
Xtr, Xte = X[tr], X[np.concatenate([ten, frd])]
yte = np.r_[np.zeros(len(ten)), np.ones(len(frd))]

class Mulberry32:                              # the page's random numbers, vectorised
    K = 0x6D2B79F5
    def __init__(self, seed): self.seed, self.n = seed, 0
    def uniform(self, m):
        a = (self.seed + self.K * np.arange(self.n + 1, self.n + m + 1, dtype=np.uint64)) & 0xFFFFFFFF
        self.n += m; M = 0xFFFFFFFF
        t = ((a ^ (a >> 15)) * (1 | a)) & M
        t = ((t + (((t ^ (t >> 7)) * (61 | t)) & M)) & M) ^ t
        return ((t ^ (t >> 14)) & M).astype(np.float64) / 4294967296
    def gauss(self, m):                        # Box-Muller, one cosine per pair, as gaussOf does
        u = self.uniform(2 * m).reshape(m, 2); assert (u[:, 0] > 0).all()
        return np.sqrt(-2 * np.log(u[:, 0])) * np.cos(2 * np.pi * u[:, 1])

def make(sizes, seed):
    r = Mulberry32(seed)
    return [dict(W=np.sqrt(1 / a) * r.gauss(a * b).reshape(a, b), c=np.zeros(b)) for a, b in zip(sizes[:-1], sizes[1:])]
acts = ["tanh", "tanh", "tanh", "id"]
def forward(net, x):
    hs = [x]
    for l, a in zip(net, acts):
        z = hs[-1] @ l["W"] + l["c"]; hs.append(np.tanh(z) if a == "tanh" else z)
    return hs

def train(sigma, epochs=40, lr=0.003, B=100):
    net = make([29, 16, 6, 16, 29], 62); Rs, Rn = Mulberry32(7), Mulberry32(8)
    for l in net: l.update(mW=np.zeros_like(l["W"]), vW=np.zeros_like(l["W"]), mc=np.zeros_like(l["c"]), vc=np.zeros_like(l["c"]))
    t, n = 0, len(Xtr)
    for e in range(epochs):
        idx = list(range(n)); u = Rs.uniform(n - 1)
        for k, i in enumerate(range(n - 1, 0, -1)):
            j = int(np.floor(u[k] * (i + 1))); idx[i], idx[j] = idx[j], idx[i]
        for b in range(0, n, B):
            xb = Xtr[idx[b:b + B]]; m = len(xb)
            xin = xb + sigma * Rn.gauss(m * 29).reshape(m, 29) if sigma > 0 else xb
            hs = forward(net, xin); g = 2 * (hs[-1] - xb) / m; t += 1
            for li in range(3, -1, -1):
                if acts[li] == "tanh": g = g * (1 - hs[li + 1] ** 2)
                gW, gc, gin = hs[li].T @ g, g.sum(0), g @ net[li]["W"].T
                for P, G, M, V in (("W", gW, "mW", "vW"), ("c", gc, "mc", "vc")):
                    l = net[li]; l[M] = 0.9 * l[M] + 0.1 * G; l[V] = 0.999 * l[V] + 0.001 * G * G
                    l[P] = l[P] - lr * (l[M] / (1 - 0.9 ** t)) / (np.sqrt(l[V] / (1 - 0.999 ** t)) + 1e-8)
                g = gin
    return net

Wrap-up

Five lines to remember

  • An autoencoder whose code is as wide as its input, or whose encoder and decoder are too powerful, can learn to copy and so learn nothing. A regularised autoencoder keeps the capacity and adds a rule that copying breaks.
  • Sparse autoencoders add λ∑|hj|, which is the negative log of a Laplace prior on the code, not on the weights. Each unit becomes a feature that a few units combine to describe an input.
  • Denoising autoencoders rebuild clean x from a corrupted x̃. With Gaussian noise and squared error the best denoiser is x̃ + σ²∇ log pσ(x̃), so a DAE’s arrows estimate the score; this is denoising score matching, the seed of diffusion models.
  • Contractive autoencoders add λ‖∂f/∂x‖F². Against the reconstruction term, the code stays sensitive only along the data’s manifold: the Jacobian’s leading singular vectors are its tangent directions, and the reconstruction pulls nearby points back on.
  • Depth matters: a one-layer encoder’s code is constant along straight lines. In practice autoencoders reduce dimension, power retrieval (semantic hashing) and flag anomalies by reconstruction error; check them against a simple baseline such as PCA.

Check your understanding

A 2→16→2 autoencoder reaches almost zero error on its training data and on random points far from the data. What has it learned?

Essentially the identity: it copies whatever it is given, so its reconstruction error says nothing about whether an input looks like the data. It has learned nothing about the data distribution. A rule such as sparsity, denoising or contraction is needed to break the copy.

Why is the sparsity penalty λ∑|hj| not just weight decay with a different name?

Weight decay is a prior on the parameters. The sparsity penalty is a prior on the latent code h: it is −log p(h) for a Laplace prior, the log p(h) part of log p(x, h) = log p(h) + log p(x | h), evaluated at the code the encoder produces. It changes with every input; weight decay does not.

A DAE is trained with Gaussian noise of standard deviation σ = 0.2. At a noisy point it outputs r(x̃) = x̃ + (0.02, −0.01). What does that say about the blurred data density there?

r(x̃) − x̃ ≈ σ²∇ log pσ(x̃), so the estimated score is (0.02, −0.01)/0.04 = (0.5, −0.25): log-density rises fastest in that direction, at 0.56 per unit of distance.

Why does a contractive autoencoder need tied weights or decoder weight decay?

Otherwise the encoder can multiply its weights by a small ε and the decoder divide its weights by ε: the reconstruction is almost unchanged while the Jacobian penalty shrinks towards zero, so the penalty stops constraining anything.

In the project, PCA with six components scores fraud about as well as the autoencoder, or better. Give one reason this dataset favours a linear model.

The V1–V28 features are already principal components of the hidden original variables, so the normal transactions are largely described by linear structure; a linear reconstruction captures much of what matters, and the extra flexibility of the autoencoder buys little with 3,000 training examples.
