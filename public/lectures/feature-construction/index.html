Feature Construction for Linear RL

Polynomials, Fourier cosines, coarse coding and tile coding

A linear value function is a weighted sum of features, so it can only ever be as good as the features you hand it. Choosing them is where your knowledge of the problem goes in. On the right is Mountain Car: an underpowered car must rock back and forth to escape a valley. The map is the car’s state, position across and velocity up, shaded by how many steps a learner believes it still needs. That learner is a plain weighted sum over 8 overlapping grids of tiles, trained in your browser a moment ago. Touch anywhere on the map to drop the car in that state and watch it drive itself out.

The idea

Linear in the weights, not in the state

The last chapter fitted value functions of the form v̂(s, w) = w · x(s). Everything about that model is linear in w: the gradient is just x(s), semi-gradient TD has a single fixed point, and LSTD solves for it directly. Nothing forces it to be linear in the state. The feature vector x(s) can bend, multiply and chop the raw state numbers in any way you like, and the curvature of v̂ is exactly the curvature you built into x.

The catch is that a linear model cannot invent what its features leave out. In Mountain Car, how urgently you need to push depends on position and velocity together: a car near the bottom moving fast is in a very different place from one near the bottom standing still. With only the raw numbers as features, v̂ is a tilted plane and can represent no such interaction. Below, the target is the real thing: the fewest steps to the flag from every state, worked out (approximately) by value iteration on a 91 × 71 grid in your browser. Swap feature sets and see how close the best possible weighted sum comes. Drag the ring to read off a single state.

\[ \begin{aligned} \hat v(s,\mathbf w) &= \mathbf w^{\top}\mathbf x(s) \\ &= \sum_{i=1}^{d} w_i\,x_i(s) \\ \nabla_{\mathbf w}\hat v(s,\mathbf w) &= \mathbf x(s) \end{aligned} \]
Read it as: a state s is turned into d numbers x1(s) … xd(s), its features; the estimate is their weighted sum. Because the weights enter only by multiplication, the gradient with respect to w is the feature vector itself, whatever the features are. Here the weights are chosen by least squares over all 6,461 grid states, the best any learning rule could hope to reach with these features.
Say it“v-hat of s is w transpose x of s, the sum of w-i times x-i of s; its gradient in w is x of s.”

Recipe 1

Polynomial features

The most familiar way to add curvature is to multiply the state variables together and raise them to powers, exactly as in polynomial regression. For a state with k numbers s1, …, sk (each scaled to [0, 1]), an order-n polynomial basis contains every product in which each variable appears with a power from 0 to n. Order 1 in two dimensions gives 1, s1, s2 and the interaction s1s2; order 2 adds the squares and their products, nine features in all.

Two problems appear quickly. The count explodes with the number of state variables, so in practice you keep only a hand-picked subset. And the high powers all look alike: on [0, 1], s9 and s10 are both flat near 0 and shoot up near 1, so their columns are almost parallel. Least squares copes, but a gradient method creeps along those nearly parallel directions, as the race below will show. The target here is the true value of the 1,000-state random walk from the previous chapter. Raise the order, watch the fit and the basis, then add dimensions to see the bill.

\[ \begin{aligned} x_i(s) &= \prod_{j=1}^{k} s_j^{\,c_{i,j}} \\ c_{i,j} &\in \{0, 1, \dots, n\} \end{aligned} \]
Read it as: feature i is a product of the state variables, variable j raised to the power ci,j. Each feature is one choice of the k exponents. All exponents 0 gives the constant feature 1.
Say it“x-i of s is the product over j of s-j to the power c-i-j, each c between zero and n.”
\[ d = (n+1)^{k} \]
Read it as: each of the k variables picks one of n + 1 powers independently, so the full basis has (n + 1)k features. It grows exponentially with the number of state variables k.
Say it“The number of features is n plus one to the power k.”

Recipe 2

The Fourier basis

Any reasonable function on an interval can be built from waves. On [0, 1] you even get away with cosines alone: reflect the function about 0 to make it symmetric on [−1, 1], and a symmetric function needs no sines. The one-dimensional Fourier cosine basis of order n is therefore cos(0), cos(πs), cos(2πs), …, cos(nπs): a constant, then waves with one, two, …, n half-periods across the state range.

In k dimensions each feature takes an integer vector c and becomes a plane wave, cos(π c · s). The vector picks both the direction the wave travels and how many crests it fits in: c = (2, 0) ripples along position only, c = (1, 1) runs diagonally and so couples position with velocity. There are again (n + 1)k features, but unlike powers these waves are spread out evenly and nearly at right angles to each other, which is exactly what a gradient method likes. Konidaris, Osentoski and Thomas (2011) also suggest giving each feature its own step size, smaller for the faster waves. Pick a vector c and see its wave; then raise n and compare the fit with the polynomial of the same order.

\[ \begin{aligned} x_i(s) &= \cos\!\big(\pi\, \mathbf s^{\top}\mathbf c^{i}\big) \\ \mathbf c^{i} &\in \{0,\dots,n\}^{k} \end{aligned} \]
Read it as: s is the state scaled to [0, 1]k. The integer vector ci gives the number of half-waves along each axis; the feature is the cosine of π times the dot product. c = 0 gives the constant 1.
Say it“x-i of s is the cosine of pi times s dotted with c-i.”
\[ \alpha_i = \frac{\alpha}{\Vert \mathbf c^{i} \Vert} \quad (\alpha_0 = \alpha) \]
Read it as: each feature’s weight learns with its own step size: the base α divided by the length of its frequency vector, so slow, broad waves move fast and rapid ripples move cautiously. The constant feature keeps α.
Say it“Alpha-i is alpha over the norm of c-i.”

Head to head

The race: polynomials against cosines, learning online

Least squares sees all the data at once. A reinforcement-learning agent does not: it learns one sample at a time with stochastic-gradient steps, and then the shape of the feature space matters a great deal. Here both bases learn the value of the 1,000-state random walk by gradient Monte Carlo: run an episode from the middle, then nudge the weights towards the final outcome at every state visited. Both get the same episodes, 10 runs of 5,000 each, and the dashed lines show the best each basis could possibly do (the weighted least-squares fit). Polynomials have the capacity but cannot get there: their nearly parallel features force a tiny step size, and progress along the weak directions is glacial. Sutton and Barto reach the same verdict and advise against polynomials for online learning. Choose an order and run the race; then try nudging the step sizes.

\[ \begin{aligned} \mathbf w \leftarrow \mathbf w &+ \alpha\,\big[G_t - \hat v(S_t,\mathbf w)\big] \\ &\quad\times \mathbf x(S_t) \end{aligned} \]
Read it as: Gt is the return that followed state St (here simply −1 or +1, the outcome of the episode). The error times the feature vector is the gradient step for the squared error at that state. With Fourier features each component also gets its own αi in principle; in one dimension the plain α already works.
Say it“w becomes w plus alpha times G-t minus v-hat of S-t, times x of S-t.”
\[ \begin{aligned} \overline{\text{VE}}(\mathbf w) = \sum_{s} \mu(s)\,\big[&v_\pi(s) \\ &- \hat v(s,\mathbf w)\big]^2 \end{aligned} \]
Read it as: the error is averaged over states with weight μ(s), the share of time the walk spends in s, so the busy middle counts more than the rarely visited edges. The plot shows its square root. Both vπ and μ are solved exactly in your browser from the walk’s 1,000 linear equations.
Say it“The value error is the sum over states of mu of s times the squared gap between v-pi and v-hat.”

Recipe 3

Coarse coding: overlapping receptive fields

A completely different idea: scatter many overlapping regions over the state space, circles say, and give each one a binary feature that is 1 when the state lies inside it and 0 otherwise. This is coarse coding (Hinton, 1984). A state is described by the handful of circles it falls in; two states are similar if they share circles. Train the value at one state and every weight of its circles moves, so the change spreads to every state that shares any of them, most strongly to those that share the most.

So the size and shape of the regions decide how learning generalises: big circles spread each lesson widely, long thin ellipses spread it along one direction only. If some point lies in no circle at all, nothing can ever be learned there. Click the map to teach it (each click pulls the value at that point half-way to the target), then change the radius or the shape and teach again. Smooth bumps instead of hard-edged circles give radial basis functions, the same idea with graded membership.

\[ \begin{aligned} x_i(s) &= \mathbb 1\big[s \in \text{region}_i\big] \\ w_i &\leftarrow w_i + \frac{\alpha}{m(s)}\big[U - \hat v(s,\mathbf w)\big] \\ &\qquad \times x_i(s) \end{aligned} \]
Read it as: each feature is 1 inside its region and 0 outside; m(s) is how many regions contain s. A training example with target U moves every active weight by the same amount, and dividing by m(s) makes α the share of the error removed at s: α = 1 fixes it in one step, α = ½ halves it. Any other state t moves by a fraction proportional to how many active regions it shares with s.
Say it“Each active weight moves by alpha over m of s times the error U minus v-hat.”

Recipe 4

Tile coding: coarse coding built for speed

Tile coding (Albus, 1975, who called it CMAC) is coarse coding with the regions arranged so that a computer can find them instantly. Cover the state space with a grid, a tiling; each tile is a binary feature, and exactly one tile per tiling is active. One tiling alone is just a lookup table with no generalisation inside a tile and none across. Lay n tilings on top of each other, each shifted by a fraction of a tile, and every state is in exactly n tiles. Neighbouring states share most of them, distant ones share none: generalisation and fine resolution at once, for the price of n array look-ups.

Because exactly n features are always active, the step size has a simple meaning: with α = 1/n a single update moves v̂(s) all the way to its target, and α = 1/(10n) moves it a tenth of the way. How the tilings are shifted matters too. Shifting every tiling by the same amount along each axis (offsets 1, 1) lines the tile corners up on a diagonal, and generalisation smears along it. Shifting by odd multiples, 1 along position and 3 along velocity, spreads it more evenly. Tiles need not be squares: stripes ignore one variable entirely, diagonal stripes generalise along a combination. Drag the ring, then change the offsets and the shapes.

\[ \begin{aligned} i_t(s) &= t\,G^2 + \big\lfloor u_1 + o_{t,1} \big\rfloor\, G \\ &\quad + \big\lfloor u_2 + o_{t,2} \big\rfloor \\ o_{t,j} &= \frac{d_j\, t \bmod n}{n} \end{aligned} \]
Read it as: uj is state variable j measured in tile widths from the edge of the box; tiling t shifts it by ot,j, a fraction of a tile set by the displacement d = (1, 1) or (1, 3). Rounding down gives the tile’s row and column, and with G = T + 1 tiles per side (one spare for the shift) it(s) is that tile’s position in one long weight array.
Say it“The active tile of tiling t is t G squared plus floor of u-one plus its offset times G, plus floor of u-two plus its offset.”
\[ \begin{aligned} \hat v(s) &= \sum_{t=0}^{n-1} w_{i_t(s)} \\ \hat v_{\text{new}}(s) &= \hat v(s) + n\alpha\,\big[U - \hat v(s)\big] \end{aligned} \]
Read it as: the estimate is the sum of the n active weights, no multiplications needed. Adding α[U − v̂(s)] to each of them moves the sum by nα times the error, so α = 1/n jumps straight to the target U. Another state t moves by the share of tiles it has in common with s.
Say it“v-hat is the sum of the n active weights; one update moves it by n alpha times the error.”

Saving memory

Hashing: many tiles, few weights

A tiling over k state variables with T tiles per side has Tk tiles, and that number is hopeless beyond a handful of dimensions. But an agent only ever visits a thin slice of its state space. Hashing keeps a fixed table of M weights and sends every tile to a pseudo-random slot. Most visited tiles still get a slot to themselves; occasionally two tiles, usually far apart, share one, and then whatever is learned at one leaks into the other. Because each state has n tiles and a collision usually hits only one of them, a little leakage is diluted by the other n − 1. This page uses Knuth’s multiplicative hash on the 648 tiles of the project’s tile coder (8 tilings of 9 × 9). Shrink the table and watch where the ring’s weights reappear; then run Mountain Car at every table size.

\[ \begin{aligned} h(i) &= \Big\lfloor \frac{(a\, i) \bmod 2^{32}}{2^{32-b}} \Big\rfloor \\ a &= 2654435761 \end{aligned} \]
Read it as: multiply the tile number i by a large odd constant (close to 232 divided by the golden ratio), keep the low 32 bits, and read off the top b of them: a slot between 0 and M − 1 = 2b − 1. Neighbouring tile numbers land far apart.
Say it“h of i is a times i modulo two to the thirty-two, divided by two to the thirty-two minus b, rounded down.”
\[ \mathbb E[\text{slots used}] = M\Big[1 - \big(1 - \tfrac{1}{M}\big)^{K}\Big] \]
Read it as: if K tiles were thrown into M slots at random, a given slot stays empty with probability (1 − 1/M)K; the rest are used. Fewer slots used than tiles means some tiles share. The real hash is not random, so the count it achieves is shown beside the formula.
Say it“The expected number of used slots is M times one minus, one minus one over M, to the K.”

Real-world project

Project: escaping the valley with tile coding and Fourier features

Mountain Car (Moore, 1990) is the classic test bed for feature construction. The state is two numbers, position in [−1.2, 0.6] and velocity in [−0.07, 0.07]; the actions are push left, coast and push right; every step costs −1 until the car passes 0.5 with non-negative velocity. Gravity beats the engine, so the only way out is to swing back up the left slope first, and the value function has a sharp spiral ridge between “one more swing” and “go now”. This page runs Gymnasium’s MountainCar-v0 (Farama Foundation, MIT licence), re-implemented line for line in JavaScript from version 1.4.0, with two honest changes: the time limit is raised from Gymnasium’s default 200 steps to 1,000, so the first clumsy episodes are visible rather than cut off, and starting positions come from the page’s own random-number generator (passed to Gymnasium through its reset options) so that Python can replay every run exactly.

The learner is semi-gradient Sarsa with γ = 1, acting greedily on q̂(s, a, w) = wa · x(s), one weight vector per action. All weights start at 0, which is optimistic (true values are all negative), so the agent explores by itself: everything it has tried looks worse than what it hasn’t. Ties are broken at random.

\[ \begin{aligned} \delta &= R + \hat q(S',A',\mathbf w) - \hat q(S,A,\mathbf w) \\ \mathbf w_{A} &\leftarrow \mathbf w_{A} + \delta\;\boldsymbol\alpha \odot \mathbf x(S) \end{aligned} \]
Read it as: after taking action A in state S, seeing reward R = −1 and choosing A′ in S′, the TD error δ moves only the weights of action A, along the features of S. α is a vector of step sizes: α/n for every tile, or α/‖ci‖ for each Fourier feature. At the flag the q̂(S′, A′) term is dropped; at the 1,000-step limit it is kept, because running out of time is not a real ending.
Say it“Delta is R plus q-hat of S-prime A-prime minus q-hat of S A; the weights of A move by delta times alpha times x of S.”

The same experiment in Python

import math, numpy as np, gymnasium as gym
XL, XH, VL, VH = -1.2, 0.6, -0.07, 0.07

def tiles(n, T, disp=(1, 3), hb=0):         # n offset tilings of (T+1) x (T+1) tiles, optionally hashed
    wx, wv, G = (XH - XL) / T, (VH - VL) / T, T + 1
    def f(x, v):
        out = []
        for t in range(n):
            ix = math.floor((x - XL) / wx + ((disp[0] * t) % n) / n)
            iv = math.floor((v - VL) / wv + ((disp[1] * t) % n) / n)
            ix, iv = min(T, max(0, ix)), min(T, max(0, iv))   # float32 observations can sit a hair outside the box
            i = t * G * G + ix * G + iv
            out.append(((i * 2654435761) & 0xFFFFFFFF) >> (32 - hb) if hb else i)
        return out
    return f, (1 << hb) if hb else n * G * G

def fourier(k):                             # cos(pi c.s) for every c in {0..k}^2, s scaled to [0,1]^2
    C = [(i, j) for i in range(k + 1) for j in range(k + 1)]
    def f(x, v):
        u, w = (x - XL) / (XH - XL), (v - VL) / (VH - VL)
        return [math.cos(math.pi * (c1 * u + c2 * w)) for c1, c2 in C]
    return f, len(C), [1.0 if c == (0, 0) else 1 / math.hypot(*c) for c in C]

def sarsa(cfg, seed, episodes=150, cap=1000):
    env, rng = gym.make("MountainCar-v0", max_episode_steps=cap), Mulberry(seed)   # Mulberry: the page's RNG
    tile = cfg["kind"] == "tile"
    if tile: phi, D = tiles(cfg["n"], cfg["T"], cfg.get("disp", (1, 3)), cfg.get("hb", 0))
    else: phi, D, sc = fourier(cfg["k"])
    W = [[0.0] * D for _ in range(3)]
    def q(a, F):
        s = 0.0
        if tile:
            for i in F: s += W[a][i]
        else:
            for i in range(D): s += W[a][i] * F[i]
        return s
    def update(a, F, d):
        if tile:
            for i in F: W[a][i] += cfg["alpha"] / cfg["n"] * d
        else:
            for i in range(D): W[a][i] += cfg["alpha"] * sc[i] * d * F[i]
    def act(F):                             # greedy, ties broken at random; w = 0 is optimistic
        qs = [q(a, F) for a in range(3)]; best = [a for a in range(3) if qs[a] == max(qs)]
        return best[0] if len(best) == 1 else best[math.floor(rng() * len(best))]
    steps = []
    for ep in range(episodes):
        x0 = -0.6 + 0.2 * rng()
        obs, _ = env.reset(options={"low": x0, "high": x0}); F = phi(*map(float, obs)); a = act(F); k = 0
        while True:
            obs, r, term, trunc, _ = env.step(a); k += 1
            if term: update(a, F, r - q(a, F)); break
            F2 = phi(*map(float, obs)); a2 = act(F2)
            update(a, F, r + q(a2, F2) - q(a, F)); F, a = F2, a2
            if trunc: break
        steps.append(k)
    return steps, W

configs = {"tiles 8 x 8x8, offsets (1,3)": dict(kind="tile", n=8, T=8, alpha=0.5),
           "tiles 8 x 8x8, offsets (1,1)": dict(kind="tile", n=8, T=8, disp=(1, 1), alpha=0.5),

print(f"gymnasium {gym.__version__}; 10 runs x 150 episodes each, cap 1000 steps")
for name, cfg in configs.items():
    runs = [sarsa(cfg, seed) for seed in range(1, 11)]
    S = np.array([s for s, _ in runs])
    print(f"{name:30s} steps/episode: ep 1-10 {S[:, :10].mean():7.2f}  ep 11-50 {S[:, 10:50].mean():7.2f}"
          f"  ep 101-150 {S[:, 100:].mean():7.2f}  all {S.mean():7.2f}  total {S.sum()}")
    print(f"{'':30s} run 1, first 8 episodes: {S[0, :8].tolist()}  sum of run-1 weights {sum(map(sum, runs[0][1])):.10f}")

Wrap-up

Five lines to remember

  • A linear value function is linear in its weights, not in the state: all the curvature, interaction and resolution comes from the features, which is where your knowledge of the problem goes in.
  • Polynomials add interactions but their high powers are nearly parallel and their number grows as (n + 1)k; for online learning they are a poor choice.
  • The Fourier basis cos(π c · s) gives evenly spread, nearly orthogonal waves; with step sizes α/‖c‖ it learns fast and smoothly in low dimensions.
  • Coarse coding makes binary features from overlapping regions: region size and shape decide how far and in which direction learning spreads, while the density of features sets the final acuity.
  • Tile coding is coarse coding with offset grids: exactly n active features, so v̂ is a sum of n weights and α = 1/(10n) has a clear meaning; asymmetric offsets avoid diagonal artefacts, and hashing keeps memory fixed.

Check your understanding

Why can’t v̂ = w₀ + w₁p + w₂v capture “a fast car near the bottom is nearly out”?

Because the effect of velocity on v̂ is w₂ whatever the position is: the model is a tilted plane. Any dependence on the combination of the two needs a feature that combines them, such as p·v, a diagonal Fourier wave or a two-dimensional tile.

A robot arm has 6 joint angles. How many features does a full order-3 polynomial or Fourier basis have?

(3 + 1)6 = 4,096. At order 5 it would be 66 = 46,656, which is why in more than a few dimensions you keep only a chosen subset, for example the features that involve at most two variables at a time.

You use tile coding with 10 tilings. What step size makes each update cover about a tenth of the error at the trained state?

α = 1/(10 × 10) = 0.01. Each of the 10 active weights moves by α times the error, so v̂(s) moves by 10α = 0.1 of it.

Why do wide coarse-coding regions not make the final value function blurry?

Early on, wide regions generalise each sample far, so the shape appears fast but smeared. With enough data the weights adjust so that the regions’ edges, packed as densely as before, carve out the fine detail. Acuity is set by the number and density of features, not their width.

What is the price of hashing 648 tiles into 128 weights, and why is it often small?

Several far-apart tiles share each weight, so learning at one state leaks into unrelated states. But each state’s value is the sum of n weights, collisions rarely hit all of them at once, and an agent visits only part of its state space, so most of the leakage lands where it never goes.
