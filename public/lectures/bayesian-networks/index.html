Bayesian Networks

Draw the causes as arrows, and one huge table becomes a few small ones.

The problem

Why structure: the table that explodes

To reason about rain, the sprinkler and wet grass together, we need their joint distribution P(R, S, G): a probability for every combination of values. With three yes/no variables there are 23 = 8 combinations. The eight probabilities must add up to 1, so 7 of them are free. That is easy to write down.

Now try a real problem. The ALARM network, built to monitor patients in intensive care, has 37 variables. Even if every one of them were yes/no, the joint table would have 237 ≈ 137 billion rows. The Bayesian network that doctors actually built needs 509 numbers. Move the sliders to see how fast the full table grows, and how slowly a network grows.

\[ \underbrace{2^{n} - 1}_{\text{full joint table}} \qquad\text{versus}\qquad \underbrace{\sum_{i=1}^{n} 2^{\,|\mathrm{pa}(i)|}}_{\text{Bayesian network}} \;\le\; n\,2^{k} \]
Read it as: n binary variables. The full table has one number per combination, minus one because they sum to 1. In a network, variable i has a parent set pa(i) and needs one number for each combination of its parents’ values. If no variable has more than k parents, the total is at most n · 2k.
In wordsThe full table grows exponentially in the number of variables; a network grows exponentially only in the number of parents.

Four things go wrong with one big table

  • StorageThe table doubles with every variable you add. Past about 40 yes/no variables it no longer fits in any computer’s memory.
  • Asking expertsNobody can tell you P(rain, sprinkler on, grass dry, cat inside, …) for billions of rows. People can tell you how likely the grass is to be wet if it rained.
  • Learning from dataWith billions of rows, almost every row is seen zero times in any real data set, so counting gives useless estimates.
  • Answering questionsAny query, such as P(rain | wet grass), means adding up rows. With an exponential number of rows, the sum takes exponential time.

The fix is to notice that most variables directly depend on only a few others. The grass does not care about the day of the week once you know whether it rained and whether the sprinkler ran. A Bayesian network writes these dependencies down as a graph, and keeps only the small tables the graph needs.

The graph

Directed acyclic graphs

A Bayesian network has two parts. The first is a directed acyclic graph (DAG). Each node is a random variable. An arrow X → Y says X directly influences Y, and we call X a parent of Y and Y a child of X. Directed means each arrow has a direction. Acyclic means you can never follow arrows and come back to where you started.

The second part is a table of probabilities for each node given its parents, which comes in section 4. In the running example, rain makes the grass wet, the sprinkler makes the grass wet, and on rainy days the gardener rarely switches the sprinkler on. That gives three arrows: Rain → Sprinkler, Rain → Wet grass and Sprinkler → Wet grass.

  • Parents pa(X)The nodes with an arrow into X. Wet grass has parents {Sprinkler, Rain}.
  • Ancestors and descendantsFollow arrows backwards to find ancestors and forwards to find descendants. Rain is an ancestor of everything; Wet grass is a descendant of everything.
  • Root and leafA root has no parents (Rain). A leaf has no children (Wet grass).
  • Topological orderA list of the nodes where every parent comes before its children: Rain, Sprinkler, Wet grass. Every DAG has at least one. A graph with a cycle has none, and that is exactly why cycles are not allowed.

Build your own graph. Choose an arrow, or no arrow, between each pair of variables. The page checks for cycles, finds a topological order, and counts how many probabilities the graph needs.

Arrows do not have to point from cause to effect. Wet grass → Rain is a legal arrow, and a graph with an arrow between every pair can represent any joint distribution. Causal directions are still the usual choice, because the numbers they need are the ones people can estimate, and causal graphs tend to need fewer arrows.

The key equation

Factorising the joint

The chain rule of probability splits any joint distribution into a product of conditionals, in any order you like. For three variables in the order R, S, G:

\[ P(R, S, G) = P(R)\; P(S \mid R)\; P(G \mid R, S) \]
Read it as: pick the first variable on its own, then the second given the first, then the third given the first two. This is always true. It follows from the definition P(A, B) = P(A) P(B | A).

A Bayesian network adds one assumption, the local Markov property: once you know a node’s parents, the node is independent of everything that is not its descendant. In a topological order, everything before a node is a non-descendant, so every term of the chain rule can drop the variables that are not parents. What is left is one small table per node:

\[ P(x_1, \dots, x_n) \;=\; \prod_{i=1}^{n} P\big(x_i \mid \mathrm{pa}(x_i)\big) \]
Read it as: the probability of a complete world (a value for every variable) is the product, over all nodes, of the probability of that node’s value given its parents’ values in the same world.
In wordsMultiply one number from each node’s table, and you get the probability of the whole world.

Pick an order for the chain rule. The terms are checked against the graph you built in the lab above. In a topological order, every term shrinks to a table the network stores. In any other order, at least one term asks about a variable given its own descendant, and the network has no table for that.

    The numbers

    Conditional probability tables

    Each node stores a conditional probability table (CPT). It has one row for each combination of its parents’ values, and each row is a probability distribution over the node’s own values, so every row adds up to 1. For a yes/no node, one number per row is free: P(true | parents). The other is 1 minus it.

    Rain is a root, so its table is one number, the prior P(R = T) = 0.2. Sprinkler has one parent, so two rows. Wet grass has two parents, so four rows. That is 1 + 2 + 4 = 7 numbers, the same as the full table, because this small graph has an arrow between every pair. The savings appear when graphs are sparse, as in the first lab.     Worked example

    The calculation, by hand

    The grass is wet. What is the probability it rained? We want P(R = T | G = T). Everything we need is in the three tables, with the textbook numbers: P(R = T) = 0.2; P(S = T | R = T) = 0.01, P(S = T | R = F) = 0.4; P(G = T | S, R) = 0.99, 0.8, 0.9, 0.0 for (T, T), (F, T), (T, F), (F, F). We did not observe the sprinkler, so we add up over both of its values. This is called summing out, or marginalising, a hidden variable.

    1. Write the question as a ratio. By the definition of conditional probability,
      \[ P(R{=}T \mid G{=}T) = \frac{P(R{=}T,\, G{=}T)}{P(G{=}T)} \]
    2. Numerator: sum out the sprinkler, with rain on. Use the factorisation for each value of S.
      \[ \begin{aligned} P(R{=}T, G{=}T) &= P(R{=}T)\,P(S{=}T \mid R{=}T)\,P(G{=}T \mid S{=}T, R{=}T) \\ &\quad + P(R{=}T)\,P(S{=}F \mid R{=}T)\,P(G{=}T \mid S{=}F, R{=}T) \\ &= 0.2 \times 0.01 \times 0.99 \;+\; 0.2 \times 0.99 \times 0.8 \\ &= 0.00198 + 0.15840 = 0.16038 \end{aligned} \]
    3. Same again with rain off.
      \[ \begin{aligned} P(R{=}F, G{=}T) &= 0.8 \times 0.4 \times 0.9 \;+\; 0.8 \times 0.6 \times 0.0 \\ &= 0.288 + 0 = 0.288 \end{aligned} \]
    4. Denominator: the two cases together. Wet grass happens either with rain or without it.
      \[ P(G{=}T) = 0.16038 + 0.288 = 0.44838 \]
    5. Divide.
      \[ P(R{=}T \mid G{=}T) = \frac{0.16038}{0.44838} \approx 0.3577 \]
      Seeing wet grass raises the probability of rain from 20% to about 36%. It does not make rain likely, because the sprinkler is the more common reason for wet grass. The same steps give P(S = T | G = T) ≈ 0.6467.

    Generative models

    Ancestral sampling

    A Bayesian network is a generative model: it is a recipe for making up data that looks like the world it describes. The recipe is called ancestral sampling. Visit the nodes in a topological order. At each node, its parents already have values, so they pick out one row of its CPT. Flip a biased coin with that row’s probability: draw a random number u between 0 and 1, and set the node to True if u is less than P(true | parents).

    One pass through the graph gives one complete world, drawn with exactly the probability the factorisation gives it. Draw many worlds, and the fraction of each kind settles on its probability. Step through one variable at a time, then add samples in bulk and watch the bars meet their targets.

    \[ \begin{aligned} &\text{for each node } X_i \text{ in topological order:} \\ &\qquad u_i \sim \mathrm{Uniform}(0, 1) \\ &\qquad x_i = \big[\, u_i < P(X_i{=}T \mid \mathrm{pa}(x_i)) \,\big] \end{aligned} \]
    Read it as: parents first. Because every parent is sampled before its child, the CPT row for the child is always known when you get to it. The brackets mean “True if the condition holds”.

    Main lab

    Lab: exact versus simulated

    Samples can answer conditional questions too. To estimate P(R = T | G = T), draw N worlds, throw away every world where the grass is dry, and count how often it rained in the worlds that are left. This is rejection sampling. The estimate wobbles around the exact answer, and the wobble shrinks like 1/√(number of kept samples).

    Efficient CPDs

    Noisy-OR: a CPT in k+1 numbers

    A yes/no node with k yes/no parents needs a CPT with 2k rows. Add a burst pipe, a dog, morning dew and seven other causes of wet grass, and the table has 1,024 rows, most of which nobody could estimate. When a node has many parents we need a cheaper conditional probability distribution (CPD): a formula that fills in the table from a few numbers.

    The most popular one is noisy-OR. It assumes each cause, on its own, turns the effect on with some probability qi; that causes fail independently of each other; and that a leak probability λ covers every cause the model leaves out. The effect stays off only if the leak and every active cause all fail.

    \[ \begin{aligned} P(G{=}F \mid \text{parents}) &= (1-\lambda) \prod_{i \text{ on}} (1 - q_i) \\ P(G{=}T \mid \text{parents}) &= 1 - P(G{=}F \mid \text{parents}) \end{aligned} \]
    Read it as: qi is the chance that cause i alone wets the grass. The product runs over the causes that are on in this row of the table. For our row with rain and sprinkler both on, qR = 0.8, qS = 0.9 and λ = 0: P(G = T) = 1 − 1 × 0.2 × 0.1 = 0.98. The full table says 0.99, so noisy-OR is nearly right with one number fewer.
    In wordsEvery cause gets its own chance to wet the grass. The grass stays dry only if they all miss.

    The price is an assumption: causes cannot interact. Noisy-OR cannot say “rain and the sprinkler together flood the lawn far more than either alone”, or “the cover only matters when it rains”. Other compact CPDs make other trade-offs. Noisy-MAX extends the idea to variables with more than two levels, a logistic CPD puts the parents through a weighted sum and a sigmoid, and a tree CPD stores only the rows that differ. Deterministic CPDs (the node is an exact function of its parents) are the extreme case with no free numbers at all.

    Code

    The whole network in Python

    Everything on this page fits in about 130 lines of plain Python, with no libraries to install. The script defines the graph and the CPTs, prints the joint table, answers queries exactly by enumeration, estimates one of them by ancestral sampling with rejection, and builds the noisy-OR table. Save it as bayes_net.py and run python bayes_net.py. It needs Python 3.8 or newer.

    """A Bayesian network for rain, sprinkler and wet grass.

Run it with:  python bayes_net.py
Needs Python 3.8 or newer and nothing else (standard library only).
"""
import itertools
import random

# 1. The graph. Each variable lists its parents. ORDER is a topological
#    order: every parent comes before its children.
PARENTS = {
    "Rain": [],
    "Sprinkler": ["Rain"],
    "WetGrass": ["Sprinkler", "Rain"],
}
ORDER = ["Rain", "Sprinkler", "WetGrass"]

# 2. The conditional probability tables (CPTs). For each combination of
#    parent values we store P(variable = True | parents).
#    P(variable = False | parents) is 1 minus that number.
CPT = {
    "Rain": {(): 0.2},
    "Sprinkler": {(False,): 0.4, (True,): 0.01},
    "WetGrass": {
        (False, False): 0.0,   # no sprinkler, no rain
        (False, True): 0.8,    # rain only
        (True, False): 0.9,    # sprinkler only
        (True, True): 0.99,    # both
    },
}


def p_node(var, value, world):
    """P(var = value | the values of var's parents in world)."""
    key = tuple(world[p] for p in PARENTS[var])
    p_true = CPT[var][key]
    return p_true if value else 1.0 - p_true


def joint(world):
    """The factorisation: P(R, S, G) = P(R) * P(S | R) * P(G | S, R)."""
    p = 1.0
    for var in ORDER:
        p *= p_node(var, world[var], world)
    return p


def all_worlds():
    """Every assignment of True/False to the three variables (8 of them)."""
    for values in itertools.product([True, False], repeat=len(ORDER)):
        yield dict(zip(ORDER, values))


def query(target, evidence):
    """Exact P(target = True | evidence) by enumerating the joint table."""
    match = [w for w in all_worlds() if all(w[k] == v for k, v in evidence.items())]
    p_evidence = sum(joint(w) for w in match)
    p_both = sum(joint(w) for w in match if w[target])
    return p_both / p_evidence


def ancestral_sample(rng):
    """Draw one world: visit variables parents-first, flip a biased coin each."""
    world = {}
    for var in ORDER:
        p_true = p_node(var, True, world)
        world[var] = rng.random() < p_true
    return world


def estimate(target, evidence, n, seed=0):
    """Rejection sampling: draw n worlds, keep those that match the evidence."""
    rng = random.Random(seed)
    kept = hits = 0
    for _ in range(n):
        w = ancestral_sample(rng)
        if all(w[k] == v for k, v in evidence.items()):
            kept += 1
            hits += w[target]
    return hits / kept, kept


def noisy_or(q, leak, active):
    """P(effect = True) when each active cause i fires with probability q[i]."""
    p_off = 1.0 - leak
    for cause, on in active.items():
        if on:
            p_off *= 1.0 - q[cause]
    return 1.0 - p_off


if __name__ == "__main__":
    tf = lambda b: "T" if b else "F"

    print("The joint table, one product per row")
    print(" R S G   P(R)  P(S|R) P(G|S,R)   joint")
    total = 0.0
    for w in all_worlds():
        f = [p_node(v, w[v], w) for v in ORDER]
        p = joint(w)
        total += p
        print(f" {tf(w['Rain'])} {tf(w['Sprinkler'])} {tf(w['WetGrass'])}  "
              f"{f[0]:5.2f}  {f[1]:5.2f}  {f[2]:6.2f}   {p:.5f}")
    print(f" sum of all 8 rows = {total:.5f}")
    print()

    g = {"WetGrass": True}
    print("Exact answers by enumeration")
    print(f" P(WetGrass = T)                   = {query('WetGrass', {}):.4f}")
    print(f" P(Rain = T | WetGrass = T)        = {query('Rain', g):.4f}")
    print(f" P(Sprinkler = T | WetGrass = T)   = {query('Sprinkler', g):.4f}")
    print(f" P(Rain = T | WetGrass = T, S = T) = "
          f"{query('Rain', {'WetGrass': True, 'Sprinkler': True}):.4f}")
    print()

    exact = query("Rain", g)
    print("Ancestral sampling + rejection, estimating P(Rain = T | WetGrass = T)")
    print("       n    kept  estimate   error")
    for n in (100, 1_000, 10_000, 100_000):
        est, kept = estimate("Rain", g, n, seed=1)
        print(f" {n:7d} {kept:7d}   {est:.4f}  {est - exact:+.4f}")
    print()

    q = {"Rain": 0.8, "Sprinkler": 0.9}
    print("Noisy-OR for WetGrass: q_rain = 0.8, q_sprinkler = 0.9, leak = 0")
    print(" S R   noisy-OR   full CPT")
    for s, r in [(False, False), (False, True), (True, False), (True, True)]:
        p = noisy_or(q, 0.0, {"Rain": r, "Sprinkler": s})
        print(f" {tf(s)} {tf(r)}   {p:8.3f}   {CPT['WetGrass'][(s, r)]:8.3f}")
    print(" parameters: noisy-OR 3 (two q's and a leak), full CPT 4;"
          " with 10 parents: 11 vs 1024")

    Wrap-up

    What to carry home

    • A full joint table over n yes/no variables needs 2n − 1 numbers. That is too many to store, to ask experts for, to learn from data, or to sum over.
    • A Bayesian network is a DAG plus one CPT per node. Arrows point from parents to children, and the graph must have no cycles so that a topological order exists.
    • The joint factorises as the product of P(xi | pa(xi)). The cost grows with the number of parents, not the number of variables.
    • Any query can be answered exactly by summing the factorised joint and normalising, or approximately by ancestral sampling: sample parents before children, then count. Rejection sampling wastes samples when the evidence is rare.
    • Noisy-OR fills a CPT with k parents from k + 1 numbers, by assuming each cause acts independently and a leak covers the rest.

    Check your understanding

    Our three-node network needs 7 numbers, the same as the full table. So what did the graph buy us here?

    Nothing in storage, because the graph has an arrow between every pair, which is a complete DAG and can represent any distribution over three variables. What it did buy is numbers that people can estimate (how often does rain wet the grass?) instead of joint probabilities of whole worlds. The storage savings appear as soon as arrows are missing: the timer version needs 6, and sparse networks with dozens of variables need thousands of times fewer numbers than the full table.

    Why can’t a Bayesian network contain a cycle such as Rain → Wet grass → Rain?

    With a cycle there is no topological order, so the product of CPTs is no longer guaranteed to be a probability distribution that sums to 1, and ancestral sampling has nowhere to start: each node in the cycle waits for the other. Feedback over time is modelled by unrolling into time slices (a dynamic Bayesian network), where Rain today points to Wet grass today, which can point to something tomorrow.

    Ancestral sampling draws worlds from P(R, S, G). How would you draw worlds from P(R, S | G = T)?

    Rejection sampling: draw from the full joint and keep only worlds where G = T. The kept worlds are exact samples from the conditional distribution. The catch is cost: if P(G = T) is 0.001, you throw away 999 of every 1,000 samples. Likelihood weighting and MCMC (later chapters) avoid this waste.

    Is P(G = T | R = T) one of the numbers in the Wet grass CPT?

    No. The CPT conditions on both parents. P(G = T | R = T) sums out the sprinkler: 0.01 × 0.99 + 0.99 × 0.8 = 0.8019. A CPT gives you probabilities given all the parents, and anything else has to be calculated.

    Noisy-OR with qR = 0.8 and qS = 0.9 gives 0.98 when both are on. The textbook table says 0.99. What would it mean if the true value were 0.5?

    That rain and the sprinkler interfere: together they wet the grass less often than either one alone would. Noisy-OR can only give a value of at least max(qR, qS) when both causes are on, so it cannot represent this. You would need the full table, or a CPD that allows interactions, such as a logistic CPD with an interaction term.
