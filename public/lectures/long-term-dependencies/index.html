Long-Term Dependencies: Echo States, Leaky Units & Clipping

Ways to make a recurrent network remember for longer

Chapter 2.5 showed that a gradient sent back through a recurrent network is multiplied once per step, so over long gaps it fades away or blows up. This chapter is a toolbox of fixes that do not need gates. You can skip training the recurrent weights altogether (echo state networks). You can give the signal shortcuts through time, or units that leak slowly. You can clip the gradient's length, or add a penalty that keeps it flowing. The figure shows a reservoir: 50 units joined by random, fixed weights. Click the reservoir to send in a pulse, then change the spectral radius and watch the echo either fade or keep ringing.

dlbook 10.8 · reservoir computing

Echo state networks: train only the read-out

Training the recurrent weights W is the hard part of an RNN, because that is where gradients vanish or explode. In 2001–2002 two groups independently suggested not training them at all. Jaeger’s echo state network (ESN) and Maass, Natschläger & Markram’s liquid state machine (the same idea with spiking neurons) both pick W and the input weights U at random, scale them carefully, and then never change them. The fixed network, called the reservoir, turns the input history into a long vector of features ht. Only a linear read-out v is learned, and learning it is just linear regression, a convex problem with a closed-form answer. The general approach is called reservoir computing.

So everything depends on whether the reservoir’s state still holds the information we need. The lab measures this directly. It feeds the reservoir random numbers xt and fits a separate read-out for each delay k that tries to recall xt−k from the current state alone. Change the spectral radius ρ and the size of the reservoir, and watch how far back the state can still recall.

\[ \begin{aligned} \mathbf{h}_t &= \tanh\!\big(W\mathbf{h}_{t-1} + U\mathbf{x}_t\big) \\ \hat y_t &= \mathbf{v}^{\top}\mathbf{h}_t \\ \mathbf{v} &= \big(H^{\top}H + \lambda I\big)^{-1} H^{\top}\mathbf{y} \end{aligned} \]
Read it as: W and U are random and frozen. Run the reservoir along the data and stack its states as the rows of a matrix H, with the targets in y. The read-out v is then ordinary ridge regression of y on H: one linear solve, with no backpropagation through time at all. λ is a small penalty that keeps v from fitting noise.
Say it“h-t is tanh of W h-t-minus-one plus U x-t; the prediction is v transpose h-t; v is H-transpose-H plus lambda I, inverted, times H-transpose y.”
\[ \begin{aligned} r^2_k &= \operatorname{corr}^2\!\big(\hat y^{(k)}_t,\; x_{t-k}\big) \\ \text{MC} &= \sum_{k=1}^{K} r^2_k \;\le\; N \end{aligned} \]
Read it as: for each delay k, fit a read-out that tries to output the input from k steps ago, and score it by its squared correlation r²k on fresh data (1 means perfect recall, 0 means none). Adding up the scores gives the memory capacity MC. Jaeger (2002) showed that for independent random inputs it can never exceed N, the number of units.
Say it“r-squared-k is the squared correlation between the read-out and x-t-minus-k; the memory capacity is the sum of r-squared-k over k, and is at most N.”

dlbook 10.8 · setting the reservoir

The spectral radius decides whether the echo dies

How should the fixed weights be chosen? Think of the recurrence as a map that takes ht−1 to ht. Nudge the state by a small δ, and one step later the nudge is multiplied by the map’s Jacobian J; n steps later, by Jn. If the nudge points along an eigenvector of J with eigenvalue λ, it is simply multiplied by λn. So the eigenvalue of largest size, the spectral radius ρ, decides the long run: if ρ < 1 every nudge dies away and if ρ > 1 some nudges grow. Backpropagation multiplies by the transposed Jacobians, which have the same eigenvalues, so the same number decides whether gradients vanish or explode. Echo state networks therefore scale W so that ρ is close to 1: memories fade, but slowly.

A purely linear network with ρ > 1 explodes. With tanh it cannot, because the state is trapped between −1 and 1 and saturated units have slope near 0, which shrinks J. That is why reservoirs work with ρ above 1 in some tasks, especially when the inputs are large enough to keep units saturated. The test below is the echo state property: start the same reservoir from two different states and drive both with the same inputs. If the two trajectories merge, the state depends only on the input history, and the reservoir has forgotten where it started. Move ρ across 1, and switch between tanh and linear units.

\[ \begin{aligned} \delta\mathbf{h}_t &\approx J\,\delta\mathbf{h}_{t-1} \;\Rightarrow\; \delta\mathbf{h}_{t+n} \approx J^{\,n}\,\delta\mathbf{h}_{t} \\ J\mathbf{u} &= \lambda\mathbf{u} \;\Rightarrow\; J^{\,n}\mathbf{u} = \lambda^{n}\mathbf{u} \\ J_t &= \operatorname{diag}\!\big(1-\mathbf{h}_t^{2}\big)\,W \end{aligned} \]
Read it as: a small change in the state is carried forward by the Jacobian. Along an eigenvector its size is multiplied by |λ| at every step, so after n steps by |λ|n. For a linear reservoir J is just W. For tanh units, Jt is W with each row scaled by that unit’s slope 1 − h², which is at most 1. Saturation can therefore only shrink J.
Say it“delta-h-t-plus-n is about J to the n times delta-h-t; along an eigenvector, J to the n times u is lambda to the n times u; for tanh, J-t is diag of one minus h-t squared, times W.”

Using a reservoir to start a trainable RNN

The same scaling is a good way to initialise an RNN whose weights will then be trained. Sutskever and colleagues (2013) found that a sparse random W rescaled to a spectral radius of about 1.1 to 1.2, followed by ordinary training with momentum, learned long-range tasks that had previously seemed to need second-order methods. Jaeger (2012) and Yildiz, Jaeger & Kiebel (2012) give the more careful theory of when the echo state property holds, and show that a radius above 1 can still be safe when the inputs keep units saturated.

dlbook 10.9, 10.9.1 · multiple time scales

Skip connections through time

A second family of fixes changes the network itself so that some of it works on a coarse time scale, carrying information across long gaps, while the rest handles the fine detail. The bluntest version adds a skip connection through time: as well as the usual link from ht−1, the state also reads ht−d directly (Lin, Horne, Tino & Giles, 1996, building on Bengio et al.). A dependence τ steps long can now be covered in about τ/d jumps instead of τ steps. A gradient multiplied by a factor λ at each jump then shrinks like λτ/d rather than λτ.

There is a catch. The short links are still there, so the gradient now travels along every mixture of short and long links, and the number of mixtures grows quickly. If the weights are large enough, the total can explode even though no single path does. In the lab both kinds of link are scalar weights in a linear network, so the gradient is an exact sum over all paths. Click a step on the timeline to see the shortest path back to it, then add a skip length d.

\[ \begin{aligned} \mathbf{h}_t = \tanh\!\big(&W_1\mathbf{h}_{t-1} + W_d\,\mathbf{h}_{t-d} \\ &+ U\mathbf{x}_t + \mathbf{b}\big) \end{aligned} \]
Read it as: each new state reads the previous state through W1 and also the state d steps back through a second matrix Wd. Both are trained as usual. The input and bias terms are unchanged.
Say it“h-t is tanh of W-one h-t-minus-one, plus W-d h-t-minus-d, plus U x-t plus b.”
\[ \begin{aligned} g(\tau) &= \frac{\partial h_T}{\partial h_{T-\tau}} \\ &= w_1\,g(\tau-1) + w_d\,g(\tau-d) \\ g(0) &= 1,\quad g(\tau<0) = 0 \end{aligned} \]
Read it as: for a linear one-unit version, hT = w1hT−1 + wdhT−d + xT. The gradient to a state τ steps back is the sum over all paths of the product of the weights along each path. Splitting on the last link taken gives this recursion: the paths whose last link is short, plus the paths whose last link is a skip.
Say it“g of tau is w-one times g of tau-minus-one, plus w-d times g of tau-minus-d.”

dlbook 10.9.2 · leaky units

Leaky units: a dial for the time scale

A smoother way to get a long path is to give a unit a linear link to itself with a weight close to 1. The unit becomes a running average: it keeps a share α of its old value and mixes in 1 − α of the new one. Such leaky units (Mozer, 1992) remember for roughly 1/(1 − α) steps, and along the self-link the gradient is multiplied by α per step with no squashing slope. A skip of length d guarantees a path exactly d steps long. A leak instead gives a smooth memory whose length can be any real number, and can be tuned by small changes to α.

Different units can be given different α, so that one layer holds a whole spectrum of time scales. The αs can be fixed by hand, for example spread evenly on a log scale and left untouched, or treated as parameters and learned; the project does both. The lab runs leaky units over six weeks of real hourly electricity demand in Great Britain. Turn α for your unit and watch it move from tracking every hour, to the daily level, to the weekly level.

\[ \begin{aligned} \mu_t &= \alpha\,\mu_{t-1} + (1-\alpha)\,v_t \\ &= (1-\alpha)\sum_{k\ge 0}\alpha^{k}\,v_{t-k} \\ \frac{\partial\mu_t}{\partial\mu_{t-\tau}} &= \alpha^{\tau} \end{aligned} \]
Read it as: the unit’s value is a weighted average of everything it has seen, with the weight of a value from k steps ago falling off as αk. Its time constant 1/(1 − α) is the average age of what it remembers, and the half-life is ln ½ / ln α. The gradient along the self-link is just ατ.
Say it“mu-t is alpha mu-t-minus-one plus one-minus-alpha v-t; the gradient back tau steps is alpha to the tau.”
\[ \begin{aligned} \mathbf{h}_t &= (1-\mathbf{a})\odot\mathbf{h}_{t-1} \\ &\quad + \mathbf{a}\odot\tanh\!\big(W\mathbf{h}_{t-1} + U\mathbf{x}_t + \mathbf{b}\big) \\ \mathbf{a} &= \sigma(\mathbf{q}) \ \text{ if learned} \end{aligned} \]
Read it as: a leaky RNN layer. Each unit moves only a share a = 1 − α of the way towards the usual tanh update. With a = 1 it is a plain RNN; with a = 0.01 it changes slowly and remembers for about 100 steps. Writing a = σ(q) lets training choose each unit’s time scale while keeping it between 0 and 1.
Say it“h-t is one-minus-a times h-t-minus-one, plus a times tanh of W h-t-minus-one plus U x-t plus b.”

dlbook 10.9.3 · removing connections

Removing connections: units that tick slowly

Skip connections add long links. The opposite approach removes the short ones, so that some units are forced to work on a long time scale. El Hihi & Bengio (1996) arranged the state in groups that update at different rates, and the Clockwork RNN of Koutník, Greff, Gomez & Schmidhuber (2014) makes this exact. Group g has a period Tg, such as 1, 2, 4, 8, …. It updates only on steps that are multiples of its period; on the other steps it holds its value and receives no input. Slow groups feed fast ones but not the other way round. A unit with period T jumps from ht−T to ht in one non-linear step, so information can cross τ steps in about τ/T non-linear steps.

The lab builds a small clockwork RNN with random weights, sends a single input pulse at the step you choose, and records each group’s state. It also computes exactly how strongly the final state depends on that input, ‖∂hT/∂xt0‖. The comparison is the same network with every group updating at every step. Click the grid to move the pulse, and add slower groups.

\[ \begin{aligned} &\text{if } t \bmod T_g = 0: \\ &\quad \mathbf{h}^{(g)}_t = \tanh\!\big(W_g\,\mathbf{h}_{t-1} + U_g\,x_t\big) \\ &\text{otherwise:}\ \ \mathbf{h}^{(g)}_t = \mathbf{h}^{(g)}_{t-1} \end{aligned} \]
Read it as: group g computes a normal RNN update only when the clock t is a multiple of its period Tg. The rest of the time it copies its old value, an identity link whose Jacobian is exactly I, with no weight matrix and no squashing slope. Wg holds the rows of W for group g, and only reads from groups that are at least as slow.
Say it“Group g's state is tanh of W-g h-t-minus-one plus U-g x-t when t is a multiple of T-g, and otherwise it is unchanged.”

dlbook 10.11, 10.11.1 · clipping gradients

Clipping the gradient at the cliff

The last two fixes leave the model alone and change the optimisation. One option is a stronger optimiser: Martens & Sutskever (2011) trained RNNs on long-range tasks with Hessian-free second-order methods, which take curvature into account. Simple SGD on a model built to be easy to optimise, such as an LSTM, usually turned out to be the more practical route. Two cheap tricks, however, help any model.

A recurrent loss surface tends to be flat almost everywhere with sudden, nearly vertical cliffs, where a small change of weight flips the network’s long-run behaviour (Pascanu, Mikolov & Bengio, 2013). The gradient says which way is downhill but not how far the downhill goes. At a cliff its length becomes enormous, and one step can throw the weights far away and undo many steps of progress. Gradient clipping limits how long a step can be. Clipping the norm (Pascanu et al., 2013) shortens the whole gradient vector to length v and keeps its direction. Clipping each element (Mikolov, 2012) caps every component at ±v; the direction changes, but the step still points downhill. If the gradient is infinite or NaN, Pascanu et al. suggest taking a random step of size v instead, which usually moves the weights away from the unstable spot. The lab’s loss belongs to a one-unit network run for 10 steps, so the cliff is real. Drag the start point, then compare the three rules.

\[ \begin{aligned} h_t &= w\,\sigma(h_{t-1}) + b,\quad h_0 = 0.5 \\ L(w,b) &= (h_{10} - 0.7)^2 \end{aligned} \]
Read it as: a single sigmoid unit feeds back into itself for 10 steps, and the loss asks it to finish at 0.7. When w is large the unit has two stable states, one low (near b) and one high (near w + b). A small change in (w, b) can switch which one the 10 steps end in, and that switch is the cliff in the map.
Say it“h-t is w times sigma of h-t-minus-one, plus b; the loss is h-ten minus 0.7, squared.”
\[ \begin{aligned} \mathbf{g} &\leftarrow \mathbf{g}\cdot\min\!\Big(1, \frac{v}{\lVert\mathbf{g}\rVert}\Big) \\ g_i &\leftarrow \max\!\big({-v}, \min(v, g_i)\big) \end{aligned} \]
Read it as: norm clipping (top line) leaves short gradients alone and shrinks long ones to length v, so the direction is kept. Element clipping (bottom line) caps each component separately, so the direction can change. Applied to one minibatch at a time, either rule changes the average step, so it is no longer an unbiased estimate of the full gradient. It is a heuristic, but one that works well in practice.
Say it“g becomes g times the smaller of one and v over the length of g; or each g-i is capped between minus v and v.”

dlbook 10.11.2 · regularising information flow

A penalty that keeps the gradient flowing

Clipping deals with gradients that explode. For gradients that vanish, Pascanu, Mikolov & Bengio (2013) proposed a regulariser. Let gt = ∇htL be the gradient arriving at step t. One step further back it becomes gt ∂ht/∂ht−1. We would like that vector to be about as long as gt, so the penalty Ω adds up, over all steps, how far the ratio of the two lengths is from 1. Computing the exact gradient of Ω is expensive. Their approximation treats the back-propagated vectors gt as constants, which makes it cheap. Combined with norm clipping, the regulariser greatly increased the span of dependencies an RNN could learn. Without clipping, the larger gradients it allows explode and learning fails. It is still not as effective as an LSTM when there is plenty of data, as in language modelling.

The lab is an 8-unit tanh RNN read for 50 steps, with a loss on the last step only. It plots how long the gradient is at every step back, then follows the gradient of Ω alone, with gt held fixed (here we also hold each step’s tanh slopes fixed; both are recomputed after every step). Start from a small W, where the gradient vanishes, and press Descend on Ω.

\[ \begin{aligned} \Omega &= \sum_{t} \Bigg( \frac{\big\lVert \mathbf{g}_t\, \frac{\partial \mathbf{h}_t}{\partial \mathbf{h}_{t-1}} \big\rVert}{\lVert \mathbf{g}_t \rVert} - 1 \Bigg)^{2} \\ \mathbf{g}_t &= \nabla_{\mathbf{h}_t} L \\ \frac{\partial \mathbf{h}_t}{\partial \mathbf{h}_{t-1}} &= \operatorname{diag}\!\big(1-\mathbf{h}_t^2\big)\,W \end{aligned} \]
Read it as: at each step, take the length of the gradient after it passes one step further back, divide by its length before, and penalise the squared distance of that ratio from 1. Ratios below 1 mean the gradient is fading and ratios above 1 mean it is growing. Ω = 0 would mean it keeps exactly its length all the way back.
Say it“Omega is the sum over t of: the length of g-t times dh-t by dh-t-minus-one, over the length of g-t, minus one, all squared.”

Real-world project

Project: forecasting Britain’s electricity demand a day ahead

The National Energy System Operator (NESO) publishes the Historic Demand Data for Great Britain: national demand (“ND”, in MW) for every half-hour settlement period. We took 2023 and 2024, 35,088 half-hours, and averaged each pair into an hourly series of 17,544 values. Demand follows a daily rhythm, a weekly one (weekends are lower) and the seasons. The task is to forecast demand 24 hours ahead from the demand series alone, with no weather and no calendar. To know that tomorrow is a Monday, a model has to remember last week, which is a dependency 144 to 168 steps long. We train on 2023, use its last 61 days to choose ridge penalties, and test on every hour of 2024 (8,760 forecasts). Data: NESO, NESO Open Data Licence v1.0 (based on the Open Government Licence v3.0). Supported by National Energy SO Open Data.

\[ \text{MAPE} = \frac{100\%}{n}\sum_{t}\left|\frac{\hat y_{t+24} - y_{t+24}}{y_{t+24}}\right| \]
Read it as: for each hour t of the test year, forecast the demand 24 hours later from data up to t, and average the size of the miss as a percentage of the true demand. We also report the root-mean-square error in GW.
Say it“MAPE is a hundred percent times the average of the absolute error over the true value.”

The same numbers in numpy

The reference loads the very same JSON the page embeds (hourly demand, reservoir weights and RNN weights), computes every row of the scoreboard with numpy, and prints it. The ESN rows use this lab’s default settings (ρ = 0.95, input scale 0.3).

import json, numpy as np
D = json.load(open("x061-data.json"))                  # what the page embeds
y = np.array(D["d2"]) / 2000; n23, H = D["n23"], D["H"]   # hourly demand, GW
mu, sd = y[:n23].mean(), y[:n23].std(); z = (y - mu) / sd
test = np.arange(n23, len(y) - H)                      # every hour of 2024
v0 = n23 - 61 * 24                                     # last 61 days of 2023 = validation

def score(p, idx):                                     # p forecasts y[idx + H]
    e = p - y[idx + H]
    return 100 * np.mean(np.abs(e) / y[idx + H]), np.sqrt(np.mean(e ** 2))

def ridge_fit(F, start, lams=(1e-3, 1e-2, 1e-1, 1, 10)):
    def fit(rows, lam):
        A = F[rows]; return np.linalg.solve(A.T @ A + lam * np.eye(A.shape[1]), A.T @ z[rows + H])
    val = np.arange(v0, n23 - H)
    errs = [score(F[val] @ fit(np.arange(start, v0 - H), l) * sd + mu, val)[0] for l in lams]
    lam = lams[int(np.argmin(errs))]
    return fit(np.arange(start, n23 - H), lam), lam

rows = {}
rows["same hour yesterday"] = score(y[test], test)
rows["same hour last week"] = score(y[test + H - 168], test)
L = np.stack([np.r_[np.zeros(k), z[:len(z) - k]] for k in range(168)] + [np.ones(len(z))], 1)
w, lam = ridge_fit(L, 167); rows["AR(168), ridge lam=%g" % lam] = score(L[test] @ w * sd + mu, test)

R = D["res"]["200"]; N = R["N"]; W0 = np.zeros((N, N))
for i, j, v in R["W"]: W0[i, j] = v
U = np.array(R["U"])
def esn(leak, rho=0.95, scale=0.3):
    a = {"none": np.ones(N), "one": np.full(N, 0.1), "spec": np.exp(-np.linspace(0, np.log(100), N))}[leak]
    W = W0 * rho / R["r0"]; h = np.zeros(N); Hs = np.zeros((len(z), N))
    for t in range(len(z)):
        h = (1 - a) * h + a * np.tanh(W @ h + U[:, 0] * scale * z[t] + U[:, 1] * 0.2); Hs[t] = h
    F = np.c_[Hs, z, np.ones(len(z))]; w, lam = ridge_fit(F, 300)
    return score(F[test] @ w * sd + mu, test), lam
for leak in ["none", "one", "spec"]:
    s, lam = esn(leak); rows["ESN leak=%s, lam=%g" % (leak, lam)] = s

for mode, P in D["rnn"].items():
    Wr, Ur, b, V, a = (np.array(P[k]) for k in "WUbVa")
    h = np.zeros(len(b)); p = np.zeros(len(z))
    for t in range(len(z)):
        h = (1 - a) * h + a * np.tanh(Wr @ h + Ur * z[t] + b); p[t] = h @ V + P["c"]
    rows["leaky RNN (BPTT), leak=%s" % mode] = score(p[test] * sd + mu, test)
    g = np.array(P["hist"])[:, 1]
    print(f"{mode:9s} clipped on {np.sum(g > P['clip'])} of {len(g)} steps, largest norm {g.max():.3f}")

print(f"{'model':38s} {'MAPE %':>8s} {'RMSE GW':>8s}")
for k, (m, r) in rows.items(): print(f"{k:38s} {m:8.4f} {r:8.4f}")

Wrap-up

Five lines to remember

  • An echo state network keeps random recurrent weights fixed and fits only a linear read-out by ridge regression, so it needs no backpropagation through time. Its memory capacity is at most N, and it is longest when the reservoir is nearly linear with ρ just below 1.
  • A small change of state is multiplied by the Jacobian at every step, and along an eigenvector by λn. The spectral radius therefore decides whether echoes and gradients fade or grow. tanh saturation can make a reservoir with ρ > 1 forget its starting state anyway.
  • Multiple time scales shorten the path back through time. Skip links of length d cover τ steps in about τ/d jumps (but the many mixed paths can still explode). Leaky units remember for 1/(1 − α) steps with a gradient of ατ. Clockwork groups that update every T steps cross τ steps in about τ/T non-linear updates.
  • At a cliff the gradient can be thousands of times its usual size. Clipping its norm to v keeps the direction and caps the step at ηv, and Pascanu’s regulariser Ω pushes each step’s gradient ratio towards 1 so that it neither fades nor grows.
  • On a day-ahead forecast of Britain’s 2024 electricity demand from demand alone, leaks helped both families: the ESN went from 6.93% to 6.58% error and the trained RNN from 6.45% to 6.07% (fixed spectrum) and 5.77% (learned time constants, from about 1 to 49 hours). The last of these beat a 168-lag linear model (5.87%) and copying yesterday (7.39%).

Check your understanding

An echo state network has 200 units and you want it to forecast 5 different quantities. What is trained, and how?

Only the read-out: five weight vectors (one per output) on the 200 reservoir states, plus a bias. Each is a ridge regression on the same matrix H of collected states, so a single factorisation of H⊤H + λI solves all five. W and U stay as they were drawn.

A linear reservoir has spectral radius 1.05. What happens to a small difference between two of its states over 100 steps, and why can a tanh reservoir with the same W behave differently?

Along the leading eigenvector the difference is multiplied by about 1.05100 ≈ 131, so it grows. In a tanh reservoir each step multiplies by diag(1 − h²)W instead. Saturated units have slopes below 1, so the effective Jacobian can be contracting, and the echo state property can still hold.

Skip connections of length d and leaky units with α = 1 − 1/d both carry information about d steps. How do they differ?

The skip connection is a discrete, trained link that reaches exactly d steps back. The leaky unit is a linear self-loop that blends all past values with weights αk, so its memory is smooth and its length is set by a real number that can be fixed by hand or learned. The skip network also keeps its one-step links, so its gradient sums over many paths and can still explode.

Your RNN’s loss suddenly jumps from 0.2 to 40 in one update. What probably happened, and what change stops it?

The weights hit a cliff in the loss surface, where the gradient is huge, and the step threw them far away. Clip the gradient’s norm to a threshold v (for example 1), so no single step can be longer than ηv. Lowering η helps less, because the gradient at a cliff can be thousands of times larger than elsewhere.

Why do Pascanu and colleagues pair their information-flow regulariser with gradient clipping?

The regulariser pushes each step’s ratio ‖gt∂ht/∂ht−1‖/‖gt‖ towards 1, which makes gradients from far back larger. That moves the network towards the edge where gradients can also explode. Without clipping those explosions wreck training; with clipping, the network keeps the longer memory and stays stable.
