Probabilistic Programming

Relational and open-universe models

A Bayes net has a fixed list of variables. The world has objects: players, customers, books, cars, earthquakes. Often we do not even know how many there are. This chapter writes probability models as programs that create objects and make random choices about them, so that one model covers any number of objects and one inference engine covers any model. AIMA 15, 15.1, 15.1.1 · relational probability models

Bayes nets that know about objects

A Bayes net is propositional, like propositional logic: it has a fixed set of named random variables and nothing else. Picture an online bookshop that wants to know how good each book really is, given its customers’ star ratings, when some customers are generous, some are harsh and a few are dishonest. As a Bayes net this needs a separate node for every customer’s honesty, every customer’s kindness, every book’s quality and every rating. A new customer means redrawing the network by hand. Logic met the same problem long ago and solved it with first-order logic, which talks about objects and relations. Probabilistic programming languages do the same for probability. You write the model once, in terms of types of objects and functions on them, and a single general-purpose inference engine answers queries for any set of objects. This chapter visits three kinds: relational models over a known set of objects, open-universe models where the objects themselves are uncertain, and generative programs, where the model is any program that makes random choices.

A relational probability model (RPM) has the vocabulary of first-order logic. It has types (Customer, Book), constant symbols naming the objects (C1, C2, B1, …), and functions with type signatures: Honest takes a customer to true or false, Kindness takes a customer to 1–5, Quality takes a book to 1–5, and Recommendation takes a (customer, book) pair to 1–5 stars. Each function gets a dependency statement, a rule for its distribution written once with logical variables: Honest(c) ~ ⟨0.9, 0.1⟩, and Recommendation(c, b) ~ RecCPT(Honest(c), Kindness(c), Quality(b)). The semantics adds two assumptions from databases: unique names (different constants are different objects) and domain closure (there are no other objects). Then every function applied to every tuple of objects is one ground random variable, its parents come from instantiating the dependency statement, and the result is an ordinary Bayes net, called the grounding or unrolling of the RPM. A possible world assigns a value to every ground variable, and its probability is the product of their conditional probabilities. That is well defined as long as the dependencies have no cycles.

Two refinements make RPMs more expressive than they look. A dependency can be context-specific: Recommendation(c, b) ~ if Fan(c, Author(b)) then Exactly(5) else RecCPT(…) says that a fan gives five stars whatever the book is like, so honesty, kindness and quality do not matter for that rating. And a function value can itself be unknown, which is relational uncertainty: if we are unsure who wrote B2, then Recommendation(C1, B2) needs Fan(C1, a) for every author a as parents, and the unknown Author(B2) acts as a multiplexer that picks which one counts. Click a rating to cycle its stars, add customers or books, and switch on fans with unknown authors; the network unrolls itself and the posterior is recomputed exactly.

\[ \begin{aligned} P(\omega) &= \prod_{X} P\big(X(\omega) \mid \text{Pa}(X)(\omega)\big) \\ N_{\text{plain}} &= 2C + B + CB \\ N_{\text{fans}} &= 2C + 2B + CB + CA \end{aligned} \]
Read it as: the probability of a possible world ω is the product, over every ground random variable X of the unrolled net, of the probability of X’s value in ω given its parents’ values in ω. With C customers and B books there are two variables per customer (Honest, Kindness), one per book (Quality) and one per pair (Recommendation). Fans add Author(b) for each book and Fan(c, a) for each customer and each of the A authors.
Say it“The probability of a world is the product over the ground variables of each one given its parents.”
\[ \begin{aligned} P(r \mid h, k, q) &\propto \exp(-z^2/2) \\ z &= (r - \mu)/0.75 \\ \mu &= q + (k - 3)/2 \\ P(\{1, 5\} \mid \neg h) &= 0.85 \\ P(5 \mid \text{fan}) &= 1 \end{aligned} \]
Read it as: the RecCPT used here (made up for teaching). An honest customer’s rating r on 1–5 is a Gaussian bump, normalised over the five values, centred on μ: the book’s quality q, nudged up by half a star for each kindness level above 3 and down for each below. A dishonest customer mostly gives 1 or 5 stars regardless of the book: P(r | not honest) = (0.45, 0.05, 0.05, 0.05, 0.40), so 1 or 5 with probability 0.85. A fan of the book’s author always gives 5. Priors: P(honest) = 0.9; Kindness (0.1, 0.1, 0.2, 0.3, 0.3); Quality (0.05, 0.2, 0.4, 0.2, 0.15); Fan(c, a) true with probability 0.15; Author(b) uniform over two authors.

AIMA 15.1.2 · example: rating player skill

Rating player skill

Chess, Go, tennis and online games all need the same thing: a number for how strong each player is, learned only from who beat whom. The classic answer is a relational model with one hidden variable per player and one per game. Each player p has a skill, Skill(p). In each game g a player turns in a performance, Performance(p, g), which is the skill plus luck: some days you play above yourself. The player with the higher performance wins. This is the model behind Arpad Elo’s chess ratings and behind Microsoft’s TrueSkill, which Xbox Live used to match players.

Written as an RPM it is three lines, and it holds for any number of players and games. The Win statement is deterministic: given both performances there is nothing random left. Because the difference of two independent Gaussian performances is Gaussian, the performances can be integrated out by hand, and the chance that x beats y depends only on the skill gap divided by √2β. Two easy additions make it fit real games. A draw margin ε calls a game drawn when the performances are within ε of each other. An advantage term adds a few points to one side, for White’s first move in chess or for playing at home. Move the two skills and the luck β, then play a hundred simulated games and compare the counts with the formula.

\[ \begin{aligned} \text{Skill}(p) &\sim \mathcal N(\mu, \sigma^2) \\ \text{Perf}(p, g) &\sim \mathcal N\big(\text{Skill}(p), \beta^2\big) \\ \text{Win}(x, y, g) &= \text{Perf}(x, g) \\ &\quad > \text{Perf}(y, g) \\ P(\text{Win}) &= \Phi\Big(\frac{s_x - s_y}{\sqrt 2\, \beta}\Big) \end{aligned} \]
Read it as: skills come from a population prior; each game draws a performance around each skill with spread β; the higher performance wins. Perf(x) − Perf(y) is Gaussian with mean sx − sy and variance 2β², so the probability it is positive is the standard normal CDF Φ of the gap over √2β.
Say it“x wins with probability Phi of the skill gap over root-two beta.”
\[ \begin{aligned} d &= s_x - s_y + a \\ c &= \sqrt 2\, \beta \\ P(x \text{ wins}) &= \Phi\big((d - \varepsilon)/c\big) \\ P(\text{draw}) &= \Phi\big((\varepsilon - d)/c\big) \\ &\quad - \Phi\big((-\varepsilon - d)/c\big) \\ P(y \text{ wins}) &= \Phi\big((-d - \varepsilon)/c\big) \end{aligned} \]
Read it as: with an advantage a for x (say, playing White) and a draw margin ε, the performance gap is compared with ±ε: above ε x wins, below −ε y wins, in between it is a draw. The three probabilities add to 1. This is an ordered probit model; the chess project fits a and ε from data.
Say it“A draw is a performance gap smaller than epsilon either way.”

AIMA 15.1.3 · inference in relational probability models

Inference: unroll, then sample

The simplest way to answer a query about an RPM is to unroll it into its ground Bayes net and hand that to any algorithm from the earlier chapters. That works, but three things get in the way at scale. The unrolled net can be enormous: a shop with a million customers and a hundred thousand books has 1011 possible ratings. It is full of repeated substructure: every rating node has the same CPT, so a generic algorithm recomputes the same numbers again and again, which caching avoids. And it is full of symmetry: customers about whom we know the same things have identical posteriors. Lifted inference works on whole groups of interchangeable objects at once, the way first-order resolution reasons with variables instead of grounding every sentence.

The workhorse in practice is MCMC, because each ground variable’s Markov blanket stays small however big the net grows. In the skill model, Skill(p)’s blanket is its prior and the games p played; nothing else matters for resampling it. A Metropolis–Hastings step proposes a new skill, multiplies the likelihoods of those games only, and accepts or rejects. (The sampler here also redraws the common level of all the skills once per sweep, a move the chess project explains.) TrueSkill instead uses assumed density filtering, a one-pass form of expectation propagation: it keeps a Gaussian per player and, after each game, replaces the exact (non-Gaussian) update by the Gaussian with the same mean and variance. That is fast and online, but it is approximate and depends on the order of the games. Click cells to record wins (row player beats column player), or simulate a round robin, and compare the MCMC posterior with the one-pass Gaussian.

\[ \begin{aligned} p(\mathbf s \mid \text{res}) &\propto \textstyle\prod_{p} \mathcal N(s_p; \mu, \sigma^2) \\ &\quad \times \prod_{g} \Phi\Big(\frac{s_{w_g} - s_{l_g}}{\sqrt 2 \beta}\Big) \\ s_p' &= s_p + \tau z, \quad z \sim \mathcal N(0, 1) \\ \alpha &= \min\Big(1, \frac{\mathcal N(s_p')\, \Pi_p'}{\mathcal N(s_p)\, \Pi_p}\Big) \\ \Pi_p &= \textstyle\prod_{g \ni p} \Phi_g \end{aligned} \]
Read it as: the unrolled posterior over all skills is the product of the priors and one Φ factor per game, with wg the winner and lg the loser of game g (“res” is the list of results; Πp multiplies the Φ factors of p’s games). A random-walk step for one player’s skill is accepted with probability α, a ratio in which every factor not touching p cancels: only p’s prior and p’s games (g ∋ p) are recomputed.
Say it“Propose a new skill; accept with the ratio of prior times p’s game likelihoods, new over old.”
\[ \begin{aligned} c^2 &= 2\beta^2 + \sigma_w^2 + \sigma_l^2 \\ t &= (\mu_w - \mu_l)/c \\ v(t) &= \phi(t)/\Phi(t) \\ w(t) &= v(t)\big(v(t) + t\big) \\ \mu_w &\leftarrow \mu_w + \sigma_w^2\, v(t)/c \\ \mu_l &\leftarrow \mu_l - \sigma_l^2\, v(t)/c \\ \sigma_w^2 &\leftarrow \sigma_w^2 \big(1 - \sigma_w^2\, w(t)/c^2\big) \end{aligned} \]
Read it as: TrueSkill’s update after w beats l. The surprise of the result is measured by t, the winner’s lead in units of the total uncertainty c. An unexpected win (t very negative) gives a large v and a big jump; an expected win barely moves anything. Both variances shrink by a factor that w(t) ∈ (0, 1) controls; the loser’s variance shrinks in the same way.
Say it“Move the winner up and the loser down by v of t, scaled by their variances over c.”

AIMA 15.2, 15.2.1 · open-universe probability models

Open universes: when the objects are unknown

An RPM assumes we know exactly which objects exist. Real problems rarely grant that. How many people are behind these login IDs, given that dishonest customers open many accounts to boost their own books? Which citation strings refer to the same paper? How many aircraft are behind these radar blips, and how many earthquakes behind these seismometer readings? In logical terms this is uncertainty about existence (how many objects are there?) and identity (are these two observations the same object?). Dropping domain closure and unique names gives an open-universe probability model (OUPM).

An OUPM, written here in the style of the BLOG language, adds number statements to the dependency statements. #Customer ~ UniformInt(1, N) says how many customers exist. Number statements can depend on other objects through origin functions: #LoginID(Owner = c) ~ if Honest(c) then Exactly(1) else UniformInt(2, 10) creates one login ID for each honest customer and several for each dishonest one. Each created object is named by its origin, such as “the third login ID whose owner is the second customer”, so objects can be referred to before anyone knows how many there are. The semantics is a generative process: create the customers, decide each one’s honesty, create their login IDs, and so on. A possible world is the record of everything that process did. Its probability is the product of the probabilities of every number variable and every basic random variable in it. There are infinitely many possible worlds, and a world can contain unboundedly many variables. The model is still well defined if the dependencies are acyclic and every variable has finitely many ancestors. These conditions are checked on a contingent Bayes net, whose edges are labelled with the conditions under which they are active. Set how many login IDs posted reviews and how honest people are, and read off how many customers are behind them; then sample worlds to see the process run.

type Customer; type LoginID;
origin Customer Owner(LoginID);
#Customer ~ UniformInt(1, N)
Honest(c) ~ Boolean(h)
#LoginID(Owner = c) ~ if Honest(c) then Exactly(1) else UniformInt(2, 10)
evidence: there are exactly n login IDs        query: #Customer, #{c : not Honest(c)}
\[ \begin{aligned} P(\omega) &= \prod_{\#X} P\big(\#X \mid \text{Pa}\big) \\ &\quad \times \prod_{X} P\big(X \mid \text{Pa}\big) \\ P(\omega_{\text{ex}}) &= \tfrac{1}{N} \cdot h \cdot (1-h) \cdot 1 \cdot \tfrac{1}{9} \end{aligned} \]
Read it as: a world’s probability multiplies every choice the generative process made: how many objects of each kind, and the value of every function on them. The second line is an example world: two customers (probability 1/N), the first honest (h) with its one login ID (probability 1), the second dishonest (1 − h) with, say, four IDs (probability 1/9 under UniformInt(2, 10)).
Say it“The probability of a world is the product of all its number choices and all its value choices.”
\[ \begin{aligned} &P(\#C = m,\ D = d \mid n) \\ &\ \propto \tfrac{1}{N} \tbinom{m}{d} (1-h)^d h^{m-d} \\ &\quad \times P\big(\textstyle\sum_{i \le d} U_i = n - m + d\big) \\ &U_i \sim \text{UniformInt}(2, 10) \end{aligned} \]
Read it as: the exact posterior over the number of customers m and the number of dishonest ones d. Choose which d of the m are dishonest, weight by the honesty prior, and require the IDs to add up: the m − d honest customers own one ID each, so the d dishonest ones must own the other n − (m − d) between them. That last probability is a convolution of d uniform distributions, computed exactly here.

AIMA 15.2.2, 15.2.3 · inference in open-universe models · examples

How many things are out there?

Exact inference is rarely possible in an OUPM, because different worlds contain different numbers of variables. The general tool is MCMC over possible worlds. Besides moves that change a value, the sampler needs moves that change the structure of the world: create or delete an object (birth and death), or reassign an observation to a different object (split, merge and switch). Two facts keep this practical. A move touches only a small part of the world, so its acceptance ratio involves only that part. And the sampler need not build a whole world: it can work on partial worlds that instantiate only the variables relevant to the query and evidence, which is how a model with infinitely many possible objects fits in a computer.

Here is a small model that is the skeleton of many real ones. The number of objects K is Poisson(λ); each object has an unknown position θ uniform on [0, 10]; each object emits Poisson(μ) reports, and each report is its object’s position plus Gaussian noise σ. Objects that emit nothing exist but are never seen. Given the reports, a possible world comes down to a partition: which reports share an origin. Summing out the positions and the unseen objects by hand leaves a remarkably simple posterior over partitions. The Gibbs sampler then visits each report in turn and moves it to an existing group, or to a new one, which is a birth; emptying a group is a death. With up to nine reports every partition can also be listed, so here the sampler can be graded against the exact answer. Drag the reports together and apart, and change the noise; then run the sampler and see whether it finds the exact bars.

\[ \begin{aligned} P(\pi) &\propto \rho^{k} \prod_{j=1}^{k} M(\mathcal B_j) \\ \rho &= \lambda e^{-\mu} \\ M(\mathcal B) &= \int_0^{L} \tfrac{1}{L} \prod_{i \in \mathcal B} \mathcal N(y_i; \theta, \sigma^2)\, d\theta \\ K_{\text{unseen}} &\sim \text{Poisson}(\lambda e^{-\mu}) \end{aligned} \]
Read it as: a partition of the reports into k groups has prior weight ρk. The number of ways to pick which objects are seen, the Poisson counts and the orderings of the reports all collapse into that one factor. Each group contributes its marginal likelihood M, the chance its reports came from one object at an unknown position; M has a closed form in terms of the group’s mean and spread. The objects nobody saw are Poisson with mean λe−μ, whatever the reports say.
Say it“Each group costs a factor rho and earns its marginal likelihood.”
\[ \begin{aligned} P(i \to \mathcal B \mid \text{rest}) &\propto \frac{M(\mathcal B \cup \{i\})}{M(\mathcal B)} \\ P(i \to \text{new} \mid \text{rest}) &\propto \rho\, M(\{i\}) \\ \#\text{partitions of } n &= \text{Bell}(n) \end{aligned} \]
Read it as: the Gibbs move for report i. Take i out of its group, then put it back: into an existing group ℬ with weight given by how much better ℬ explains it, or into a brand-new object with weight ρ times its likelihood alone. Every term not involving i cancels (ℬ here is any existing group). The number of partitions of n reports is the Bell number, 21,147 for n = 9, which is why exact listing stops being possible quickly.
Say it“Join a group in proportion to how well it explains you, or start a new object in proportion to rho.”

Two open-universe systems that run in the real world

Citation matching. Bibliographic search engines see millions of citation strings, typed by different people in different styles, with abbreviations, typos and fields in different orders. The question is how many distinct papers and authors lie behind them, and which strings refer to which. The OUPM says there is an unknown number of researchers, each with a name; an unknown number of papers, each with a title and a list of authors; and each citation string comes from one paper through a noisy formatting process. Inference with MCMC over these worlds groups the strings far better than string-similarity heuristics, because it can explain away a typo using everything else known about the paper (Pasula et al., 2003).

Nuclear test-ban monitoring. The Comprehensive Nuclear-Test-Ban Treaty Organization runs a worldwide network of seismic stations, and must work out from their detections what events occurred, where and when. Every detection is either a false alarm or an arrival of some event’s wave at some station, and nobody knows how many events there were. The NET-VISA model (Arora, Russell & Sudderth, 2013) writes this as an OUPM: a Poisson number of events with random times, locations and magnitudes; a detection probability for each event, phase and station; false alarms at each station; and arrival times given by travel time plus noise. Its MCMC inference with birth, death and switch moves is the same pattern as the lab above, at planetary scale, and the organisation adopted it for its monitoring.

#SeismicEvent ~ Poisson(T * lambda_e)

AIMA 15.3, 15.3.1, 15.3.2 · keeping track of a complex world

Keeping track: which blip is which?

Add time to an open universe and you get the problem of keeping track. Objects persist and move; each time step brings new observations; and nothing says which observation came from which object. This is the data association problem. Its classic setting is multitarget tracking. A radar sweeps the sky every few seconds and returns a set of blips. Each aircraft is detected with some probability below 1, so some blips go missing. Clutter adds false alarms. Aircraft fly close together and cross. As an OUPM: an unknown number of aircraft, each position following a linear-Gaussian motion model; #Blip(Source = a, Time = t) is 1 with probability pD, else 0; #Blip(Time = t) ~ Poisson(λc) false alarms with no source; and each blip’s position is its source’s position plus noise.

If the associations were known, each track would be a separate Kalman filter. They are not, and the number of joint association hypotheses multiplies at every step, so the exact posterior is a mixture whose number of components grows exponentially. Practical trackers approximate. The nearest-neighbour filter lets each track grab the closest blip. Global nearest neighbour picks the single most probable joint assignment at each step, which the Hungarian algorithm finds in polynomial time; here it is found by listing every assignment. Multiple-hypothesis tracking keeps the best few histories alive in case the evidence later changes its mind. MCMC over associations and particle filters are the other main options. Turn up the clutter and lower the detection rate, and watch where the greedy method swaps two aircraft that the others keep apart.

\[ \begin{aligned} \Delta \log P &= \sum_{i \to j} \Big[\log p_D - \log \frac{\lambda_c}{L} \\ &\qquad + \log \mathcal N\big(z_j;\ \hat z_i,\ S_i\big)\Big] \\ &\quad + \sum_{i \to \varnothing} \log(1 - p_D) \end{aligned} \]
Read it as: the score one assignment adds to a hypothesis at one time step. For each track i given blip j: the log chance it was detected, plus the log density of that blip under the track’s Kalman prediction (mean ẑi, innovation variance Si), minus the log density the same blip would have as clutter (λc false alarms spread over a range of length L). For each track given no blip: the log chance it was missed. Blips left over are clutter.
Say it“Each assigned blip scores detection times fit over clutter density; each miss scores one minus p-D.”
\[ \begin{aligned} H_t &= \sum_{k} \tbinom{n}{k}\, \frac{m_t!}{(m_t - k)!} \\ H_{1:T} &= \prod_{t=1}^{T} H_t \end{aligned} \]
Read it as: with n tracks and mt blips at step t, choose which k tracks were detected (k from 0 to the smaller of n and mt) and give them distinct blips, in order: that is Ht joint assignments for one step. Over T steps the hypotheses multiply, which is why the exact posterior is out of reach after a few steps and every practical tracker prunes.

Traffic monitoring: the same car, two cameras later

A freeway traffic system with cameras every few kilometres wants travel times and origin–destination counts, and for that it must decide which vehicle seen downstream is which vehicle seen upstream. It is the tracking problem with only two scans and rich observations. Each vehicle has an appearance (length, colour, shape) that both cameras measure, differently, because of lighting and viewing angle. Its travel time is uncertain but not arbitrary. Some vehicles leave at an exit in between, and others join. Huang and Russell (1998) framed this as object identification: a posterior over matchings between the two sets of sightings, computed from an appearance model and a travel-time model learned from data. With six vehicles every possible matching can be listed and weighed. Make the cameras noisier and watch the matching become uncertain; the edge widths are exact posterior probabilities.

\[ \begin{aligned} P(\mathcal M \mid \text{obs}) &\propto \prod_{(i,j) \in \mathcal M} \pi_{ij} \\ &\quad \times p_{\text{ex}}^{\,n_{\text{exit}}}\, \kappa^{\,n_{\text{new}}} \\ \pi_{ij} &= (1 - p_{\text{ex}})\, f_\tau(\Delta t_{ij}) \\ &\quad \times f_\ell(\Delta \ell_{ij})\, f_c(\Delta c_{ij}) \end{aligned} \]
Read it as: a matching ℳ pairs some upstream sightings i with downstream sightings j. Each pair (i, j) scores πij: the chance the vehicle stayed on (1 − pex) times the densities of its travel time Δtij = tBj − tAi and of the changes Δℓij, Δcij in length and shade between the cameras. Each unmatched upstream vehicle left at an exit (probability pex = 0.15 each); each unmatched downstream one is a newcomer, with density κ.
Say it“A matching scores every pair’s travel time and appearance change, times p-ex for each exit and kappa for each newcomer.”
\[ \begin{aligned} P(i \leftrightarrow j) &= \sum_{\mathcal M \ni (i,j)} P(\mathcal M \mid \text{obs}) \\ |\{\mathcal M\}| &= \sum_{k} \binom{n_A}{k} \binom{n_B}{k}\, k! \end{aligned} \]
Read it as: the probability that i and j are the same vehicle adds up the posterior of every matching that pairs them. Choosing k vehicles on each side and pairing them in one of k! ways counts the matchings: 13,327 for six and six, so listing them all is easy here and hopeless for a real freeway, where MCMC or assignment algorithms take over.
Say it“The chance two sightings are one car sums every matching that pairs them.”

AIMA 15.4, 15.4.1, 15.4.2, 15.4.3, 15.4.4 · programs as probability models

Programs as probability models: reading text

The most general step is to drop the special syntax altogether. Take an ordinary programming language, add a primitive that makes a random choice and a way to condition on observed outputs, and every program becomes a probability model. Church, WebPPL, Anglican, Pyro and Gen are languages of this kind; they can express anything a computer can simulate. The semantics is short. A possible world is an execution trace: the sequence of random choices made in one run of the program. The probability of a trace is the product of the probabilities of the choices in it. Conditioning on the program’s output keeps the traces that produce it, each weighted by how likely it was to produce exactly that output.

The example is reading text. A generative program for an image of a line of text chooses how many letters there are, chooses each letter, chooses the spacing after each one, renders the letters with a font, and adds noise to every pixel. Reading is inference: given the noisy image, which traces could have drawn it? This is “analysis by synthesis”, or inverse graphics. Nothing in the program says how to read, only how to write. Here the font is a 5×7 pixel grid, the gap after each letter is 1 or 2 blank columns at random, and the noise is Gaussian. This program has a chain structure, so the posterior can be computed exactly by dynamic programming over columns, and the page does that. Type a phrase and raise the noise until the reader starts to make mistakes.

def text_image():
    letters = []
    prev = " "
    while True:
        c = sample(Uniform(ALPHABET))            # the Markov version: sample(Bigram(prev))
        g = sample(UniformInt(1, 2))             # blank columns after this letter
        letters.append((c, g)); prev = c
        if sample(Bernoulli(q)): break           # stop after each letter with probability q = 0.1
    ink = render(letters, FONT_5x7)              # a 7-row image, 5 columns per letter plus its gap
    for each pixel x:
        observe(Normal(ink[x], sigma), image[x]) # every pixel is its ink (0 or 1) plus noise
\[ \begin{aligned} P(\text{trace}) &= (1-q)^{n-1}\, q \\ &\quad \times \prod_{i=1}^{n} \tfrac12\, P(c_i \mid c_{i-1}) \\ &\quad \times \prod_{x} \mathcal N(\text{img}_x; \text{ink}_x, \sigma^2) \end{aligned} \]
Read it as: a trace is the list of letters c1, …, cn and gaps. Its prior is the product of each letter’s probability (1/27 each in the uniform version; the bigram probability given the previous letter in the Markov version), ½ for each gap and the geometric stopping probability. The likelihood multiplies a Gaussian density for every one of the 7 × W pixels.
Say it“A trace’s probability is its choices’ probabilities times the noise density of every pixel.”
\[ \begin{aligned} F(x, c) &= \sum_{g=1}^{2} \tfrac12\, \Lambda(c, x_g, g) \\ &\quad \times \sum_{c'} F(x_g, c')\, P(c \mid c') \\ &\quad \times (1 - q) \\ x_g &= x - 5 - g \\ P(\text{img}) &= \frac{q}{1 - q} \sum_c F(W, c) \end{aligned} \]
Read it as: F(x, c) adds up the probability of every way to write the first x columns ending with letter c and its gap. Λ(c, xg, g) is the likelihood of the columns from xg = x − 5 − g on (where the letter must start) showing glyph c followed by g blank columns. Starting from F(0, space) = 1/(1 − q), one pass over the columns gives the evidence. Replacing each sum by a max (and remembering the argmax) gives the most probable reading, which is the Viterbi algorithm of the HMM chapter.

Adding a Markov model of letters

With uniform letters, the reader has only the pixels to go on, so when the noise is high it will happily read “tqe” for “the”. A better generative program knows something about English. Replace the uniform letter choice by a bigram model, in which each letter is drawn given the one before it, with probabilities estimated by counting letter pairs in a large text. Here that text is the 0.94 million letters and spaces of the Tiny Shakespeare corpus. Nothing else in the program changes, and inference is the same dynamic program with P(c | c′) in place of 1/27. The improvement comes entirely from a better prior, which is the probabilistic-programming promise: change the model, keep the inference.

\[ \begin{aligned} P(c \mid c') &= \frac{\text{count}(c' c) + 1}{\text{count}(c') + 27} \end{aligned} \]
Read it as: the chance that letter c follows c′ is how often the pair c′c appears in the corpus, plus one, over how often c′ appears, plus 27 (add-one smoothing, so no pair is impossible). Spaces count as a letter, so the model also knows how words start and end.
Say it“P of c given c-prime is the pair count plus one over the count of c-prime plus twenty-seven.”

Compiling inference

Dynamic programming worked for the text program only because the program happens to have a chain structure. A general engine for any program uses MCMC over traces. Pick one random choice in the current trace, propose a new value for it, re-run the program with every other choice held fixed, and accept or reject using the ratio of the two traces’ probabilities. This is lightweight Metropolis–Hastings (Wingate, Stuhlmüller & Goodman, 2011). Two things make it subtle. A change can alter which later choices exist. Here a longer gap shifts every later letter and changes the image width, so this sampler pairs it with a shorter gap elsewhere to keep the width the observed W, and re-proposes the letters that move. And re-running the whole program to change one letter is wasteful, because only a few pixels’ likelihoods actually change.

That waste is the subject of compiling approximate inference. A generic Gibbs or MH implementation looks up each variable’s parents and children, indexes its tables and recomputes its Markov blanket, over and over, from data structures. A compiler analyses the model once and emits straight-line code for each update, with the CPT entries written in as constants and only the factors that can change recomputed. Compiling Bayes-net samplers this way can make each update many times faster. Probabilistic-programming systems do the same with incremental re-execution: they re-run only the parts of a trace that depend on the changed choice. Run both samplers below and read the timings; the answers are identical, only the speed differs.

\[ \begin{aligned} \alpha &= \min\Big(1,\ r\, \frac{q(\text{tr} \mid \text{tr}')}{q(\text{tr}' \mid \text{tr})}\Big) \\ r &= P(\text{tr}')/P(\text{tr}) \\ &= \frac{\Lambda_i'}{\Lambda_i} \cdot \frac{P(c_i' \mid c_{i-1})}{P(c_i \mid c_{i-1})} \\ &\quad \cdot \frac{P(c_{i+1} \mid c_i')}{P(c_{i+1} \mid c_i)} \end{aligned} \]
Read it as: the Metropolis–Hastings acceptance probability for a proposed trace tr′ (tr is the current trace, r the ratio of their probabilities). A letter change proposes a uniform new letter, which is symmetric, so the q terms cancel. A gap swap (a 1-gap with a 2-gap) also re-draws each letter it shifts from that letter’s pixel likelihood at its new position, so for swaps the q ratio stays in. For a letter change, everything cancels except the two bigram terms touching letter i and the likelihood Λi of its 35 pixels. The generic sampler recomputes all 7W pixels anyway; the compiled one computes only this ratio.
Say it“Accept with the ratio of new to old trace probability; for one letter only its neighbours and its pixels change.”
\[ \begin{aligned} P(x_i \mid \text{mb}_i) &\propto P(x_i \mid \text{pa}_i) \\ &\quad \times \textstyle\prod_{j \in \text{ch}_i} P(x_j \mid \text{pa}_j) \\ P(r \mid \cdot) &\propto P(r \mid c)\, P(w \mid s, r) \\ P(r \mid s, w) &= 0.3204 \end{aligned} \]
Read it as: Gibbs sampling resamples a variable from its distribution given its Markov blanket, which is its own CPT times its children’s CPTs. In the sprinkler network with Sprinkler and WetGrass observed true, Rain’s update (P(r | ·) is shorthand for given c, s and w) needs only P(Rain | Cloudy) and P(WetGrass | Sprinkler, Rain). The exact answer, by enumeration, is 0.0891/0.2781 = 0.3204.

Real-world project

Project: rating Lichess players with a probabilistic program

Lichess, the free online chess server, publishes every rated game it has hosted, and its database is released under Creative Commons CC0 (public domain dedication). This page embeds the headers of the 5,800 rated blitz games of January 2013 played among the 100 players who played the most blitz that month, taken from database.lichess.org’s file for 2013-01 on 2026-11-19. For each game it keeps only who had White, who had Black, the result, the day and the two players’ Lichess ratings before the game. Usernames have been replaced by numbers (player 1 played the most games, player 100 the fewest, 18). Results: White won 2,902, Black 2,676, and 222 were drawn.

The model is the skill model of this chapter, with White’s first-move edge and a draw margin added, and it is written below as a program in a tiny probabilistic programming language that this page implements: sample() makes a named random choice, v() reads one, and observe() conditions on data. Each observe() is handed a small function that builds its distribution, so the engine can re-evaluate one factor on its own. The inference engine runs the program once to compile it, recording which random choices each of those functions reads, and from that it builds each choice’s Markov blanket. Then it runs Metropolis-within-Gibbs on the 4,540 games of 1–24 January. The 1,260 games of the last week are held out to test the predictions.

function chessModel(m, data) {
  for (let p = 0; p < data.P; p++) m.sample('skill', p, Normal(1500, 300));     // one hidden skill per player
  m.sample('adv', 0, Normal(0, 100));                                            // White's first-move edge
  m.sample('eps', 0, Uniform(0, 100));                                           // draw margin
  for (let g = 0; g < data.ntrain; g++) {
    const w = data.w[g], b = data.b[g];
    m.observe(() => OrderedProbit(m.v('skill', w) - m.v('skill', b) + m.v('adv', 0),
                                  200 * Math.SQRT2, m.v('eps', 0)), data.r[g]);  // r: 0 Black wins, 1 draw, 2 White wins
  }
}
\[ \begin{aligned} s_p &\sim \mathcal N(1500, 300^2) \\ a &\sim \mathcal N(0, 100^2), \quad \varepsilon \sim \mathcal U(0, 100) \\ d_g &= s_{w_g} - s_{b_g} + a \\ r_g &\sim \text{OrdProbit}\big(d_g,\ 200\sqrt 2,\ \varepsilon\big) \end{aligned} \]
Read it as: the program in mathematics. Performance spread β = 200 rating points per player, the value Elo himself assumed, so the skill scale is close to the familiar rating scale. Only differences of skills affect any game, so the overall level is set by the prior’s 1500, not by Lichess’s scale; compare shapes, not levels.
Say it“Each game’s result is an ordered probit of the skill gap plus White’s edge, with a draw margin.”
\[ \begin{aligned} \text{mb}(s_p) &= \{\text{prior of } s_p\} \\ &\quad \cup \{g : p \in \{w_g, b_g\}\} \\ \bar s &\leftarrow \mathcal N\big(1500,\ 300^2/P\big) \\ s_p &\leftarrow s_p - \bar s_{\text{old}} + \bar s \end{aligned} \]
Read it as: what compilation finds: a skill’s Markov blanket is its prior and its own games, about 90 of the 4,540 on average, so a skill update costs about 1/50 of a full re-run. The engine cannot discover the second move, which the modeller adds: shifting every skill by the same amount changes no game’s likelihood, so the overall level can be drawn exactly from the prior each sweep. Without it the level drifts slowly.

Held-out week and the comparison with Python

The Python script below implements the same mini-language’s compiled sampler with the page’s random-number generator (mulberry32 with the same Box–Muller step) and the same Numerical Recipes erfc. Started from the same seed it walks the same chain, so the posterior means and the last sweep’s state can be compared digit for digit. As an independent check it also finds the posterior mode with SciPy’s L-BFGS, using SciPy’s exact normal CDF, and computes a Laplace approximation of the posterior spread.

import json, sys, math, time
import numpy as np
from scipy import optimize, stats
S = sys.argv[1] if len(sys.argv) > 1 else "./"
M32 = 0xFFFFFFFF
def rng(a):                                   # mulberry32, as on the page
    st = [a & M32]
    def r():
        st[0] = (st[0] + 0x6D2B79F5) & M32; a = st[0]
        t = ((a ^ (a >> 15)) * (1 | a)) & M32
        t = ((t + (((t ^ (t >> 7)) * (61 | t)) & M32)) & M32) ^ t
        return ((t ^ (t >> 14)) & M32) / 4294967296
    return r
def gauss(r):                                 # Box-Muller, as on the page
    u = 0.0
    while u == 0.0: u = r()
    return math.sqrt(-2 * math.log(u)) * math.cos(2 * math.pi * r())
def erfc(x):                                  # Numerical Recipes erfcc, as on the page
    z = abs(x); t = 1 / (1 + 0.5 * z)
    r = t * math.exp(-z * z - 1.26551223 + t * (1.00002368 + t * (0.37409196 + t * (0.09678418 + t * (-0.18628806 + t * (0.27886807 + t * (-1.13520398 + t * (1.48851587 + t * (-0.82215223 + t * 0.17087277)))))))))
    return r if x >= 0 else 2 - r
SQRT2 = math.sqrt(2)
Phi = lambda x: 0.5 * erfc(-x / SQRT2)

D = json.load(open(S + "x124-chess.json")); P, G, NT = D["P"], D["G"], D["ntrain"]
w, b, res = D["w"], D["b"], D["r"]
BETA = 200.0; C = BETA * math.sqrt(2)         # performance sd 200 per player, so a difference has sd 200*sqrt(2)
MU0, SD0 = 1500.0, 300.0
LOG2PI = math.log(2 * math.pi)
def lpN(x, m, sd): z = (x - m) / sd; return -0.5 * (z * z) - math.log(sd) - 0.5 * LOG2PI   # Normal log-density, as on the page
def ll(d, eps, r):                            # ordered probit: white wins, draw or black wins
    if r == 2: return math.log(Phi((d - eps) / C))
    if r == 0: return math.log(Phi((-d - eps) / C))
    return math.log(Phi((eps - d) / C) - Phi((-eps - d) / C))
# the "compiled" sampler: each skill's Markov blanket is the list of its games
mine = [[] for _ in range(P)]
for g in range(NT): mine[w[g]].append(g); mine[b[g]].append(g)
def run(sweeps, burn, seed):
    R = rng(seed); s = [MU0] * P; adv = 0.0; eps = 20.0
    L = [ll(s[w[g]] - s[b[g]] + adv, eps, res[g]) for g in range(NT)]
    acc = [0, 0, 0]; keep = []; trace = []
    for it in range(sweeps):
        for p in range(P):
            new = s[p] + 60 * gauss(R); old = s[p]
            dl = lpN(new, MU0, SD0) - lpN(old, MU0, SD0); nl = []
            for g in mine[p]:
                sw = new if w[g] == p else s[w[g]]; sb = new if b[g] == p else s[b[g]]
                v = ll(sw - sb + adv, eps, res[g]); nl.append(v); dl += v - L[g]
            if math.log(R()) < dl:
                s[p] = new; acc[0] += 1
                for g, v in zip(mine[p], nl): L[g] = v
        new = adv + 8 * gauss(R); dl = lpN(new, 0, 100) - lpN(adv, 0, 100); nl = [0.0] * NT
        for g in range(NT): nl[g] = ll(s[w[g]] - s[b[g]] + new, eps, res[g]); dl += nl[g] - L[g]
        if math.log(R()) < dl: adv = new; L = nl; acc[1] += 1
        new = eps + 4 * gauss(R)
        if 0 < new < 100:
            dl = -math.log(100) - (-math.log(100)); nl = [0.0] * NT
            for g in range(NT): nl[g] = ll(s[w[g]] - s[b[g]] + adv, new, res[g]); dl += nl[g] - L[g]
            if math.log(R()) < dl: eps = new; L = nl; acc[2] += 1
        else: R()                                 # the page also draws its uniform when the proposal leaves (0, 100)
        # a block move: shifting every skill by the same amount leaves every game's likelihood unchanged,
        # so the shift can be drawn exactly from the prior (a Gibbs step on the overall level)
        delta = (MU0 - sum(s) / P) + SD0 / math.sqrt(P) * gauss(R)
        s = [x + delta for x in s]
        trace.append((s[0], s[P - 1], adv, eps, sum(L)))
        if it >= burn: keep.append(s[:] + [adv, eps])
    return np.array(keep), acc, trace

           np.log(stats.norm.cdf((e - d) / C) - stats.norm.cdf((-e - d) / C))))

Wrap-up

Five lines to remember

  • A relational probability model writes dependency statements once, over types and functions; with unique names and domain closure it unrolls into an ordinary Bayes net with one ground variable per function and tuple of objects, and P(world) is the product of their CPTs.
  • The skill model (Skill ~ N(μ, σ²), Performance ~ N(Skill, β²), the higher performance wins) gives P(win) = Φ(gap/√2β); inference unrolls it and samples, because each skill’s Markov blanket is just its own games. TrueSkill’s one-pass Gaussian is the fast, approximate alternative.
  • Open-universe models add number statements and origin functions, so worlds differ in which objects exist; a world’s probability multiplies all its number and value choices, and inference is MCMC over worlds with birth, death, split and merge moves.
  • Keeping track of moving objects is data association: the number of association hypotheses multiplies every step, so trackers prune (nearest neighbour, best assignment per step, multiple hypotheses, MCMC). Matching cars between cameras is the same problem with two scans.
  • Any program with random choices is a probability model whose worlds are execution traces; reading text is inference in a rendering program, a bigram prior fixes what the pixels cannot, and compiling inference (incremental re-execution, generated straight-line code) gives the same answers far faster.

Check your understanding

An RPM for a bookshop has 1,000 customers and 200 books. How many ground random variables does its unrolling have, without fans?

Two per customer (Honest, Kindness), one per book (Quality) and one per customer–book pair (Recommendation): 2,000 + 200 + 200,000 = 202,200. The model itself is still four dependency statements; only the grounding grows.

Two players have skills 1,700 and 1,500 with β = 200 and no draws. What is the chance the stronger one wins, and why is it not higher?

Φ(200/(200√2)) = Φ(0.707) ≈ 0.76. Each performance has spread 200, so their difference has spread 283, and a 200-point gap is less than one standard deviation of that difference: the weaker player out-performs the stronger about one game in four.

Why can an open-universe model have infinitely many possible worlds and still define a proper distribution?

Each world is produced by a generative process whose choices have probabilities that multiply. If the dependencies are acyclic and every variable has finitely many ancestors, each variable’s distribution is defined by finitely many earlier choices, and the probabilities of all worlds add up to 1 even though there are infinitely many of them (for example, a Poisson number of objects).

A tracker that always assigns each track its nearest blip works well in clear skies. When does it fail, and what do better trackers do differently?

When targets come close or cross, and when clutter or missed detections put a false blip nearest to a track. Then a greedy choice can swap identities, or attach a track to clutter, and it never reconsiders. Global assignment makes the best joint choice per step; multiple-hypothesis tracking keeps several histories until later scans disambiguate; MCMC over associations samples the full posterior.

In lightweight MH over program traces, why is it a problem to change the gap after one letter, and how did this chapter’s sampler handle it?

Changing a gap shifts every later letter, so the change touches every later pixel. It also changes the image’s width, which must equal the observed width, so a lone gap change always produces a trace of probability zero. The sampler instead swaps a 1-gap with a 2-gap elsewhere, which keeps the width, and re-proposes the letters in between from their pixels at the new positions, with the proposal probabilities kept in the acceptance ratio. General systems handle such structure changes with address schemes and with proposals that add or remove choices.
