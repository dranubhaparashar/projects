Deep Q-Networks

When the table is too big, learn a function instead

Chapter 3.1 kept one number for every state and action. That works on a 4×4 grid and fails on anything with a camera, a joystick or a continuous measurement. A deep Q-network replaces the table with a neural network that reads the state and outputs a value for every action. Getting it to learn needed three ideas, which this chapter builds one by one. On the right, a small network trained in this page is balancing a pole on a cart. Tap the picture to shove the pole and watch the network’s two Q-values decide how to recover.

The problem

Too many states for a table

The cart-pole’s state is four real numbers: the cart’s position x and velocity \(\dot x\), the pole’s angle θ and its angular velocity \(\dot\theta\). A Q-table needs a finite list of states, so the obvious move is to chop each number into b bins. The trouble is the exponent. Four numbers with b bins each make b4 cells, and every cell must be visited, many times, before its Q-value means anything. A table also learns nothing about a cell from its neighbours: with fine bins, a pole at 2.0° and one at 2.1° are strangers. Raise the number of bins and see how much of the table real experience ever touches.

\[ |\text{table}| = b^{\,d} \times |\mathcal{A}| \]
Read it as: d numbers in the state, b bins for each, |𝔄| actions. The table grows exponentially with the number of state variables. For an Atari screen (84×84 grey pixels, 4 frames stacked, 256 grey levels) d = 28,224, so the table would have 25628,224 rows, a number with about 68,000 digits.
Say it“The table size is b to the power d, times the number of actions.”

Function approximation

One update, many states

Instead of a row per state, describe each state by a few features φ(s) and let Q be a weighted sum of them. Now the parameters are the weights w, not the table entries, and one update changes Q at every state that shares features with the one you updated. That sharing is called generalisation. Below is a one-dimensional corridor: from position s the agent steps 0.1 to the right, and reaching the end pays +1. The true Q-values form a staircase, γ lower for every step still to go. The features are bumps spread along the corridor. Click anywhere on the plot to make one Q-learning update at that state, then widen the bumps and click again.

\[ \begin{aligned} Q(s,a;\mathbf{w}) &= \mathbf{w}_a^{\top}\boldsymbol{\phi}(s) \\ &= \sum_{i=1}^{k} w_{a,i}\,\phi_i(s) \end{aligned} \]
Read it as: k features, each a bump φi(s) centred at ci with width σ, scaled so the k bumps add up to 1 at every s. Q is a blend of the weights of the bumps that are “on” at s. A table is the special case of one bump per state, each covering only its own state.
Say it“Q of s and a is the dot product of that action’s weights with the feature vector of s.”
\[ \begin{aligned} \delta &= r + \gamma \max_{a'} Q(s',a') - Q(s,a) \\ \mathbf{w} &\leftarrow \mathbf{w} + \alpha\,\delta\,\nabla_{\mathbf{w}} Q(s,a;\mathbf{w}) \end{aligned} \]
Read it as: the same TD error as tabular Q-learning (Q now means the current approximation Q(·;w)), but the correction is spread over the weights in proportion to the gradient, which for a linear Q is just φ(s). It is called a semi-gradient update because the target r + γ max Q(s′) also depends on w, and we pretend it doesn’t.
Say it“Delta is reward plus gamma times the best next Q, minus the current Q; nudge the weights by alpha times delta times the gradient of Q.”

The price

The deadly triad, in two states

Generalisation has a dark side. Sutton and Barto name three ingredients that are each harmless and together can make the weights run off to infinity: function approximation (states share weights), bootstrapping (targets built from your own estimates) and off-policy learning (updating on a different mix of states than the policy would visit). Their smallest example has two states. The first has feature 1, so its value is w; the second has feature 2, so its value is 2w. The move from the first to the second pays 0, and the true value of both is 0. If we only ever update the first transition, its target is γ·2w: raising w raises the target twice as fast. Pick which ingredient to remove and watch whether the estimate settles.

\[ \begin{aligned} w_{t+1} &= w_t + \alpha\,(0 + \gamma\cdot 2w_t - w_t)\cdot 1 \\ &= \big(1 + \alpha(2\gamma - 1)\big)\,w_t \end{aligned} \]
Read it as: the TD error at state 1 is the target γ·2w minus the estimate w; the gradient of w·1 with respect to w is 1. Each update multiplies w by the same factor. When γ > ½ the factor is above 1, so w grows geometrically, for any step size α > 0. Shrinking α only slows the explosion.
Say it“w next is w times one plus alpha times two-gamma-minus-one.”

The architecture

A network that scores every move

Hand-made bumps work in one dimension. For four (or 28,224) dimensions we let a neural network learn its own features. The DQN design has one trick worth noticing: the state goes in, and one output per action comes out, so a single forward pass scores every move and the greedy action is the largest output. Learning is regression: the network’s Q(s,a) is pulled towards the target y = r + γ max Q(s′,·). The network below has two hidden layers of 32 ReLU units and is the best snapshot of the project’s seed-0 run (press Train below with both tricks on and seed 0 to get exactly this network). Move the sliders to set up a state and see what the network would do, and whether its numbers satisfy Bellman’s equation.

\[ \begin{aligned} \mathbf{h}_1 &= \operatorname{relu}(W_1\mathbf{s} + \mathbf{b}_1) \\ \mathbf{h}_2 &= \operatorname{relu}(W_2\mathbf{h}_1 + \mathbf{b}_2) \\ Q(\mathbf{s},\cdot\,;\theta) &= W_3\mathbf{h}_2 + \mathbf{b}_3 \end{aligned} \]
Read it as: s is the 4-number state (each divided by a fixed scale so it is roughly between −1 and 1). Two layers of ReLU units build features; the last layer gives two numbers, Q(s, push left) and Q(s, push right). θ collects every weight and bias: here 1,282 numbers in all.
Say it“Two ReLU layers, then a linear layer with one output per action.”
\[ \begin{aligned} y &= r + \gamma \max_{a'} Q(s',a';\theta) \\ L(\theta) &= \mathbb{E}\big[\,\ell\big(y - Q(s,a;\theta)\big)\big] \end{aligned} \]
Read it as: the loss compares the network’s value for the action taken with a one-step look-ahead. ℓ is the squared error, or (as DQN uses) the Huber loss: squared for errors below 1 and linear beyond, which caps each sample’s gradient at 1. A network that has learned well has y ≈ Q everywhere it has been.
Say it“The target is reward plus gamma times the best next Q; the loss is the expected Huber error between target and prediction.”

Trick one

Experience replay: learning from shuffled memories

An agent’s experience arrives as a stream in which each step looks almost exactly like the last. Gradient descent assumes the opposite: that each mini-batch is a fair sample of everything. Feed a network 32 consecutive steps and it fits the corner of the world it is standing in, and quietly forgets the rest. Experience replay (Lin, 1992) stores the last N transitions (s, a, r, s′) in a buffer and trains on random mini-batches drawn from it. Neighbouring steps rarely land in the same batch, and each transition gets reused many times. To isolate the effect, the network below fits a fixed target curve (no bootstrapping), from data that arrives in the order an agent walking the corridor would see it. Press Run, then change the buffer size.

\[ \begin{aligned} \mathcal{D} &= \{e_{t-N+1},\dots,e_t\} \\ e &= (s,a,r,s') \\ \mathcal{B} &\sim \text{Uniform}(\mathcal{D}) \\ L(\theta) &= \tfrac{1}{|\mathcal{B}|}\textstyle\sum_{j\in\mathcal{B}} \big(y_j - Q(s_j,a_j;\theta)\big)^2 \end{aligned} \]
Read it as: keep the N most recent transitions; at every step draw a mini-batch 𝔅 uniformly at random from them and take one gradient step on its average loss. A transition stays in the buffer for N steps and is picked with probability |𝔅|/N each time, so it is used about |𝔅| times on average whatever N is. Replay only works with an off-policy method like Q-learning: old transitions came from older, worse policies, and the max in Q-learning’s target does not care.
Say it“The loss is the average squared error over a mini-batch drawn uniformly from the last N transitions.”

Trick two

Freezing the target

In supervised learning the labels sit still. In Q-learning the label y = r + γ max Q(s′) is computed by the very network being trained, so every gradient step also moves the target, often in the same direction: you are chasing your own tail. DQN’s fix is a target network: a copy θ− of the weights that computes the targets and is only refreshed every C steps. Between refreshes the problem is ordinary regression towards fixed labels. Below is Baird’s counterexample (1995), the classic case where semi-gradient Q-learning blows up: seven states, eight weights, all rewards 0, and updates spread evenly over the states while the target policy always heads for state 7. Raise the refresh period C and compare the two curves.

\[ \begin{aligned} y &= r + \gamma \max_{a'} Q(s',a';\theta^{-}) \\ \theta^{-} &\leftarrow \theta \ \text{ every } C \text{ updates} \end{aligned} \]
Read it as: the only change to the loss is the minus sign on θ: the target comes from the frozen copy. With C = 1 the copy is always current and nothing changes. Mnih et al. refreshed it every 10,000 updates. Here, states 1–6 have value 2wi + w8 and state 7 has w7 + 2w8; every state’s target is γ times the value of state 7, and the true values are all 0.
Say it“The target uses the frozen weights theta-minus, which are copied from theta every C updates.”

Trick three

Why max is an optimist: Double DQN

Every Q-value the network outputs is an estimate with some error. The target takes the maximum of several such estimates, and the maximum of noisy numbers is biased upwards: whichever action happens to be overestimated wins. That optimism is then bootstrapped into the previous state, and the one before. Double Q-learning (van Hasselt, 2010) separates the two jobs. One set of estimates chooses the best action; an independent set judges it. Double DQN (van Hasselt, Guez & Silver, 2016) uses the online network to choose and the target network to judge, a one-line change. Below, every action is truly worth 0 and each estimate is the true value plus noise. Add actions or noise and compare the two targets.

\[ \mathbb{E}\Big[\max_a \hat Q(a)\Big] \;\ge\; \max_a \mathbb{E}\big[\hat Q(a)\big] \]
Read it as: the expected maximum of the estimates is at least the maximum of the true values, with equality only when there is no noise. For n actions with independent errors of size σ, the bias is σ times the expected largest of n standard normal draws: about 0.56σ for 2 actions, 1.54σ for 10.
Say it“The expected max of the estimates is at least the max of their expectations.”
\[ \begin{aligned} a^{*} &= \arg\max_{a'} Q(s',a';\theta) \\ y^{\text{DDQN}} &= r + \gamma\, Q(s',a^{*};\theta^{-}) \end{aligned} \]
Read it as: pick the next action with the online weights θ, but read its value from the target weights θ−. An action that looks good only because of the online net’s noise is unlikely to be overvalued by the target net too, so the bias mostly disappears.
Say it“Reward plus gamma times the target net’s value of the action the online net likes best.”

Real-world project

Project: teaching a network to balance a pole

The cart-pole is the oldest benchmark in reinforcement learning. Barto, Sutton and Anderson (1983) used it to show that two neuron-like elements could learn to balance a pole from nothing but a failure signal; today it ships as CartPole-v1 in Gymnasium, the maintained successor of OpenAI Gym. A 1 kg cart on a frictionless track carries a 0.1 kg pole, 1 m long, hinged at its base. Each 0.02 s the agent pushes the cart left or right with 10 N. It earns +1 for every step the pole stays within 12° of upright and the cart within 2.4 m of the centre; an episode is capped at 500 steps. You will check the page’s physics against Gymnasium itself, then train a DQN here, with each of the three tricks switchable.

1 · The physics, checked against Gymnasium

\[ \begin{aligned} \text{temp} &= \frac{F + m_p l\,\dot\theta^2 \sin\theta}{m_c + m_p} \\ \ddot\theta &= \frac{g\sin\theta - \cos\theta\cdot\text{temp}}{l\left(\frac43 - \frac{m_p\cos^2\theta}{m_c+m_p}\right)} \\ \ddot x &= \text{temp} - \frac{m_p l\,\ddot\theta\cos\theta}{m_c+m_p} \end{aligned} \]
Read it as: F = ±10 N is the push, g = 9.8 m/s², mc = 1, mp = 0.1, and l = 0.5 m is half the pole’s length. Gravity tips the pole (g sinθ); accelerating the cart swings it the other way (cosθ·temp). Then one Euler step of 0.02 s: x += 0.02·\(\dot x\), \(\dot x\) += 0.02·\(\ddot x\), θ += 0.02·\(\dot\theta\), \(\dot\theta\) += 0.02·\(\ddot\theta\), exactly as Gymnasium’s cartpole.py computes them, operation for operation.
Say it“Theta double-dot is g sine theta minus cos theta times temp, over l times four-thirds minus the pole’s share of cos-squared theta.”

The same project in Python

import numpy as np, gymnasium as gym

def mulberry32(a):                       # the page's random numbers, bit for bit
    s = [a & 0xFFFFFFFF]
    def r():
        s[0] = (s[0] + 0x6D2B79F5) & 0xFFFFFFFF; a = s[0]
        t = ((a ^ (a >> 15)) * (1 | a)) & 0xFFFFFFFF
        t = ((t + (((t ^ (t >> 7)) * (61 | t)) & 0xFFFFFFFF)) & 0xFFFFFFFF) ^ t
        return ((t ^ (t >> 14)) & 0xFFFFFFFF) / 4294967296
    return r

CFG = dict(H=32, lr=1e-3, gamma=0.99, batch=32, buffer=25000, sync=200, steps=25000,
           warmup=500, eps_steps=4000, eps_end=0.05, check=1000, check_n=5)
SCALE = np.array([2.4, 3.0, 0.21, 3.0])
env, test_env = gym.make("CartPole-v1"), gym.make("CartPole-v1")   # Gymnasium physics, 500-step limit

def start(env, r):                                # seeded start state, uniform in ±0.05
    env.reset(); s = np.array([r() * 0.1 - 0.05 for _ in range(4)])
    env.unwrapped.state = s
    return s.astype(np.float32) / SCALE

def init(r, sizes):                               # uniform(±1/sqrt(fan_in)), like PyTorch
    P = []
    for fi, fo in zip(sizes[:-1], sizes[1:]):
        b = 1 / np.sqrt(fi)
        P += [np.array([[(r() * 2 - 1) * b for _ in range(fo)] for _ in range(fi)]),
              np.array([(r() * 2 - 1) * b for _ in range(fo)])]
    return P

def forward(P, X):                                # ReLU hidden layers, linear output: one Q per action
    hs = [X]
    for i in range(0, len(P), 2):
        z = hs[-1] @ P[i] + P[i + 1]
        hs.append(z if i == len(P) - 2 else np.maximum(z, 0))
    return hs

def greedy_test(P, n, seed):
    r, out = mulberry32(seed), []
    for _ in range(n):
        o, k, done = start(test_env, r), 0, False
        while not done:
            q = forward(P, o[None])[-1][0]
            o, _, term, trunc, _ = test_env.step(int(q[1] > q[0])); o = o / SCALE; k += 1; done = term or trunc
        out.append(k)
    return np.mean(out)

def train(seed, replay=True, target=True, double=False, c=CFG):
    r = mulberry32(seed * 7919 + 1); B, N = c["batch"], c["buffer"]
    P = init(r, [4, c["H"], c["H"], 2]); T = [p.copy() for p in P]
    m = [0 * p for p in P]; v = [0 * p for p in P]
    S, A, S2, D = np.zeros((N, 4)), np.zeros(N, int), np.zeros((N, 4)), np.zeros(N)
    size = ptr = upd = ep = 0; episodes = []; best = (-1, None)
    o = start(env, r)
    for t in range(c["steps"]):
        eps = max(c["eps_end"], 1 - (1 - c["eps_end"]) * t / c["eps_steps"])
        if r() < eps: a = int(r() * 2)                       # explore
        else: q = forward(P, o[None])[-1][0]; a = int(q[1] > q[0])
        o2, rew, term, trunc, _ = env.step(a); o2 = o2 / SCALE; ep += 1
        S[ptr], A[ptr], S2[ptr], D[ptr] = o, a, o2, term       # store the transition
        ptr = (ptr + 1) % N; size = min(size + 1, N); o = o2
        if term or trunc: episodes.append(ep); ep = 0; o = start(env, r)
        if t + 1 >= c["warmup"]:
            idx = (np.array([int(r() * size) for _ in range(B)]) if replay      # random mini-batch
                   else np.array([(ptr - 1 - j) % N for j in range(B)]))        # or: the last B steps
            qn = forward(T if target else P, S2[idx])[-1]
            if double and target:                                              # online net chooses, target net judges
                nv = qn[np.arange(B), forward(P, S2[idx])[-1].argmax(1)]
            else: nv = qn.max(1)
            y = 1.0 + c["gamma"] * (1 - D[idx]) * nv                            # every step pays +1
            hs = forward(P, S[idx]); err = hs[-1][np.arange(B), A[idx]] - y
            g = np.zeros((B, 2)); g[np.arange(B), A[idx]] = np.clip(err, -1, 1) / B   # Huber gradient
            grads = [None] * len(P)
            for i in range(len(P) - 2, -1, -2):                                 # backpropagation
                grads[i], grads[i + 1] = hs[i // 2].T @ g, g.sum(0)
                if i: g = (g @ P[i].T) * (hs[i // 2] > 0)
            upd += 1; lr = c["lr"] * max(0.05, 1 - t / c["steps"])
            for k in range(len(P)):                                             # Adam
                m[k] = 0.9 * m[k] + 0.1 * grads[k]; v[k] = 0.999 * v[k] + 0.001 * grads[k] ** 2
                P[k] = P[k] - lr * (m[k] / (1 - 0.9 ** upd)) / (np.sqrt(v[k] / (1 - 0.999 ** upd)) + 1e-8)
            if target and upd % c["sync"] == 0: T = [p.copy() for p in P]      # refresh the target net
        if (t + 1) % c["check"] == 0:                                           # keep the best snapshot
            e = greedy_test(P, c["check_n"], 999)
            if e >= best[0]: best = (e, [p.copy() for p in P])
    return episodes, greedy_test(P, 20, 12345), greedy_test(best[1], 20, 12345)

Wrap-up

Five lines to remember

  • A Q-table needs bd rows and a visit to each; a function Q(s,a;θ) shares what it learns between similar states, which is the only way to handle continuous or pixel states.
  • Function approximation + bootstrapping + off-policy learning (the deadly triad) can diverge: in the two-state example w grows by 1 + α(2γ−1) per update.
  • A DQN takes the state in and gives one Q-value per action out, and is trained by regression towards y = r + γ max Q(s′,·), usually with the Huber loss.
  • Experience replay breaks the correlation of consecutive steps and reuses data; a target network θ− holds the labels still for C updates.
  • The max over noisy estimates is biased upwards; Double DQN lets the online net choose the action and the target net judge it.

Check your understanding

Why not simply discretise CartPole into 30 bins per variable and run tabular Q-learning?

That is 304 = 810,000 cells, times 2 actions, and most are never visited, while the visited ones need many visits each. Worse, nothing learned in one cell helps its neighbour. A function approximator lets nearby states share estimates.

Experience replay works with Q-learning. Why would it be a problem for SARSA?

SARSA’s target uses the next action the current policy would take. A stored transition carries the action an older policy took, so the target would describe the wrong policy. Q-learning’s max target is off-policy: it does not care which policy produced (s, a, r, s′).

In the w→2w example with γ = 0.9, would a smaller step size α prevent divergence?

No. The factor 1 + α(2γ−1) = 1 + 0.8α is above 1 for every α > 0; a smaller α only slows the growth. You must remove one leg of the triad (or change the features).

A target network tamed Baird’s counterexample. Would it rescue the two-state w→2w example too?

No. With a frozen copy, each phase fits w to the target γ·2w−, so after a long phase w ≈ 2γw−, which still grows when γ > ½. A single feature cannot represent the target, so freezing it only slows the spiral. Baird’s features can represent any value function, so there each frozen phase makes real progress.

Ten actions, all truly worth 0, each estimated with independent noise of standard deviation 1. What does the max target expect, and what does the double target expect?

The max of 10 standard normal draws averages about 1.54, so the max target is 1.54 too high on average. The double target picks with one set and reads the value from an independent set, whose error has mean 0, so it averages 0.
