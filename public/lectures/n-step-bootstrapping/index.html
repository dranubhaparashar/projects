n-step Bootstrapping

Look a few rewards ahead, then trust your estimate

One-step TD learns from a single reward and then leans on its own guess. Monte Carlo waits for the whole episode and leans on nothing. Neither extreme is usually best. An n-step method adds up the next n rewards and only then bootstraps, so n becomes a dial between the two, and a dial you can tune. On the right a boat is learning, by n-step Sarsa, to cross a real wind field: the January winds off the Pacific coast of southern Mexico, measured by satellite, where a jet of wind pours south through a gap in the mountains. Each voyage costs one point per step. Pick n, or tap the sea to move the start, and watch how quickly the voyages get shorter.

The idea

Between one step and the whole episode

Every value-learning method answers one question: after visiting a state, what number do we nudge its value towards? Monte Carlo waits for the end of the episode and uses the actual return, every reward that followed. One-step TD uses one reward plus the discounted value of the next state, a guess standing in for everything after it. That is bootstrapping: updating an estimate from another estimate.

There is a whole family in between. Take two real rewards and then bootstrap; or three; or n. The target is the n-step return, and its diagram is a chain n transitions long that ends in a state whose value we look up. A second benefit hides here: with one-step TD, the same time step decides both how often we act and how far ahead we look. n-step methods let the look-ahead span several actions, so we can bootstrap over a stretch of time in which something meaningful has happened.

Below is one recorded episode of a random walk along 19 states (it starts in the middle, steps left or right with equal chance, and pays +1 for leaving on the right, −1 on the left, 0 otherwise). The value estimate V is what one-step TD had learned after 30 episodes (α = 0.3): roughly right, but not exactly. Pick a time t and slide n to see which rewards and which estimate make up the target.

\[ \begin{aligned} G_{t:t+n} &= R_{t+1} + \gamma R_{t+2} + \cdots + \gamma^{n-1} R_{t+n} \\ &\quad + \gamma^{n}\, V_{t+n-1}(S_{t+n}) \\ G_{t:t+n} &= G_t \quad \text{if } t+n \ge T \end{aligned} \]
Read it as: the target for the state visited at time t is the next n rewards, each discounted by γ per step, plus the discounted estimate of the state reached n steps later. Vt+n−1 is the estimate as it stands when that state is reached. If the episode ends (at time T) before n steps are up, there is nothing left to bootstrap from and the target is just the full return Gt, as in Monte Carlo. n = 1 gives the one-step TD target Rt+1 + γV(St+1).
Say it“The n-step return from t is the sum of the next n discounted rewards, plus gamma to the n times the value of the state n steps on.”

Prediction

n-step TD prediction

The learning rule is the familiar one with the new target. There is one practical wrinkle: the n-step return for time t needs the reward at time t + n, so the update for the state visited at t can only be made n steps later. The algorithm therefore keeps the last n + 1 states and rewards in a small rolling buffer; at time t it updates the state from time τ = t − n + 1. Nothing is updated during the first n − 1 steps of an episode, and once the episode ends the remaining n − 1 states are updated in a burst, each with whatever rewards are left.

\[ \begin{aligned} V_{t+n}(S_t) &= V_{t+n-1}(S_t) \\ &\quad + \alpha\,\big[\,G_{t:t+n} - V_{t+n-1}(S_t)\,\big] \end{aligned} \]
Read it as: for each time 0 ≤ t < T, move the estimate for St a fraction α of the way towards its n-step return. Every other state’s value stays as it was. The subscript t + n says when the update happens, n steps after the visit.
Say it“The new V of S-t is the old V plus alpha times the n-step return minus the old V.”

Why should this work? Because the expected n-step return is a better estimate of vπ than V itself, and provably so in the worst state: its error is at most γn times V’s worst error. This error-reduction property is what lets every n-step TD method converge to the right values under the usual conditions.

\[ \begin{aligned} &\max_s \Big|\, \mathbb{E}_\pi\big[G_{t:t+n} \mid S_t = s\big] - v_\pi(s) \Big| \\ &\qquad \le\; \gamma^{n} \max_s \big| V_{t+n-1}(s) - v_\pi(s) \big| \end{aligned} \]
Read it as: take the n-step return’s average from each state, under the policy being evaluated. Its largest error over all states is no more than γn times the largest error of V. The n real rewards carry no error at all; only the bootstrapped tail does, and it is discounted n times. With γ = 1 the bound alone promises only “no worse”, but episodes that end inside the window remove error too.
Say it“The worst error of the expected n-step return is at most gamma to the n times the worst error of V.”

Read it as: after episode e, compare every estimate with the true value; the true values of this walk are a straight line from −0.9 (state 1) to +0.9 (state 19). Each curve point is the average of RMS1, …, RMS10 over 100 runs, so low means “learned fast and accurately”.

Control

n-step Sarsa: credit flows back n steps at once

For control we learn action values instead, and switch the states in the n-step return for state–action pairs. The return ends with the estimated value of the pair n steps on; the policy is ε-greedy with respect to the current Q, so improving Q improves the policy. One-step Sarsa is the case n = 1.

The payoff shows up when rewards are rare. In the grid below the only reward is +1 for reaching the goal ★, and all values start at zero. After the first episode, one-step Sarsa has learned something about a single action, the last one; n-step Sarsa has strengthened the last n actions of the path at once. A variant, n-step Expected Sarsa, replaces the last sampled action by the policy’s average over all actions, which removes one source of noise. Play a few episodes with n = 1, then reset and do it again with n = 8.

\[ \begin{aligned} G_{t:t+n} &= \textstyle\sum_{k=1}^{n} \gamma^{k-1} R_{t+k} \\ &\quad + \gamma^n\, Q_{t+n-1}(S_{t+n}, A_{t+n}) \\ Q_{t+n}(S_t,A_t) &= Q_{t+n-1}(S_t,A_t) \\ &\quad + \alpha\big[G_{t:t+n} - Q_{t+n-1}(S_t,A_t)\big] \end{aligned} \]
Read it as: n discounted rewards plus the discounted value of the action actually taken n steps later; the pair (St, At) moves towards it. As before the update happens n steps late, and past the end of the episode the return is the plain return Gt.
Say it“The Sarsa n-step return is n discounted rewards plus gamma to the n times Q of the state and action n steps on.”
\[ \begin{aligned} G_{t:t+n} &= \textstyle\sum_{k=1}^{n} \gamma^{k-1} R_{t+k} \\ &\quad + \gamma^n\, \bar V_{t+n-1}(S_{t+n}) \\ \bar V_t(s) &= \textstyle\sum_a \pi(a \mid s)\, Q_t(s,a) \end{aligned} \]
Read it as: Expected Sarsa keeps the n sampled rewards and actions but ends with V̄, the policy-weighted average of the action values in the last state (zero if that state is terminal). Here π is the ε-greedy policy itself.
Say it“Expected Sarsa ends with V-bar, the policy-weighted average of Q over all actions in the last state.”

Learning about one policy while following another

n-step off-policy learning: importance sampling

Off-policy learning evaluates a target policy π from data gathered by a different behaviour policy b, for example learning the greedy policy while still exploring. An n-step return built from b’s actions describes b, not π. The standard fix is importance sampling: weight the whole update by how much more (or less) likely π was to take the actions in the window than b was. Actions that π would never take give weight 0; actions π likes more than b give weight above 1.

The catch is that the weight is a product of n ratios, so its variance can grow exponentially in n. Below, the 19-state walk is followed by a coin-flip behaviour policy (right with probability ½) while we evaluate a target policy that goes right more often. Raise the target’s preference for “right” and lengthen n, and watch the weights spread out and the learning curves break apart.

\[ \begin{aligned} \rho_{t:h} &= \prod_{k=t}^{\min(h,\,T-1)} \frac{\pi(A_k \mid S_k)}{b(A_k \mid S_k)} \\ V_{t+n}(S_t) &= V_{t+n-1}(S_t) \\ &\quad + \alpha\,\rho_{t:t+n-1}\big[G_{t:t+n} - V_{t+n-1}(S_t)\big] \end{aligned} \]
Read it as: ρt:h is the importance-sampling ratio, the relative probability of the actions At … Ah under the two policies. For state values the n rewards in Gt:t+n depend on the n actions At … At+n−1, so the update is weighted by ρt:t+n−1. If b = π, every ratio is 1 and this is ordinary n-step TD.
Say it“Rho from t to h is the product of pi over b for each action in the window; the update is scaled by rho from t to t plus n minus one.”
\[ \begin{aligned} Q_{t+n}(S_t,A_t) &= Q_{t+n-1}(S_t,A_t) \\ &\quad + \alpha\,\rho_{t+1:t+n}\big[G_{t:t+n} \\ &\qquad\quad - Q_{t+n-1}(S_t,A_t)\big] \end{aligned} \]
Read it as: off-policy n-step Sarsa. At is already given (we are learning its value), so its ratio is left out and the product starts one step later; it runs to At+n because the return bootstraps from Q(St+n, At+n). The Expected Sarsa version ends with V̄ and uses ρt+1:t+n−1, one ratio fewer.
Say it“For Sarsa, scale the update by rho from t plus one to t plus n.”
\[ \begin{aligned} \mathbb{E}_b\big[\rho_{t:t+n-1}\big] &= 1 \\ \operatorname{Var}_b\big[\rho_{t:t+n-1}\big] &= \Big(\textstyle\sum_a \frac{\pi(a)^2}{b(a)}\Big)^{n} - 1 \end{aligned} \]
Read it as: on average the weight is exactly 1, which is why the method is unbiased. But for a window of n independent steps (as in this walk, where both policies ignore the state) the second moment multiplies up, so the variance grows like a power of n. Windows cut short by the end of the episode have fewer factors, so the weights actually seen spread a little less.
Say it“The expected weight is one; its variance is the sum of pi squared over b, to the power n, minus one.”

Taming the weights

Per-decision importance sampling with control variates

Plain importance sampling has a wasteful habit. When a ratio is 0 (the target would never have taken that action) the whole update is thrown away, and the estimate stays put. That is right on average, but it adds variance for nothing. A smarter return applies each ratio only to the part of the return that follows its own action, one decision at a time, and when an action is unlikely under π it falls back on the current estimate instead of on zero.

The fallback term (1 − ρt)V(St) is a control variate: a quantity whose expected value is exactly zero, added because it is correlated with the noise and cancels much of it. It changes nothing on average and a great deal in any single update. Compare the two returns across step sizes: the control-variate curve stays low over a far wider range of α.

\[ \begin{aligned} G_{t:h} &= \rho_t\big(R_{t+1} + \gamma\, G_{t+1:h}\big) \\ &\quad + (1 - \rho_t)\, V_{h-1}(S_t) \\ G_{h:h} &= V_{h-1}(S_h), \qquad h = t + n \end{aligned} \]
Read it as: build the return backwards from the horizon h. At each step, with ratio ρt = π(At|St)/b(At|St), take ρt of “the reward plus the rest” and top it up with (1 − ρt) of the current estimate. If ρt = 0 the target is just V(St), so the update does no harm. If h ≥ T the recursion starts from G = 0 at the end. The update then uses this G with no extra weight.
Say it“G from t to h is rho-t times the reward plus gamma G from t plus one, plus one minus rho-t times V of S-t.”
\[ \begin{aligned} G_{t:h} &= R_{t+1} + \gamma\,\bar V_{h-1}(S_{t+1}) \\ &\quad + \gamma\,\rho_{t+1}\big(G_{t+1:h} \\ &\qquad\quad - Q_{h-1}(S_{t+1},A_{t+1})\big) \end{aligned} \]
Read it as: the action-value version. The first action is given, so the first reward is not weighted. From the next state on, take the expected value V̄ and correct it by ρ times how much the sampled continuation beat the taken action’s estimate. The recursion ends with Gh:h = Q(Sh, Ah) if h < T, or with RT at the end; at its last step the correction vanishes, which makes it a relative of Expected Sarsa.
Say it“G is the reward plus gamma times V-bar of the next state, plus rho times the next return minus the next Q.”

Off-policy without ratios

Tree backup: weigh what you didn’t do

Is there a way to learn off-policy with no importance sampling at all? For one step, Q-learning and Expected Sarsa already do it: they never ask how likely the next action was, because they average over all next actions with the target’s probabilities. The tree-backup algorithm extends that idea to n steps. Along the sampled path, at every state, the actions that were not taken contribute their estimated values, weighted by π; the action that was taken contributes the rest of the sampled return, weighted by its own π-probability. The return never needs b, so the behaviour policy can be anything.

The diagram is a spine of sampled actions with leaves hanging off it. Each leaf’s weight is the product of the target probabilities on the way down, so if the behaviour takes an action π would rarely take, everything below it is weighted down. The weights of all leaves always add to 1. Click the actions on the spine to change what the behaviour did, and move the target from greedy to random.

\[ \begin{aligned} G_{t:t+n} &= R_{t+1} \\ &\quad + \gamma\, \pi(A_{t+1} \mid S_{t+1})\, G_{t+1:t+n} \\ &\; + \gamma \textstyle\sum_{a \ne A_{t+1}} \pi(a \mid S_{t+1})\, Q(S_{t+1}, a) \\ G_{t+n-1:t+n} &= R_{t+n} \\ &\quad + \gamma \textstyle\sum_a \pi(a \mid S_{t+n})\, Q(S_{t+n}, a) \end{aligned} \]
Read it as: the return from t is the first reward, plus the discounted π-weighted values of the actions not taken in the next state, plus the discounted π-probability of the action taken times the return from there. Q here is Qt+n−1, the estimate when the update is made. The recursion ends at the last level with a full expectation, Expected-Sarsa style (or with RT if the episode ends). The update is the usual Qt+n(St, At) ← Q + α[Gt:t+n − Q], with no ratio. One-step tree backup is exactly Expected Sarsa.
Say it“Tree backup: the reward, plus gamma times pi-weighted values of the untaken actions, plus gamma times pi of the taken action times the rest of the return.”

One algorithm for all of them

n-step Q(σ): sample or expect, step by step

Look at the two off-policy action-value returns side by side. The control-variate return samples the next action and corrects with ρ; tree backup expects over all actions and weights the taken one by π. Both have exactly the same shape: reward, plus the expected value of the next state, plus a weight times “the rest of the return minus the taken action’s estimate”. Only the weight differs. So mix them. Choose a degree of sampling σ ∈ [0, 1] at every step: σ = 1 samples (weight ρ), σ = 0 expects (weight π), and anything between blends the two. That is n-step Q(σ) (De Asis et al., 2018).

Below, Q(σ) learns the action values of a target policy on the walk, from coin-flip behaviour. The four curves run on the same random numbers: σ = 1, σ = 0.5, σ = 0, and a dynamic σ that starts at 1 and shrinks by 5% after every episode. Lengthen n and push the target away from the behaviour: the more the two policies disagree, the more the sampling end suffers from its ratios.

\[ \begin{aligned} G_{t:h} &= R_{t+1} + \gamma\, \bar V_{h-1}(S_{t+1}) \\ &\quad + \gamma\, w_{t+1}\big(G_{t+1:h} \\ &\qquad\quad - Q_{h-1}(S_{t+1},A_{t+1})\big) \\ w_k &= \sigma_k\rho_k + (1-\sigma_k)\,\pi(A_k \mid S_k) \\ G_{h:h} &= Q_{h-1}(S_h, A_h) \quad (h < T) \\ G_{T-1:T} &= R_T \end{aligned} \]
Read it as: at each step the weight w on “sampled continuation minus estimate” is a blend: σ of the importance ratio ρ and 1 − σ of the target probability π(A). With σ = 1 everywhere this is the control-variate return of the last section; with σ = 0 everywhere, expanding V̄ shows it is exactly tree backup. The update has no extra ratio: Q(St, At) ← Q + α[Gt:t+n − Q]. Here γ = 1.
Say it“The Q-sigma return is the reward, plus gamma V-bar of the next state, plus gamma times sigma-rho plus one-minus-sigma pi, times the next return minus the next Q.”

Real-world project

Project: tuning n on a real wind jet

Sutton and Barto’s windy gridworld pushes the agent upward in a few middle columns. This one takes its wind from measurements. The field is the January mean of the 10-metre ocean winds from NOAA CoastWatch’s gridded product of the ASCAT scatterometers on the MetOp satellites (dataset erdQMwindmday, monthly composites at 0.25°), averaged over the nine Januaries 2014–2022, for the box 12–16.5° N, 98.5–91.5° W. That is the Gulf of Tehuantepec, where in winter cold air from the Gulf of Mexico squeezes through a gap in the mountains and blows out over the Pacific as a narrow jet (Steenburgh, Schultz & Colle, 1998; Chelton, Freilich & Esbensen, 2000). The extract was downloaded through NOAA’s ERDDAP server on 11 November 2026; NOAA’s licence statement says the data “may be used and redistributed for free”, with no warranty.

The rules: 0.5° cells (each the mean of four 0.25° points; a cell with fewer than two ocean readings is land), four moves (N, E, S, W), and after every move the wind of the cell you left pushes you by its speed divided by 12 m/s, in cells, in each direction. A push of 0.83 cells means one cell with probability 0.83 and none otherwise, so the expected drift equals the real wind. Land and the edge of the box stop you. Every step costs −1 (γ = 1), so the return is minus the length of the voyage. The agent is n-step Sarsa with ε = 0.1 and all Q-values starting at 0.

The same experiment in Python

import json, math, os, time
G = json.load(open(os.path.join(os.path.dirname(os.path.abspath(__file__)), "x071-gulf.json")))["grid"]
R, C, L, SC = G["R"], G["C"], G["L"], G["scale"]
START, GOAL = G["start"][0] * C + G["start"][1], G["goal"][0] * C + G["goal"][1]

def mulberry32(a):                          # the page's random numbers, bit for bit
    s = [a & 0xFFFFFFFF]
    def r():
        s[0] = (s[0] + 0x6D2B79F5) & 0xFFFFFFFF; a = s[0]
        t = ((a ^ (a >> 15)) * (1 | a)) & 0xFFFFFFFF
        t = ((t + (((t ^ (t >> 7)) * (61 | t)) & 0xFFFFFFFF)) & 0xFFFFFFFF) ^ t
        return ((t ^ (t >> 14)) & 0xFFFFFFFF) / 4294967296
    return r

MV = [(1, 0), (0, 1), (-1, 0), (0, -1)]     # N E S W; row 0 is the southern edge
def move(i, j, a, wy, wx):                  # one cell for the action, then the wind, stopping at land
    ni, nj = i + MV[a][0], j + MV[a][1]
    if 0 <= ni < R and 0 <= nj < C and not L[ni * C + nj]: i, j = ni, nj
    for _ in range(abs(wy)):
        ti = i + (1 if wy > 0 else -1)
        if 0 <= ti < R and not L[ti * C + j]: i = ti
        else: break
    for _ in range(abs(wx)):
        tj = j + (1 if wx > 0 else -1)
        if 0 <= tj < C and not L[i * C + tj]: j = tj
        else: break
    return i * C + j

def step(s, a, r):                          # wind push = wind / 12 m/s, rounded up or down at random
    wy, wx = G["V"][s] / SC, G["U"][s] / SC
    fy, fx = math.floor(wy), math.floor(wx)
    wy = fy + (1 if r() < wy - fy else 0); wx = fx + (1 if r() < wx - fx else 0)
    return move(s // C, s % C, a, wy, wx)

def outcomes(s, a):                         # the same step as an exact distribution (for value iteration)
    wy, wx = G["V"][s] / SC, G["U"][s] / SC; fy, fx = math.floor(wy), math.floor(wx); py, px = wy - fy, wx - fx
    return [(pa * pb, move(s // C, s % C, a, y, x)) for y, pa in ((fy + 1, py), (fy, 1 - py)) for x, pb in ((fx + 1, px), (fx, 1 - px)) if pa * pb > 0]

def solve(eps):                             # expected steps to the goal: optimal (eps 0) or best eps-greedy
    OUT = {s: [outcomes(s, a) for a in range(4)] for s in range(R * C) if not L[s]}; v = [0.0] * (R * C)
    for _ in range(5000):
        for s in OUT:
            if s == GOAL: continue
            q = [1 + sum(p * v[t] for p, t in o) for o in OUT[s]]
            v[s] = (1 - eps) * min(q) + eps * sum(q) / 4
    return v[START]

def egreedy(q, r, eps):
    if r() < eps: return int(r() * 4)
    m = max(q); ties = [a for a in range(4) if q[a] == m]
    return ties[0] if len(ties) == 1 else ties[int(r() * len(ties))]

def sarsa_episode(Q, r, n, alpha, eps=0.1, cap=10000):   # n-step Sarsa, reward -1 per step, gamma = 1
    S, A, T, t, cut = [START], [egreedy(Q[START], r, eps)], math.inf, 0, False
    while True:
        if t < T:
            s2 = step(S[t], A[t], r); S.append(s2)
            if s2 == GOAL: T = t + 1
            else:
                A.append(egreedy(Q[s2], r, eps))
                if t + 1 >= cap: T, cut = t + 1, True          # a cut-off episode still bootstraps
        tau = t - n + 1
        if tau >= 0:
            h = min(tau + n, T); Gr = 0.0
            for k in range(tau + 1, h + 1): Gr += -1
            if tau + n < T or cut: Gr += Q[S[h]][A[h]]
            q = Q[S[tau]]; q[A[tau]] = q[A[tau]] + alpha * (Gr - q[A[tau]])
        if tau == T - 1: return T
        t += 1

t0 = time.time()
print(f"water cells {R * C - sum(L)}; optimal expected steps {solve(0):.4f}; best epsilon-greedy (0.1) {solve(0.1):.4f}")
NS_, ALPHAS, RUNS, EPS = [1, 2, 4, 8, 16], [0.1, 0.2, 0.3, 0.4, 0.6, 0.8], 10, 100
best = {}
print("n   alpha:" + "".join(f"{a:>9}" for a in ALPHAS) + "   (mean steps, episodes 11-100 | episode 1)")
for n in NS_:
    late, first = [], []
    for alpha in ALPHAS:
        lt = fs = 0.0
        for run in range(1, RUNS + 1):
            r, Q = mulberry32(run), [[0.0] * 4 for _ in range(R * C)]
            lens = [sarsa_episode(Q, r, n, alpha) for _ in range(EPS)]
            lt += sum(lens[10:]) / (EPS - 10); fs += lens[0]
        late.append(lt / RUNS); first.append(fs / RUNS)
    k = min(range(len(ALPHAS)), key=lambda i: late[i]); best[n] = (ALPHAS[k], late[k])
    print(f"{n:<3} late    " + "".join(f"{x:9.2f}" for x in late))
    print(f"{'':3} first   " + "".join(f"{x:9.1f}" for x in first))
for n, (a, v) in best.items(): print(f"n = {n:2d}: best alpha {a}, {v:.2f} steps per episode")

Wrap-up

Five lines to remember

  • The n-step return sums n real rewards and then bootstraps from the estimate n steps on; n = 1 is TD, n ≥ T is Monte Carlo, and an intermediate n usually learns fastest.
  • Updates arrive n steps late, from a buffer of the last n transitions; the expected n-step return is at least γn times closer to the truth in the worst state than V is.
  • n-step Sarsa pushes credit back along the last n actions at once, which matters most when rewards are sparse; larger n wants a smaller α.
  • Off-policy, importance-sampling ratios multiply over the window and their variance can explode with n; per-decision control variates keep the mean and remove much of the noise.
  • Tree backup needs no ratios at all, weighting untaken actions by π; Q(σ) blends sampling (σ = 1) and expectation (σ = 0) step by step and contains them all.

Check your understanding

In an episode of length T = 5, which states does 3-step TD update, and when?

None during steps t = 0 and 1. At t = 2 it updates S0 (τ = 0) using R1, R2, R3 and V(S3); at t = 3 it updates S1; at t = 4 it updates S2 using R3, R4, R5 (the episode ended, so no bootstrap); after the end it updates S3 and S4 with the rewards that remain. Every state gets exactly one update.

Why does a larger n usually need a smaller α?

A longer return contains more random rewards (and, off-policy, more ratios), so each target is noisier. A large step size follows that noise; a smaller one averages it out. On the random walk, n = 1 does best at α = 0.8, n = 4 at 0.4, and n = 64 needs α = 0.05 or less.

The target policy is greedy and the behaviour is ε-greedy. What happens to n-step Sarsa with importance sampling whenever the behaviour explores?

The ratio for the exploratory action is 0, so every update whose window contains it is multiplied by 0 and learns nothing. With long windows most updates contain an exploratory step, so learning nearly stops. Control variates replace those zeros with the current estimate; tree backup simply cuts the spine there and keeps the leaves above it.

Why is the control-variate term (1 − ρt)V(St) harmless on average?

Because the expected ratio under the behaviour policy is 1: Eb[ρt] = ∑a b(a) π(a)/b(a) = ∑a π(a) = 1, so Eb[1 − ρt] = 0 and the term adds nothing to the expected target. It is correlated with the noise in the return, so it cancels much of it.

Which settings of σ turn n-step Q(σ) into tree backup, and into the per-decision importance-sampling return?

σ = 0 at every step gives tree backup (the weight on the sampled continuation is π(A)); σ = 1 at every step gives the control-variate return of equation 7.14 (the weight is ρ). With n = 1, any σ gives Expected Sarsa, because the correction term vanishes at the last step.
