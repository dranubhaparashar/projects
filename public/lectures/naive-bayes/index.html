Naive Bayes

A deliberately wrong assumption that works brilliantly

In 2002 Paul Graham published “A Plan for Spam”, and within a year almost every email program was filtering with this method. It reads a message word by word, asks “how much more often does this word appear in spam than in real mail?”, and multiplies the answers. It assumes words don't influence each other — which is false — and it still catches 98% of spam. On the right is a real filter, trained in your browser on 4,180 text messages. Type anything.

Foundations

The “naive” bet that works

Logistic regression and LDA learn a boundary between classes. Naive Bayes is a generative classifier like LDA: it learns what each class looks like, then uses Bayes' theorem to ask which class most probably produced the example in front of it. What makes it special is one bold simplification: to describe what a spam message looks like, it describes each word separately, as if words were drawn independently from a bag.

That single assumption turns an impossible counting problem into a trivial one. It is why Naive Bayes trains in one pass over the data, works with a few hundred examples, scales to millions of features, and is still the first baseline people try for text.

The engine

Bayes’ rule, counted out

Suppose 15% of messages are spam, the word “free” appears in 60% of spam and in only 5% of real messages. A message contains “free”. How likely is it spam? Don't calculate — count. Each square is one of 400 messages.

P(spam | the message contains “free”)

\[ P(\text{spam} \mid \text{free}) = \frac{P(\text{free} \mid \text{spam})\,P(\text{spam})}{P(\text{free} \mid \text{spam})\,P(\text{spam}) + P(\text{free} \mid \text{real})\,P(\text{real})} \]
Read it as: the top is “spam messages that contain free”; the bottom is “all messages that contain free”. Exactly what you counted in the grid. (The full story of Bayes' theorem, with its own playground, is in the LDA & QDA building blocks.)
Say it“Probability of spam given free equals likelihood times prior, over the total probability of seeing free.”
The assumption

Pretending features don’t talk

One word is easy. But a message has many words, and Bayes needs P(the whole message | spam). To estimate that honestly we'd need to have seen that exact combination of words many times — impossible. The naive assumption cuts through it: given the class, treat each word as independent, and multiply.

\[ P(x_1, x_2, \dots, x_d \mid C) \;\approx\; \prod_{j=1}^{d} P(x_j \mid C) \qquad\Rightarrow\qquad \hat{C} = \arg\max_{C}\; P(C)\prod_{j=1}^{d} P(x_j \mid C) \]
Read it as: the probability of the whole message is approximated by the product of each word's probability. The classifier picks the class whose prior times this product is biggest. We can drop the denominator P(x): it's the same for every class.
Say it“Predict the class that maximises its prior times the product of each feature's likelihood.”

The price: double counting

Spam often says “free” and “FREE” and “freebie” together: really one piece of evidence. Naive Bayes multiplies each copy as if it were new. Each copy here has likelihood ratio ×12.

The honest summary: Naive Bayes's probabilities are often overconfident, but its ranking — which class wins — is surprisingly often right.

Read it as: how often word w appears in class C, out of all NC words in that class. α (alpha) is the smoothing — one imaginary extra sighting of every word in the vocabulary V; the next section shows why we need it.

A trap and its fix

The zero-probability trap

“lunch” never appears in the toy spam. Without smoothing, P(lunch | spam) = 0 — and because we multiply, one zero wipes out everything else. Below, a message is stuffed with spam words plus one innocent “lunch”. Slide α to 0 and watch a single unseen word overrule four screaming spam words. Laplace smoothing (α = 1, “add one”) pretends every word was seen once more in each class, so nothing is ever impossible.

Numerics

Adding logs, not multiplying

Multiply a few hundred small probabilities and a computer runs out of digits: below about 10−324 a double-precision number is simply 0, for spam and real alike, and the classifier can't tell them apart. The fix is to work with logarithms: the log of a product is the sum of the logs, and sums of moderate negative numbers never underflow. Lengthen the message:

\[ \hat{C} = \arg\max_C \Big[\, \ln P(C) + \sum_{j} \ln P(x_j \mid C) \,\Big] \]
Read it as: the same decision (log is increasing, so the biggest product has the biggest log), computed as a sum. Every real Naive Bayes implementation works this way. Each term is a “vote” that you can show as a bar, as the hero and the project do.
Say it“Pick the class with the largest log-prior plus the sum of log-likelihoods.”

Numeric features

Gaussian NB for numbers

For measurements instead of words, give each feature in each class its own bell curve. Naive independence then means each class is an axis-aligned Gaussian cloud: no tilt allowed. That is exactly QDA with the off-diagonal covariances forced to zero. When the features really are correlated, the true clouds are tilted ellipses and Naive Bayes draws the wrong shape. Tilt them:

\[ P(x_j \mid C) = \frac{1}{\sqrt{2\pi\sigma_{jC}^2}}\exp\!\Big(-\frac{(x_j-\mu_{jC})^2}{2\sigma_{jC}^2}\Big) \]
Read it as: feature j in class C follows a bell curve with its own mean μ and spread σ. Training = compute a mean and a variance per feature per class. Compare QDA, which also learns how features co-vary (QDA lecture).
Say it“Each feature, given the class, is normal with its own mean and variance.”

The same project in scikit-learn

import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.metrics import accuracy_score, confusion_matrix

rows = [line.rstrip("\n").split("\t", 1) for line in open("SMSSpamCollection", encoding="utf-8")]
y = np.array([r[0] == "spam" for r in rows], dtype=int)
text = [r[1] for r in rows]
tr, te = train_test_split(np.arange(len(y)), test_size=0.25, random_state=42, stratify=y)

vec = CountVectorizer()                                  # lower-case, words of 2+ characters
X_tr = vec.fit_transform([text[i] for i in tr])
X_te = vec.transform([text[i] for i in te])

for alpha in (1.0, 0.1):
    nb = MultinomialNB(alpha=alpha).fit(X_tr, y[tr])
    p = nb.predict(X_te)
    print(f"alpha={alpha}: accuracy {accuracy_score(y[te], p):.4f}", confusion_matrix(y[te], p).tolist())
alpha=1.0: accuracy 0.9821 [[1202, 5], [20, 167]]
alpha=0.1: accuracy 0.9871 [[1202, 5], [13, 174]]

Wrap-up

Five lines to remember

  • Naive Bayes is Bayes' theorem plus one bold assumption: features are independent once you know the class.
  • Training is counting (words) or computing means and variances (numbers): instant, tiny, and good with little data.
  • Smoothing (α) stops one unseen word from forcing a probability to zero; Laplace's “add one” is the default.
  • Work in logs: sums of log-probabilities never underflow and read as per-word votes.
  • Its probabilities are overconfident when features are correlated, but its decisions are often excellent: 98% on real SMS spam.

Check your understanding

Why is it called “naive”?

Because it assumes the features are independent given the class — for text, that each word is chosen without regard to the others. That's obviously false (“New” makes “York” likely), yet the classifier still ranks classes well.

A test message contains a word the model never saw in training. What happens?

With a fixed vocabulary (as in scikit-learn), the word is simply ignored. A word that is in the vocabulary but never appeared in one class is the dangerous case: without smoothing its probability is 0 and it vetoes that class outright.

How does Gaussian Naive Bayes relate to QDA?

It is QDA with diagonal covariance matrices: each class gets its own variances, but no correlations. It needs far fewer parameters (2d per class instead of d + d(d+1)/2), so it is safer on small data and worse when features are strongly correlated.

Your spam filter blocks too many real messages. Which setting do you change, and what do you give up?

Raise the blocking threshold on P(spam) (or, equivalently, the prior's weight). False alarms fall, but more spam slips through — the same precision–recall trade-off as every classifier.

Why do implementations add log-probabilities instead of multiplying probabilities?

Products of hundreds of small numbers underflow to exactly 0 in floating point. Logs turn the product into a sum of moderate numbers, give the same argmax, and are faster.
